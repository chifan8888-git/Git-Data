## 2. 背景與系統概觀

### 2.1 奧多曼水表工作原理

奧多曼 (Odomann) 水表為「機械-電子複合式流量計」:

- 水流推動葉輪旋轉,葉輪上有永久磁鐵
- 感測板上的 HKD0823 霍爾 IC 偵測磁場變化,產生方波訊號
- MCU 透過計數脈衝積算累計水量,亦可由相位差判定水流方向 (防盜水)

### 2.2 元件選用

| 元件類別 | 我方設計 | 競品 |
|---|---|---|
| 霍爾感測 IC | HKD0823 × 2 | HKD0823 × 2 (相同) |
| 訊號調理 | RC + NPN 反相緩衝 | MCP6044 quad OP × 2 |
| 數位整形 | (霍爾 IC 內建 Schmitt) | MCP6541 比較器 × 2 |
| 電源管理 | 一般 LDO | C2N LDO + 完整保護鏈 |

### 2.3 訊號流(共通五階段)

```
[葉輪+磁鐵] → [HKD0823 感測] → [訊號調理] → [輸出緩衝] → [MCU 介接]
   機械         類比-數位         RC/OP/Comp     BJT/Comp     GPIO/Timer
```

## 3. 第一階段:奧多曼水表感測電路分析(我方設計)

### 3.1 整體訊號鏈

我方原設計分為五個方塊:

```
① 葉輪 + 磁鐵
② HKD0823 × 2 (MR1, MR2)
③ Pull-up + RC 低通濾波
④ NPN 電晶體緩衝 / 反相輸出級
⑤ MCU 介接 (GPIO / Timer / Encoder)
```

### 3.2 HKD0823 內部結構

```
[Hall Plate] → [差動放大器] → [Chopper 穩定電路] → [Schmitt 比較器] → [Open-Drain Output]
```

關鍵公式:

- **霍爾電壓**: `V_H = (I_H · B) / (n · q · t)`
- **切換條件**: `B ≥ B_OP` 輸出 LOW;`B ≤ B_RP` 輸出 HIGH
- **遲滯磁場**: `B_HYS = B_OP − B_RP`

### 3.3 Pull-up + RC 設計

- **Pull-up 電阻**: 典型 10kΩ~47kΩ,平衡上升時間與靜態功耗
- **上升時間**: `t_r ≈ 2.2 · R_PU · C_L` (含 PCB 走線電容與 MCU 輸入電容)
- **LPF 截止頻率**: `f_c = 1/(2π·R·C)`,應 ≥ 10 × f_signal_max
- **典型: R = 10kΩ, C = 100pF → f_c ≈ 159 kHz**,可濾除 MHz 級 EMI

### 3.4 NPN 反相緩衝級

- 目的: 電壓位準轉換 (5V → 3.3V)、驅動能力強化、邏輯反相
- **飽和條件**:
  - `I_C(sat) = (V_CC − V_CE_sat) / R_C`
  - `I_B(min) = I_C(sat) / β_min`
  - 過驅動因子 `OD ≥ 2~5` 確保飽和
- 範例: V_CC=3.3V, R_C=10kΩ, β_min=100 → R_B 取 100kΩ~220kΩ

### 3.5 MR OUT 與 MR TR OUT 選用準則

| 項目 | MR OUT (霍爾原始) | MR TR OUT (BJT 緩衝後) |
|---|---|---|
| 輸出型態 | Open-Drain,需 pull-up | R_C 拉升,CMOS 相容 |
| 邏輯極性 | 磁鐵接近 → LOW | 磁鐵接近 → HIGH (反相) |
| 驅動能力 | 弱 (mA 級) | 強 (數十 mA) |
| 抗雜訊 | 一般 | 較佳 |
| 適用場合 | 短距離、共電源 | 長距離、跨電壓、雜訊環境 |

## 4. 第二階段:競品 SENSOR BOARD 電路分析

### 4.1 競品整體架構

競品採「感測子板 + 訊號調理母板」雙板架構:

**感測子板 (Sheet 1)**:
- 安裝 2 顆 HKD0823 (MR1, MR2)
- J1/J2 雙磁場輸入接點
- J3 對外 4-pin 接頭 (VCC、GND、MR1 OUT、MR2 OUT)

**訊號調理母板 (Sheet 2)**:
- U5: C2N LDO + 完整保護鏈 (R20/D1/C5/C6/R21/C7/C8)
- U3 (MCP6044): MR1 通道 4 OP (U3A/U3B/U3C/U3D)
- U1 (MCP6044): MR2 通道 4 OP (U1A/U1B/U1C/U1D)
- U2, U4 (MCP6541): 推挽比較器 × 2
- C3, C4: 跨通道耦合電容
- OUT1: 原始霍爾輸出 (VCC, MR1 OUT, MR2 OUT, GND)
- OUT2: 比較器整形輸出 (VIN, MR2 TR OUT, MR1 TR OUT, 預留)

### 4.2 電源與保護鏈

```
VIN → R20(100Ω) → [C5/C6 + D1 保護] → U5 (C2N LDO) → R21(100Ω) → [C7/C8] → VCC
```

- **R20**: 限流,突波時保護 D1 與 LDO
- **D1**: 反接/TVS 保護,符合 ESD 要求
- **C5/C6**: 輸入濾波
- **R21 + C7/C8**: π 型輸出濾波,抑制 LDO 紋波

### 4.3 VCC/2 虛擬地網路

```
VCC ─[R1=10MΩ]─┬─[C1]─ GND
                ├─ VREF (≈ VCC/2) → 供 U3A pin3, U1A pin3
GND ─[R2=10MΩ]─┴─[C2]─ GND
```

關鍵特性:
- **VREF = VCC/2**:單電源系統的虛擬地中點
- **靜態電流 ≈ 165 nA** (10MΩ 級偏壓),超低功耗
- **τ ≈ 1 秒** (若 C ≈ 100nF):上電後需數秒穩定,韌體需「上電 ignore 期」

### 4.4 MR1 通道詳細推導

**U3C — VREF 緩衝器**:
- 單位增益緩衝 (Voltage Follower)
- 輸出 VC = VREF (低阻參考)
- 目的: 避免後級小電流拉動 10MΩ 級 VREF

**U3B — 同相放大 ×11**:
- R17 = 100kΩ (V− 至 VC), R18 = 1MΩ (回授)
- `VU3B_7 − VC = 11 · (V_MR1 − VC)`
- **實際效應**: 因 MR1 OUT 為 0~VCC 數位方波,×11 後遠超軌限,實際是「強力 Schmitt 整形」而非線性放大

**U3A — 反相鏡射**:
- R6 = R7 = 150kΩ
- `VU3A_1 = 2·VP − VL` (以 VP=VCC/2 為對稱軸)
- 形成互補訊號

**U3D — 動態補償**:
- R12 = 150kΩ + C4 構成零點
- 低頻反相: `VU3D_14 ≈ 2·VX − VA`
- 含 C4 動態: `+ R · C4 · d(VA − VX)/dt`
- 零點頻率: `f_z = 1/(2π · R7 · C4)`
- 作用: 邊緣加速,讓快速磁鐵通過時獲額外增益

### 4.5 MR2 通道詳細推導

MR2 通道對稱於 MR1,結構差異:

| 元件 | 對應 | 功能 |
|---|---|---|
| U1A | ≈ U3C | VREF 緩衝 |
| U1B | ≈ U3B | 同相放大 ×11 |
| U1C | (本通道特有) | VN 節點緩衝 |
| U1D | ≈ U3D | 反相補償 + C3 跨通道耦合 |

- R10 = 150kΩ: MR2 加權注入電阻
- R3 = 1MΩ: U2 輸出弱拉升

### 4.6 比較器 U2 / U4 (MCP6541)

**規格**:
- 供電 1.6~5.5V,適用低電壓系統
- t_pd ≈ 4 μs (足以涵蓋 < 1 kHz 水表訊號)
- Push-pull 輸出 (CMOS 相容,無需外部上拉)
- 靜態電流 600 nA

**門檻計算**:
```
V_th = VCC · R11 / (R14 + R11) = VCC · 51k/102k = VCC/2
MR1 TR OUT = HIGH  if  VU3B_7 > VCC/2
MR1 TR OUT = LOW   if  VU3B_7 < VCC/2
```

**為何在 HKD0823 之後再加比較器?**
1. 驅動能力強化 (Open-Drain → Push-Pull)
2. 噪聲免疫力提升 (放大後 + 跨通道耦合)
3. 邊緣陡度提升 (< 1 μs vs HKD0823 的數 μs)
4. 門檻可微調 (透過分壓比)

### 4.7 跨通道耦合 (C3 / C4)

**共模雜訊抑制**:
```
V_signal (差模) = (V_MR1 − V_MR2) / 2     ← 保留
V_noise  (共模) = (V_MR1 + V_MR2) / 2     ← 抵消
```

典型 CMRR @ 1kHz ≈ 20~40 dB。

**動態前饋**:
- C4 對 VP 中點施加擾動: `ΔVP(t) ≈ C4/(C1+C2+C4) · ΔVL(t)`
- 邊緣到來時 VP 暫時被拉動,U3A 輸出產生瞬間尖峰,加速比較器穿越門檻

### 4.8 設計亮點與弱點

**亮點**:
1. 全 nA 級靜態電流元件 (適合電池水表)
2. 差動雜訊抑制 (20~40 dB CMRR)
3. 雙重輸出彈性 (OUT1 + OUT2)
4. Push-pull 比較器直接 CMOS 相容
5. 完整 ESD/突波保護鏈

**弱點 / 風險**:
1. ×11 增益對「已是數位邏輯」之 MR OUT 而言實質為過度設計
2. PCB 設計時感測器位置偏移將影響 Encoder DIR 判讀
3. BOM 元件數量眾多 (R ≈ 20、C ≈ 10、IC ≈ 5)
4. VREF 上電穩定需數秒,韌體需配合
5. C3/C4 容差敏感,量產良率風險

## 5. 第三階段:磁鐵與感測器配置修正歷程

本次討論經歷數次配置修正,以下記錄完整歷程:

| 階段 | 磁鐵配置 | 感測器配置 | 備註 |
|---|---|---|---|
| 初始假設 | 180° | (隱含 90°) | 第一版報告假設 |
| 第一次修正 | 90° | 未指定 | 中途修正 |
| 第二次修正 | 120° | 未指定 | 中途修正 |
| **最終確認** | **180° (對稱)** | **135° 機械夾角** | **最終配置** |

### 5.1 為何需要兩個感測器?

- 單一感測器: 僅能計數,無法判定方向
- 雙感測器 + 相位差: 可形成 Quadrature (正交) 訊號,使用 Encoder Mode 硬體解碼方向 → **防盜水核心功能**

### 5.2 機械相位 ↔ 電氣相位轉換

最關鍵的觀念:

```
1 電氣週期 = 2 個脈衝間的角度
         = 180° 機械 (因兩磁鐵 180° 對稱)

θ_電氣 = 2 × θ_機械
```

**Quadrature 條件**: `θ_電氣 = ±90°` → `θ_機械 = ±45° 或 135°`

### 5.3 最終配置 (180° + 135°) 之相位

```
MR1 偵測點 (每轉): θ = 0°, 180°
MR2 偵測點 (每轉): θ = 135°, 315°
連續邊緣間隔: 135° → 45° → 135° → 45° (交替)
電氣相位: 2 × 135° = 270° = −90° (Quadrature)
```

## 6. 第四階段:感測器夾角 Duty Cycle 評估

### 6.1 評估目的

於磁鐵 180° 對稱前提下,評估感測器機械夾角 α ∈ {90°, 120°, 135°, 180°} 之 Duty Cycle 表現,找出最佳值。

評估條件: θw = 90° (脈衝寬度,單路 50% Duty Cycle)。

### 6.2 四角度完整比較

#### α = 90° (反相)

```
MR1 HIGH: [0°, 90°)
MR2 HIGH: [90°, 180°)
```

| 狀態 | 持續角度 | 佔比 |
|---|---|---|
| 11 | 0° | **0% ✗** |
| 10 | 90° | 50% |
| 00 | 0° | **0% ✗** |
| 01 | 90° | 50% |

**結果: ✗ 不可用** — 僅 2 狀態交替,失去 quadrature

#### α = 120° (Sub-Quadrature)

```
MR1 HIGH: [0°, 90°)
MR2 HIGH: [120°, 180°) ∪ [0°, 30°)
```

| 狀態 | 持續角度 | 佔比 |
|---|---|---|
| 11 | 30° | 16.7% |
| 10 | 60° | 33.3% |
| 00 | 30° | 16.7% |
| 01 | 60° | 33.3% |

**結果: △ 次優** — 4 狀態齊備但不均衡

#### α = 135° (★ 最佳)

```
MR1 HIGH: [0°, 90°)
MR2 HIGH: [135°, 180°) ∪ [0°, 45°)
```

| 狀態 | 持續角度 | 佔比 |
|---|---|---|
| 11 | 45° | **25% ✓** |
| 10 | 45° | **25% ✓** |
| 00 | 45° | **25% ✓** |
| 01 | 45° | **25% ✓** |

**結果: ★ 最佳** — 完美均衡 25%×4,Gray code 標準遞進

#### α = 180° (同相)

```
MR1 HIGH: [0°, 90°)
MR2 HIGH: [0°, 90°)  ← 與 MR1 完全同步
```

| 狀態 | 持續角度 | 佔比 |
|---|---|---|
| 11 | 90° | 50% |
| 10 | 0° | **0% ✗** |
| 00 | 90° | 50% |
| 01 | 0° | **0% ✗** |

**結果: ✗ 不可用** — 兩路完全同步,失去獨立資訊

### 6.3 綜合評等

| α (機械) | 電氣相位 | 11/10/00/01 | Encoder ×4 | 方向判定 | 總評 |
|---|---|---|---|---|---|
| 90° | 180° (反相) | 0/50/0/50 | ✗ 失敗 | ✗ 無法 | ✗ 不可用 |
| 120° | 240° | 16.7/33.3/16.7/33.3 | ○ 可,不均 | ○ 不對稱 | △ 次優 |
| **135° ★** | **270° (−90°)** | **25/25/25/25** | **★ 完美** | **★ 完美對稱** | **★ 最佳** |
| 180° | 360° (同相) | 50/0/50/0 | ✗ 失敗 | ✗ 無法 | ✗ 不可用 |

### 6.4 為何 135° 是最佳值

數學上,Quadrature 條件對應 θ_電氣 = ±90°,即 θ_機械 ∈ {45°, 135°}。兩者皆為等效最佳值,僅方向定義相反。

選擇 135° 的工程理由:
1. **PCB Layout**: 對角線佈線特性,IC 間有較大空間
2. **磁鐵切換時序**: 較長間隔有利後級 OP Amp 穩定
3. **機械結構**: 便於塑膠射出與卡榫定位
4. **互換性**: 對稱性高,容易透過軟體校正

### 6.5 θw 變化對最佳性的影響

若磁鐵不夠強導致 θw < 45°,即使 α = 135°,狀態 11 也會消失:

| α | θw=30° | θw=60° | θw=90° | θw=120° |
|---|---|---|---|---|
| 90° | 0 | 0 | 0 | 30° |
| 120° | 0 | 0 | 30° | 60° |
| **135°** | 0 | 15° | **45°** | 75° |
| 180° | 30° | 60° | 90° | 120° |

**建議**:
- 選 NdFeB 釹鐵硼磁鐵,確保 θw ≥ 60°
- 控制氣隙 1~3 mm
- 出廠校正量測實際 θw

## 7. MCU 軟體動作方式總整理

### 7.1 五種介接策略

| 策略 | 方式 | 優點 | 缺點 | 適用場合 |
|---|---|---|---|---|
| **A. GPIO 中斷** | 雙路 TR OUT 接 EXTI | 通用、簡單 | 高頻時 CPU 負擔大 | 一般水表 |
| **B. Timer Encoder ★** | 接 TIM CH1/CH2 | 0 CPU 負擔、×4 解碼 | 需校正 DIR | 防盜水水表 |
| **C. RAW+TR 自診斷** | 4 路 GPIO 比對 | 高可靠、容錯 | 4 隻 GPIO | 工業級 |
| **D. Input Capture** | 單路接 TIM IC | 瞬時頻率精準 | 不判向 | 顯示流量 |
| **E. RTC Tamper 喚醒** | TR OUT → Tamper Pin | μA 級超低功耗 | 部分 MCU 才有 | NB-IoT 智慧水表 |

### 7.2 推薦組合 — 防盜水智慧水表

```
HKD0823 → (調理電路) → MR TR OUT × 2
                          ↓
                  STM32 TIM2 Encoder Mode (CH1+CH2)
                          ↓
                  ┌─────────────────────────┐
                  │ 硬體 32-bit 計數器       │
                  │ DIR bit 自動方向判定     │
                  └─────────────────────────┘
                          ↓
                  RTC 1 Hz 喚醒 → 讀 delta → 計算 Q
                          ↓
                  反轉偵測 → log_tamper_event()
```

### 7.3 STM32 HAL 程式範例

#### 策略 A: GPIO 中斷

```c
volatile int32_t flow_count = 0;
volatile uint8_t reverse_flag = 0;

void HAL_GPIO_EXTI_Callback(uint16_t pin) {
    if (pin == MR1_TR_Pin) {
        uint8_t m1 = HAL_GPIO_ReadPin(MR1_TR_GPIO_Port, MR1_TR_Pin);
        uint8_t m2 = HAL_GPIO_ReadPin(MR2_TR_GPIO_Port, MR2_TR_Pin);
        if (m1 == m2) { flow_count++; reverse_flag = 0; }
        else          { flow_count--; reverse_flag = 1; }
    } else if (pin == MR2_TR_Pin) {
        uint8_t m1 = HAL_GPIO_ReadPin(MR1_TR_GPIO_Port, MR1_TR_Pin);
        uint8_t m2 = HAL_GPIO_ReadPin(MR2_TR_GPIO_Port, MR2_TR_Pin);
        if (m1 != m2) { flow_count++; reverse_flag = 0; }
        else          { flow_count--; reverse_flag = 1; }
    }
}
```

#### 策略 B: Timer Encoder Mode (推薦)

```c
/* CubeMX: TIM2 → Combined Channels → Encoder Mode TI1 and TI2 */
HAL_TIM_Encoder_Start(&htim2, TIM_CHANNEL_ALL);

int32_t get_count(void) {
    return (int32_t)__HAL_TIM_GET_COUNTER(&htim2);
}

uint8_t get_direction(void) {
    uint8_t dir_raw = ((TIM2->CR1 & TIM_CR1_DIR) == TIM_CR1_DIR) ? 1 : 0;
    return dir_raw ^ FORWARD_DEF;   /* FORWARD_DEF 由 FLASH 校正值決定 */
}

void task_1Hz(void) {
    static int32_t last = 0;
    int32_t cur = get_count();
    int32_t delta = cur - last;
    total_pulse += delta;
    float lpm = (delta / 8.0f) * 60.0f * 2 / K_p;
    last = cur;
}
```

## 8. 關鍵公式彙整

### 8.1 霍爾感測

```
V_H = (I_H · B) / (n · q · t)         霍爾電壓
B_HYS = B_OP − B_RP                    遲滯磁場
I_OL = (V_CC − V_OL) / R_PU            開汲極 LOW 時電流
```

### 8.2 訊號調理

```
f_c_LPF = 1 / (2π · R · C)             RC 低通截止
t_r ≈ 2.2 · R_PU · C_L                 上升時間
G_OP = 1 + R_f / R_i                   同相放大增益
f_z = 1 / (2π · R · C)                 動態零點
VREF = VCC · R2 / (R1+R2)              虛擬地分壓
τ_VREF = (R1 ∥ R2) · C_eq              VREF 時間常數
```

### 8.3 流量計算

```
N_pulse/rev = 2                        每轉脈衝數 (兩磁鐵)
f_MR = 2 × n_rev/s (Hz)                訊號頻率
Q (L/min) = (f × 60) / K_p             瞬時流量
V_total (L) = N_count / K_p            累計水量
```

### 8.4 相位關係

```
θ_電氣 = 2 × θ_機械                    機械-電氣換算
Quadrature 條件: θ_電氣 = ±90°
最佳 θ_機械 ∈ {45°, 135°}
N_count/rev (×4 解碼) = 8              每轉計數點
θ_min = 360° / 8 = 45°                 角度解析度
```

### 8.5 BJT 緩衝級

```
I_C(sat) = (V_CC − V_CE_sat) / R_C    集極飽和電流
I_B(min) = I_C(sat) / β_min            最小基極電流
I_B(actual) = (V_in − V_BE) / R_B      實際基極電流
OD = I_B(actual) / I_B(min) ≥ 2~5     過驅動因子
```

### 8.6 跨通道差動

```
V_signal (差模) = (V_MR1 − V_MR2) / 2     保留
V_noise  (共模) = (V_MR1 + V_MR2) / 2     抵消
CMRR ≈ 20~40 dB
```

## 9. 設計建議與行動方案

### 9.1 短期 (家用市場保持簡潔)

- 維持現有 BJT 反相緩衝架構
- BOM 成本維持 USD 0.20~0.35
- MR1/MR2 PCB layout 確認機械夾角 135° (即使單路使用,亦預留升級空間)

### 9.2 中期 (工業/智慧市場參考競品)

- 引入 4 OP + 1 Comp 之精簡版差動架構 (而非完整 8 OP + 2 Comp)
- 加入輸入保護鏈 (R + D),提升 EFT/Surge 表現
- 改用 nA 級 OP Amp (如 MCP6044) 提升電池壽命

### 9.3 長期 (NB-IoT 智慧水表)

- MCU 改用支援 RTC Tamper Wake-up 之 STM32L 系列
- 軟體實作: Timer Encoder + RAW/TR 雙路冗餘自診斷
- 出廠校正流程確認:
  1. DIR bit 方向定義 (正轉/反轉)
  2. K_p 脈衝係數
  3. θw 實測值 (確認狀態 11 存在)
- 通訊協定: NB-IoT 或 LoRa

### 9.4 PCB Layout 鐵則

| 項目 | 規範 |
|---|---|
| MR1 ↔ MR2 機械夾角 | **135° ± 2°** |
| 磁鐵類型 | NdFeB 釹鐵硼 |
| 葉輪-感測板氣隙 | 1~3 mm |
| C3/C4 電容精度 | ±5% (X7R) 或 ±2% (C0G) |
| C3/C4 走線 | 對稱、等長 |
| VREF 上電穩定時間 | 軟體預留 3~5 秒 ignore 期 |

### 9.5 風險管控

- 競品 SENSOR BOARD 之 OUT2 第 4 隻腳目前預留,需確認量產時用途
- D1 規格須符合 IEC 61000-4-2 ESD 等級
- 若 θw 實測 < 45°,需提供「3 狀態解碼」備援韌體
- BOM 元件數量眾多,需檢視 SMT 組裝失敗率
