## 19.1 基礎概念與發展脈絡

### 電腦視覺的定位

電腦視覺（Computer Vision, CV）是讓機器從靜態影像或動態影片中擷取、辨識並解釋語意資訊的領域，本質是影像處理（Image Processing）、模式辨識（Pattern Recognition）與深度學習（Deep Learning）的交集，不是單一技術。

### 三個技術階段

| 階段 | 期間 | 特徵怎麼來 | 代表技術 | 瓶頸／突破 |
|---|---|---|---|---|
| **特徵工程主導** | 1980s–2010 | 人工設計（Handcrafted） | Canny 邊緣偵測、SIFT／SURF／ORB 特徵點、色彩與紋理分析 + SVM／KNN／隨機森林 | 無法自學高階語意，效能受特徵設計品質綁死 |
| **CNN 革命** | 2012–2020 | 模型自動學習 | AlexNet（2012 ImageNet 突破）、VGG、GoogLeNet、ResNet、DenseNet；任務擴至 YOLO／Faster R-CNN、FCN／U-Net、FaceNet | 需要大量標註資料與 GPU 算力 |
| **多模態與生成式融合** | 2020– | 跨模態對齊 + 生成 | CLIP、Vision Transformer（ViT）、DALL·E／Stable Diffusion／Midjourney、SAM（Segment Anything Model） | 從「看懂」走向「跨模態理解」與「創造」 |

**分水嶺記法：** 2012 年 AlexNet 在 ImageNet 上的分類突破，是 CV 從手工特徵轉向自動特徵學習的起點；2020 年後 CLIP／ViT 把 NLP 的 Transformer 與對比學習搬進視覺，才出現零樣本（Zero-shot）與文字生成影像。

### 一定要背的一句話

> **電腦視覺任務的層級，是由「輸出的粒度」決定的：整張圖一個標籤 → 一組框 → 一張逐像素的類別圖 → 一張逐像素且帶實例編號的圖。**

## 19.2 四大視覺任務的層次區辨（本節最穩定的考點）

### 輸出型態與標註成本總表

| 任務 | 輸出型態 | 能定位嗎 | 能分同類個體嗎 | 涵蓋背景類別嗎 | 標註方式 | 標註成本 |
|---|---|---|---|---|---|---|
| **影像分類**<br>Image Classification | 整張影像 → 1 個（或多個）類別標籤 + 機率 | ✗ | ✗ | — | 類別標籤（Label） | 最低 |
| **物件偵測**<br>Object Detection | N 組（類別, 邊界框座標, 信心分數） | ✓ 矩形框 | ✓ 每框即一個實例 | ✗ 只框可數物件 | 邊界框（Bounding Box） | 中 |
| **語意分割**<br>Semantic Segmentation | 與輸入同尺寸的類別圖，每個像素 1 個類別 | ✓ 像素級 | ✗ 同類併為一塊 | ✓ 道路、天空等也標 | 逐像素遮罩 | 高 |
| **實例分割**<br>Instance Segmentation | 每個實例一組（類別, 框, 二值遮罩 Mask） | ✓ 像素級 | ✓ 每個個體獨立遮罩 | ✗ 通常不含背景 | 像素遮罩 + 實例 ID | 最高 |
| **全景分割**<br>Panoptic Segmentation | 每個像素同時得到（類別, 實例 ID） | ✓ 像素級 | ✓ | ✓ 可數物件與背景全含 | 語意 + 實例合併標註 | 最高 |

**標註成本的排序才是考點**：類別標籤 < 邊界框 < 像素遮罩 < 遮罩＋實例 ID。標一張分類圖只要點一個類別，標一張分割圖要沿著物件輪廓畫多邊形，工時是數倍到數十倍——所以「標註成本高」的情境題，答案往往是往上退一階（用偵測代替分割），或改用遷移學習／自動化標註。

### 選型決策流程

```
┌──────────────────────────────────────────────┐
│        視覺任務選型決策樹                    │
├──────────────────────────────────────────────┤
│ 需要知道「在哪裡」嗎？                       │
│  NO  → 影像分類                              │
│  YES ↓                                       │
│                                              │
│ 精度需要「框」還是「像素」？                 │
│  框   → 物件偵測（YOLO / Faster R-CNN / SSD）│
│  像素 ↓                                      │
│                                              │
│ 需要區分「同類別的不同個體」嗎？             │
│  NO  → 語意分割（FCN / U-Net）               │
│  YES ↓                                       │
│                                              │
│ 需要連道路、建築等背景也逐像素標嗎？         │
│  NO  → 實例分割（Mask R-CNN）                │
│  YES → 全景分割（Panoptic）                  │
└──────────────────────────────────────────────┘
```

### 題幹關鍵字 → 任務對照

| 題幹出現這種描述 | 指向 | 為什麼 |
|---|---|---|
| 「判斷這張影像屬於哪一類」「商品分類」 | 影像分類 | 只要影像層級標籤 |
| 「標示位置」「邊界框」「即時偵測畫面中有幾台車」 | 物件偵測 | 要定位但只需矩形框 |
| 「每一個像素所屬的類別（道路／建築／行人）」且**未提到區分個體** | 語意分割 | 逐像素但同類合一 |
| 「像素級遮罩（Pixel-level Mask）」＋「行人#1 與行人#2 分開」「不同顧客拿相同商品要分別標記」 | 實例分割 | 逐像素＋區分個體 |
| 「同時辨識每個像素類別」＋「區分同類個體」＋**明確含道路、建築等不可數背景** | 全景分割 | 語意＋實例的聯集 |

**115Q1 第 6、7 題與 114Q2 第 34 題的分野就卡在最後一格**：三題都給了「像素級 + 區分個體」，115Q1 的兩題物件都是可數的（行人、購物籃、手機、商品）→ 答案是實例分割；114Q2 第 34 題把「道路、建築」這類不可數背景也寫進需求 → 實例分割不完整，答案升級為全景分割。**看到背景類別被列進需求，才選全景分割。**

### 常見誘答句型拆解

| 誘答敘述 | 錯在哪 |
|---|---|
| 「實例分割對每個像素分類但不產生 Bounding Box；語意分割產生 Bounding Box」 | 完全顛倒。Mask R-CNN 這類實例分割通常先出框再出遮罩；語意分割才是不出框、只做逐像素標記 |
| 「實例分割僅用於影像層級的類別分類」 | 影像層級分類是影像分類的定義 |
| 「語意分割與實例分割皆為逐像素分類，兩者在是否區分個體上並無差異」 | 直接否定唯一的根本分野 |
| 「物件偵測即可滿足像素級區域標記」 | 偵測的輸出是矩形框，框內仍含背景像素 |

## 19.3 影像標註與資料前處理

### 標註方式與工具對照

| 任務類型 | 標註方式 | 說明 | 工具範例 |
|---|---|---|---|
| 影像分類 | 類別標籤 | 整張影像標單一類別 | LabelImg、Label Studio |
| 物件偵測 | 邊界框 | 標示物件位置與類別 | CVAT、Roboflow |
| 語意分割 | 每像素分割標籤 | 每一像素皆對應類別 | LabelMe、SuperAnnotate |
| 實例分割 | 像素遮罩 + 實例 ID | 區分同類型的多個物件 | VGG Image Annotator |
| 關鍵點標註 | 身體節點／特定點位座標 | 人體姿態估計 | COCO Annotator |
| 文字辨識（OCR） | 區塊框選 + 文字內容 | 每段文字框選並輸入字串 | Tesseract Trainer |

### 標註品質控管三原則

- **一致性**：所有標註者遵循同一份標註準則（Annotation Guideline），避免風格差異變成模型雜訊
- **準確度**：邊界框與像素範圍必須貼合真實輪廓，鬆散的框會直接壓低 IoU
- **品質控制**：定期抽查；高風險任務採「雙重標註」（兩人標同一張圖後比對）；醫療影像須由專業醫師標註

**降低標註成本的三種正規手段**：自動化標註（Auto-labeling，模型先標、人工只校對）、半監督式學習（少量標註 + 大量未標註）、主動學習（Active Learning，模型挑最難的樣本優先送人工標）。

### 前處理技術表

| 處理類別 | 技術 | 目的 |
|---|---|---|
| 尺寸處理 | Resize / Padding / Cropping | 統一成模型輸入尺寸，Padding 用於避免變形 |
| 正規化 | Pixel Normalization | 0–255 轉 0–1，或標準化到均值 0、標準差 1，穩定訓練 |
| 像素增強 | 直方圖均衡化、Gamma 校正 | 提升低光源或低對比影像的可辨度 |
| 噪聲去除 | 高斯濾波、雙邊濾波（邊緣保留） | 降低感測器雜訊，雙邊濾波可保住邊緣 |
| 色彩空間轉換 | RGB ↔ Grayscale／HSV | 依任務簡化或重組通道 |
| 資料擴增 | 翻轉、旋轉、裁剪、模糊、色彩偏移 | 提升泛化、對抗過擬合，**只對訓練集做** |
| 序列統一 | 影片影格取樣 | 動作辨識、影像序列建模 |

### 擴增 vs 合成資料 vs 過採樣（極易混淆）

| 手法 | 做什麼 | 解決什麼問題 | 官方考過的陷阱 |
|---|---|---|---|
| **資料擴增**<br>Data Augmentation | 對既有影像做幾何／色彩變換 | 樣本多樣性不足、過擬合 | 變換過頭會讓增強後的特徵分佈偏離原始資料，泛化能力反而下降；正解是**調整增強策略以維持語意一致性**，不是提高增強比例 |
| **合成資料**<br>Synthetic Data | 用模擬器或生成模型產生全新場景，生成當下即附帶精確標註 | 真實世界難蒐集的長尾情境（大雨、濃霧） | **不能完全取代真實資料**，存在領域差距（Domain Gap），須與真實資料混用 |
| **過採樣**<br>SMOTE | 在少數類樣本與其近鄰之間內插產生新樣本 | 類別不平衡（良品 99%／瑕疵 1%） | 屬**資料層級**手法，不動模型架構與學習演算法；複製多數類只會讓不平衡更極端 |

## 19.4 關鍵技術與常用模型

### CNN 的組件與職責

| 組件 | 做什麼 | 備註 |
|---|---|---|
| 卷積層 Convolutional Layer | 以卷積核擷取局部特徵，產生特徵圖（Feature Map） | 具平移不變性與空間局部性，這是影像模態選 CNN 的根本理由 |
| 池化層 Pooling Layer | 降維（如 Max Pooling），減少計算量 | 增強對位移的容忍度 |
| 激活層 Activation Layer | 引入非線性（ReLU） | 沒有它，多層等同單層線性 |
| 全連接層 Fully Connected Layer | 把特徵整合成一維向量做最終分類 | 輸入必須是二維張量 |
| 輸出層 | Softmax 轉成類別機率 | 放在最後，不是放在全連接層之前 |

**卷積輸出接全連接層的必經一步（考過語法）：**

```python
x = self.conv(x)           # (B, C, H, W) 四維特徵圖
x = torch.flatten(x, 1)    # (B, C*H*W) <- 必要的展平（Flatten / view / reshape）
x = self.fc(x)             # (B, num_classes)
```

PyTorch **不會**自動轉換維度，直接串接會因張量形狀不符報錯。全域平均池化（Global Average Pooling）雖然也能把特徵圖壓成向量且參數更少，但那是**另一種架構選擇**，不是「卷積輸出與全連接層之間」的基本銜接操作——這是官方設計過的誘答。

### 經典分類架構

| 模型 | 關鍵貢獻 |
|---|---|
| LeNet | 早期 CNN（約 5 層），手寫數字辨識 |
| AlexNet | 2012 ImageNet 里程碑，8 層，引入 ReLU 與 Dropout |
| VGG | 深度 + 小卷積核（3×3），層數可達 19 |
| ResNet | 殘差連接（Residual Connection）解決深層梯度消失，可達 152 層 |
| ViT | 以 Transformer 處理影像切塊；**缺乏卷積的歸納偏置，從頭訓練需極大量資料** |

### 物件偵測：單階段 vs 兩階段

| 模型 | 階段 | 流程 | 特性 | 適用 |
|---|---|---|---|---|
| **YOLO** | 單階段（One-stage） | 整張影像劃分網格，一次回歸出框座標與類別機率 | 快、延遲低 | 高頻影像流、產線即時檢測 |
| **SSD** | 單階段 | 多尺度特徵圖上直接偵測 | 速度與準確度平衡 | 一般即時應用 |
| **Faster R-CNN** | 兩階段（Two-stage） | RPN 先產生候選區域（Region Proposal），再分類與框回歸 | 準確度高、延遲較高 | 精度優先、可離線批次 |

YOLO 的速度優勢來自**取消候選區域機制**，不是靠增加候選區域數量——這是官方誘答的原句。

### 影像分割與多模態／生成模型

| 模型 | 定位 | 關鍵機制 |
|---|---|---|
| FCN | 語意分割 | 全卷積 + 上採樣（Upsampling）還原到原尺寸，端到端 |
| U-Net | 語意分割（醫療） | 對稱編碼器／解碼器 + **跳躍連接（Skip Connections）**，從高解析特徵恢復細節 |
| Mask R-CNN | 實例分割 | Faster R-CNN + 額外的遮罩分支，輸出每個物件的二值 mask |
| SAM | 通用分割 | 高泛化的可提示分割，處理未見過的分割任務 |
| CLIP | 多模態理解 | 圖文**對比式學習**，把影像與文字映射到**共同嵌入空間**，可直接以語意相似度做**零樣本分類**，無須新增標註 |
| GAN | 生成 | 生成器 vs 鑑別器對抗；典型病症是**模式崩潰（Mode Collapse）**，主流解法是改用 Wasserstein 距離（WGAN 損失） |
| Diffusion（Stable Diffusion／DALL·E） | 生成 | 逐步去雜訊；細節不足時**增加取樣步數 + 換高品質取樣器**，而非提高 CFG（CFG 過高會過飽和與假影） |

### 評估指標

| 指標 | 用在哪 | 重點 |
|---|---|---|
| Accuracy | 分類 | 預測正確樣本數 ÷ 總樣本數 |
| Top-5 Error | 大類別數分類（ImageNet） | 真實類別落在前五名即算對 |
| 混淆矩陣 Confusion Matrix | 分類 | 固定閾值下的 TP／FP／FN／TN；**Precision、Recall、Accuracy 都能直接算，但 AUC 不能**（AUC 需掃過所有閾值） |
| ROC 曲線 | 二元分類 | **X 軸 = 假陽率 FPR，Y 軸 = 真陽率 TPR（即召回率）**；PR 曲線則是 X 軸 = 召回率、Y 軸 = 精確率 |
| IoU | 偵測／分割 | 交集面積 ÷ 聯集面積，範圍 0–1；通常 > 0.5 或 0.7 視為成功偵測 |
| mAP | 物件偵測 | 各類別平均精確率；**IoU 閾值設得越高 = 要求重疊度越高 = 定位越精準才算對** |

**IoU 算例（官方指引原題型）：** 真實框 100、預測框 80、重疊 40 → 聯集 = 100 + 80 − 40 = 140 → IoU = 40 ÷ 140 ≈ 0.286。

## 19.5 應用情境與實務案例

### 四大場域

| 場域 | 主要任務 | 標準流程／要點 | 關鍵風險 |
|---|---|---|---|
| **監控與安全** | 人臉辨識、車牌辨識（ANPR） | 人臉：檢測 → 特徵提取 → 比對；ANPR：車牌區域檢測 → 字元辨識 | PII 與 GDPR／個資法；不同族群辨識率落差；即時推論延遲 |
| **醫療影像** | 分類（CT／MRI 診斷分類）、分割（U-Net 定位腫瘤病灶） | 須由專業醫師標註；人機協作（HITL）由醫師最終審核 | HIPAA；誤檢（False Positive）造成不必要檢查、漏檢（False Negative）延誤治療 |
| **智慧製造** | 瑕疵偵測（偵測／分割） | 邊緣運算就近推論 + 即時回饋產線 | 瑕疵樣本稀少、類別不平衡、延遲上限硬性要求 |
| **零售** | 商品辨識、顧客行為分析 | 熱點圖（Heatmap）分析動線與停留時間 | 顧客影像的隱私告知與保存期限 |

自駕車是以上任務的綜合體：車道線偵測 + 物件偵測 + 分割，再加上**多模態融合**（攝影機 + 雷達 + LiDAR）提升環境感知可靠度。AR 用視覺追蹤實體物體以疊加虛擬資訊，VR 則追蹤使用者動作。

### 限制條件 → 標準解法（情境題套路）

| 題幹的限制 | 正解方向 | 常見誘答 |
|---|---|---|
| 每類僅數十張標註影像、擴充成本高 | **預訓練 CNN + 遷移學習微調** | 從頭訓練大型 ViT（資料量遠不足，必過擬合）；單純複製既有資料（未帶入新資訊） |
| 地端無 GPU、每件須 < 100ms | 遷移學習微調 + **量化（Quantization）或蒸餾（Distillation）** 壓縮後地端部署 | 採購高階 GPU（違反預算）；上雲 AutoML（影像外流 + 網路往返延遲） |
| 已在邊緣裝置仍達不到延遲、不得換硬體 | **FP32 → INT8 量化** 搭配推論引擎加速 | 批次推論（提升吞吐但單張延遲更高）；模型集成（延遲成倍增加） |
| 患者影像不得離開院內、要用公有雲算力 | **聯邦學習**：本地訓練，只上傳模型更新聚合 | 加密上傳後雲端解密（資料仍離院）；VPN 專線（只保護通道） |
| 人命攸關、責任須由人承擔 | **HITL（Human-in-the-Loop）**，醫師最終審核簽署 | 信心低於閾值即自動關機（最需謹慎的疑難案例反而停擺） |
| 要向醫師說明 CNN 判讀依據、< 200ms、不可大量採樣 | **Grad-CAM**（一次前向 + 一次反向即得類別關注熱力圖） | LIME（需數百次擾動推論）；SHAP KernelExplainer（採樣量更大）；SHAP TreeExplainer（只適用樹模型） |
| 同時有影像 + 文本 + 時序感測資料 | 影像用 **CNN**、文字用 **Transformer**、時序用 **LSTM／Temporal CNN** | 三者統一套用 BERT；把 TF-IDF 拿去處理影像 |
| 原始影像 + 非結構化文本 + 結構化特徵的儲存 | 原始影像與文本進 **Data Lake**，整理後的結構化特徵進 **Data Warehouse** | 全部塞進 Warehouse |
| 5MB 高解析影像的推論 API | **HTTP POST**，以 multipart/form-data 或 application/octet-stream 放 Request Body | GET + Base64 附在 Query String（長度受限、體積膨脹、寫進日誌） |

## 19.6 技術挑戰與風險

### 資料隱私與合規

- 影像常含個人識別資料（Personally Identifiable Information, PII）；**人臉屬高辨識性的敏感個資**，受《個人資料保護法》與 GDPR 嚴格規範
- 因應做法：去識別化（臉部遮蔽、模糊化、敏感區域遮罩）、設置攝影機前明示告知並取得同意、依資料最小化原則自動刪除或加密過期資料
- 倫理爭議的本質是「安全防護 vs 個人隱私」的平衡，例如校園人臉門禁若未取得學生與家長充分同意即有法律風險

### 偏見與模型可靠度

| 偏見來源 | 典型表現 |
|---|---|
| 資料來源不平衡 | 訓練集族群（膚色、性別、年齡）集中，對其他族群辨識率明顯較低 |
| 標註偏誤 | 標註者的主觀認知或文化偏見造成標準不一 |
| 拍攝條件偏差 | 角度、光照、解析度差異拖垮泛化能力 |

**誤檢與漏檢的產業後果不對稱**：誤檢（False Positive）在醫療端是把健康者判為病患，導致不必要的檢查；漏檢（False Negative）在製造端是瑕疵品流入市場。應對手段為偏見診斷測試（Bias Audit）、資料平衡與重加權（過採樣／欠採樣／增強），並以 AUC、精確率、召回率等多維度指標評估，而非只看準確率。

### 部署與維運

| 風險 | 說明 | 對策 |
|---|---|---|
| 算力限制 | 邊緣裝置（智慧攝影機）資源有限 | 輕量模型（MobileNet、YOLO-Nano）、量化、蒸餾 |
| 批次處理延遲 | 影像串流塞車影響即時性 | 動態批次（Dynamic Batching）調校；GPU 使用率卡在中段且 kernel 間有明顯空檔，通常是**排程與批次大小設定不當**，不是硬體效能不足 |
| 版本管理困難 | 不同版本推論結果不一致引發爭議 | MLOps：CI／CD 管線 + 模型註冊（Model Registry），可追溯、可回滾 |
| 資料漂移 Data Drift | 光照、鏡頭、場景改變導致輸入分佈變化 | 線上監控 PSI 等漂移指標、定期再訓練 |
| 部署測試不足 | 忽略實地光照變化與影像模糊 | 影像品質監測、預設容錯與回退機制 |

MLOps 的核心角色是「把訓練→測試→部署→監控→再訓練工程化並版本化」，不是資料標註品質控管（那是資料治理），也不是自動化調參（那是 AutoML）。另外要分清楚：**每個 Epoch 的學習率曲線與超參數軌跡屬於離線實驗追蹤（MLflow、W&B），不該放進線上即時監控**；線上監控追的是 P50／P95／P99 延遲、RPS、PSI、預測分佈與回收標註的對比。

## 19.7 官方考過什麼

以下為 114-2 與 115-1 官方公告試題中與本知識點直接相關的題目。**語意／實例分割的層次區辨在兩次考試合計出現 3 題（114-2 一題、115-1 兩題），是本知識點出現頻率最高、最穩定的考點。**

| 場次題號 | 考點 | 怎麼問 | 正解思路 |
|---|---|---|---|
| 115Q1-6 | 語意 vs 實例分割 | 自駕車要逐像素分類，又要區分相鄰兩名行人，兩者根本差異為何 | 語意分割同類併為一塊；實例分割為每個個體建立**獨立遮罩** |
| 115Q1-7 | 任務選型 | 防損系統要像素級遮罩 + 區分不同顧客手上的相同商品 | 兩條件並存只有**實例分割**滿足；偵測只有框、語意分割不分個體 |
| 114Q2-34 | 全景分割 | 逐像素標註道路／建築／行人，且要分辨多位行人 | 需求含**不可數背景**，實例分割不完整 → **全景分割** |
| 115Q1-10 | 單階段 vs 兩階段偵測 | 高頻影像流下 YOLO 與 Faster R-CNN 的流程差異 | YOLO 單階段直接回歸；Faster R-CNN 先 RPN 出候選區再分類 |
| 114Q2-7 | mAP 與 IoU 閾值 | IoU 閾值設高代表什麼 | 要求更高重疊度才算正確偵測 → **定位越精準** |
| 115Q1-8 | ROC 軸定義 | 皮膚病變二元分類的 ROC 橫縱軸 | X = FPR、Y = TPR；以 IoU／mAP 作圖是偵測評估，非 ROC |
| 115Q1-9 | 混淆矩陣的極限 | 哪一項無法由混淆矩陣直接算出 | **AUC**——需掃過所有閾值，單一矩陣資訊不足 |
| 115Q1-32 | CNN 程式銜接 | 卷積輸出與全連接層之間要插入什麼 | **Flatten** 展平成一維；GAP 是另一種架構選擇，非本題所問 |
| 115Q1-36 | 小樣本策略 | 10 類共約 500 張標註影像 | **預訓練 CNN + 遷移學習微調**；從頭訓 ViT 必過擬合 |
| 115Q1-23 | 導入規劃 | 瑕疵 800 張、地端無 GPU、100ms 上限、預算中等 | 遷移學習微調 + **量化或蒸餾**後地端部署 |
| 115Q1-40 | 邊緣延遲優化 | 已在邊緣仍超過 200ms，不得換硬體 | **FP32 → INT8 量化** + 推論引擎加速 |
| 115Q1-37 | 類別不平衡 | 良品 99%／瑕疵 1%，只能動資料前處理 | **SMOTE 過採樣**；正則化屬改動學習演算法 |
| 115Q1-33 | 合成資料 | 惡劣天氣場景難蒐集 | 可控條件下擴充長尾場景、提升泛化；**不能完全取代真實資料** |
| 114Q2-9 | 資料增強失效 | 增強後模型效能反而下降 | 增強後**特徵分佈偏離原始資料** → 調整策略維持語意一致性 |
| 115Q1-29 | 視覺可解釋性 | CNN 判讀理由、200ms 內、不可大量採樣、須像素區域呈現 | **Grad-CAM**；LIME／SHAP Kernel 採樣量過大 |
| 115Q1-27 | 醫療影像治理 | 人命攸關且責任須由人承擔 | **HITL**，醫師最終審核；低信心自動關機反而讓疑難案例停擺 |
| 115Q1-46 | 影像資料不外流 | 用公有雲 GPU 訓練但 CT 影像不得離院 | **聯邦學習**，只上傳模型更新 |
| 114Q2-35 | CLIP 零樣本 | 不新增標註、僅用文字提示辨識影像 | 圖文對比學習 → **共同嵌入空間** → 語意相似度零樣本分類 |
| 114Q2-50 | 跨模態對齊不足 | 生成圖的品牌標誌顏色偏差、手部不自然 | 文字與影像編碼器在語意嵌入空間**對齊不足** |
| 114Q2-38 | Diffusion 調參 | 4K 產品圖出現顆粒化與模糊 | **增加取樣步數 + 高品質取樣器**；提高 CFG 會過飽和 |
| 114Q2-20 | GAN 模式崩潰 | 人臉生成只產出少數重複樣本 | 改用 **Wasserstein 距離（WGAN 損失）** |
| 115Q1-17 | 多模態架構配置 | X 光影像 + 病歷文字 + 生理時序 | 影像 **CNN**、文字 **Transformer**、時序 **LSTM／Temporal CNN** |
| 114Q2-45 | 降維 + 分類 | 影像特徵 1024 維經 PCA 降至 100 維再進 SVM | 降低訓練時間、減少過擬合風險；PCA 是線性轉換，不會讓 SVM 自動處理非線性 |

## 19.8 易錯與陷阱

- [ ] 語意分割是「每個像素一個**類別**」，**不是**「每個像素一個**個體**」——後者是實例分割
- [ ] 實例分割通常**先出 Bounding Box 再出遮罩**，不出框的是語意分割；把兩者的框／遮罩對調是官方最愛的誘答
- [ ] 「像素級 + 區分個體」→ 實例分割；**再加上道路、建築等背景類別**才升級為全景分割，兩者不可混用
- [ ] 物件偵測**能**區分同類的不同個體（每個框就是一個實例），它缺的是**像素級精度**，不是個體區分能力
- [ ] 標註成本由低到高：類別標籤 < 邊界框 < 像素遮罩 < 遮罩 + 實例 ID；情境題提到「標註成本高昂」時，優先想遷移學習、自動化標註、主動學習
- [ ] YOLO 快是因為**取消**候選區域階段，不是因為候選區域「變多」；Faster R-CNN 是**兩**階段，不是單階段
- [ ] IoU 閾值調高代表**要求更精準的定位**，不是讓 mAP 變高；閾值越高，達標越難
- [ ] ROC 的 X 軸是 **FPR**、Y 軸是 TPR；**PR 曲線是 X 軸 Recall、Y 軸 Precision**，兩條曲線的軸別不要對調；以 IoU 對 mAP 作圖屬偵測評估，與二元分類 ROC 無關
- [ ] 混淆矩陣可以算出 Precision／Recall／Accuracy，**唯獨算不出 AUC**
- [ ] PyTorch 中卷積接全連接**必須 Flatten**；Global Average Pooling 是可替換的架構設計，不是題目問的基本銜接
- [ ] ViT 缺乏卷積的歸納偏置，**小資料集不能從頭訓練**；小樣本情境的標準答案永遠是「預訓練 + 遷移學習微調」
- [ ] 資料擴增是在**訓練集**上做，且必須維持**語意一致性**；增強比例拉滿只會加劇分佈偏移
- [ ] 合成資料能補長尾場景，但有 **Domain Gap**，不能完全取代真實資料
- [ ] 降延遲用**量化／蒸餾／輕量模型**；批次推論提升的是**吞吐量**，單張端到端延遲反而變高；模型集成讓延遲成倍增加
- [ ] 資料不得外流 → **聯邦學習**；「加密上傳後在雲端解密」與「VPN 專線」都讓原始資料離開了原場域
- [ ] 醫療影像的安全機制是 **HITL 人工複核**，不是「信心低就自動關機」
- [ ] 要即時解釋 CNN 判讀依據選 **Grad-CAM**；LIME 與 SHAP KernelExplainer 需大量重複採樣，SHAP TreeExplainer 只能用於樹模型
- [ ] CLIP 的能力來自**對比學習 + 共同嵌入空間**帶來的零樣本分類，不是「影像增強降低標註需求」，也不是自迴歸生成文字標籤
- [ ] GAN 的模式崩潰主流解法是 **WGAN 損失**；梯度懲罰是搭配 WGAN-GP 用來穩定訓練的輔助手段
- [ ] Diffusion 生成細節不足要**增加取樣步數**；提高 CFG 是加強提示遵循，過高會造成過飽和與假影
