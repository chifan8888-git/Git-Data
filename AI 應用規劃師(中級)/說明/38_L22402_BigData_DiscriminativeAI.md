## 38.1 鑑別式 vs 生成式：學的東西根本不同

這是本節與 L22403 共同的主軸，也是整個 L224 最容易被誘答的一格。
**差別不在「能做什麼」，而在「模型學的是哪一個機率」。**

| 維度 | 鑑別式 AI（Discriminative） | 生成式 AI（Generative） |
|---|---|---|
| **學的機率** | 條件機率 **P(Y&#124;X)**，或直接學決策邊界／判別函數 | 資料分佈 **P(X)**，或聯合分佈 **P(X,Y)** |
| **白話** | 「給我一筆資料，它屬於哪一類／數值是多少」 | 「資料長什麼樣子，我能再產生一筆像它的」 |
| **核心動作** | 區分、分類、預測 | 生成、合成、重建 |
| **輸出** | 類別標籤、機率、分數 | 新的文字／影像／聲音／表格樣本 |
| **是否需標籤** | 監督式為主，**高度依賴標註品質** | 可大量使用未標註資料做自監督預訓練 |
| **代表模型** | 邏輯迴歸、SVM、決策樹／隨機森林、XGBoost／LightGBM、CNN 分類器、BERT 分類頭、GNN | 樸素貝氏、GMM、HMM、VAE、GAN、Diffusion、大型語言模型 |
| **典型任務** | 信用評分、詐欺偵測、流失預測、影像診斷、情感分類、異常偵測 | 文案生成、影像生成、資料增強、合成資料 |

### 兩個最常被寫反的點

```
鑑別式：不管資料「怎麼來的」，只關心「界線在哪裡」
        → 不建模 P(X)，所以樣本分佈一旦偏移（Data Drift），
          模型本身無從察覺，只能靠外部監控

生成式：先學會「資料長什麼樣」，再用貝氏定理推回 P(Y|X)
        → 所以生成式模型也可以拿來做分類（樸素貝氏就是最典型的例子）
```

> **「生成式模型不能分類」是錯的。** 樸素貝氏（Naive Bayes）建模 P(X|Y)·P(Y)，
> 是標準的生成式模型，卻被大量用於垃圾信與文本分類。
> 反過來，**邏輯迴歸雖然名字有「迴歸」，學的是 P(Y=1|X)，是鑑別式分類模型**。
> 這兩個名稱陷阱是同一類誘答的兩面。

### 為什麼企業先導入鑑別式 AI

| 比較項 | 鑑別式 | 生成式 |
|---|---|---|
| 商業價值衡量 | 可直接換算成攔截率、壞帳率、回應率等 KPI | 較難量化，多為效率與體驗提升 |
| 驗收方式 | 有標準答案，可用混淆矩陣客觀評估 | 常需人工評分或間接指標 |
| 資料門檻 | 需要**有標籤**的歷史資料，企業內部通常已累積 | 需要極大規模語料與算力 |
| 風險型態 | 誤判成本明確（誤攔／漏抓） | 幻覺、著作權、個資外洩等較難窮舉 |

## 38.2 五大應用場域：每一個需要什麼樣的大數據

官方把鑑別式 AI 的落地情境分成五類。**背的時候用「輸入資料型態」串起來最快**，
因為考題通常給情境、問模型或問挑戰。

| 場域 | 任務目標 | 需要什麼樣的大數據支撐 | 常見模型 | 主要挑戰 |
|---|---|---|---|---|
| **金融與風險管理** | 信用評分、詐欺偵測、反洗錢（AML）異常辨識 | 長時間跨度的交易紀錄（金額／時間／地點）、客戶屬性、API 交易日誌；AML 另需**轉帳關係圖（Graph Data）** | 邏輯迴歸（可解釋，適合信用評分）、隨機森林、**XGBoost／LightGBM**（不平衡）、**GNN**（AML 網路關係） | 類別極不平衡、個資法遵循與欄位匿名化、異常值未處理造成誤判 |
| **零售與電商推薦** | 顧客流失預測、客戶分群與精準行銷、商品分類／價格預測 | 購買紀錄＋用戶屬性（結構化）、點擊日誌 JSON（半結構化）、評論文字與商品圖片（非結構化）→ **典型多模態** | 決策樹／隨機森林、LSTM（價格時序）、CLIP 等多模態模型 | 多來源格式不一致、商品分類標註成本高、推薦需**即時處理串流**（如 Kafka） |
| **客服與文本分類** | 對話分類、情感分析、內容過濾與審查 | 大量**標註一致**的對話與評論語料；在地化詞典 | 樸素貝氏／SVM（簡單文本）、**BERT／RoBERTa**（高準確度）、正規表示式（簡單違規檢測） | 標註一致性、台灣用語在地化、高缺失或邏輯錯誤污染統計檢定 |
| **醫療與健康科技** | 疾病預測與診斷、保險理賠異常分析、臨床決策支援 | 結構化病歷＋醫療影像＋醫師筆記的**多模態**資料；**必須由專家標註** | **CNN**（ResNet／VGG 影像分類）、隨機森林／XGBoost（病歷）、CNN＋BERT 多模態 | 隱私與加密、**專家標註成本極高 → 用主動式學習**、生理訊號異常值 |
| **資安與異常偵測** | 登入行為異常辨識、惡意流量分類、釣魚郵件分類 | 高頻登入紀錄與封包元資料、JSON／CSV 日誌串流；要求**低延遲** | **孤立森林（Isolation Forest）**、LSTM（流量序列）、BERT（郵件）、正規表示式 | 異常樣本比例極低、即時性依賴串流平台、**日誌重複值**扭曲統計 |

### 官方列出的實務案例（數字偶爾被題幹直接引用）

| 場域 | 案例 | 成果 |
|---|---|---|
| 金融 | 某銀行以 XGBoost 結合交易與信用資料預測違約 | 準確率提升至 85%，壞帳損失減少 20% |
| 電商 | 某平台以隨機森林預測顧客流失 | 識別 90% 高風險顧客，行銷回應率提升 12% |
| 客服 | 某電信以 BERT 分類客服對話 | 識別 95% 物流問題，人工處理時間減少 30% |
| 醫療 | 某醫院以 ResNet 分析 X 光片 | 肺炎診斷準確率 92%，誤診率減少 25% |
| 資安 | 某企業以孤立森林分析登入日誌 | 識別 98% 異常登入，安全事件減少 40% |

### 一個常被混淆的邊界：異常偵測 ≠ 預測

```
異常偵測（Anomaly Detection）：找出「與正常模式明顯不同」的少數樣本
  → 即時比對交易行為是否偏離常態、登入是否來自可疑裝置

預測（Regression / Time Series）：用歷史資料推估「未來的數值」
  → 預測旺季是否缺貨、預測次日登入量

分類（Classification）：判斷樣本屬於哪一個已定義的類別
  → 預測客戶是否違約、郵件是否為釣魚
```

> 官方考過一題正是要求在四個選項中挑出**真正屬於異常偵測**的情境：
> 「即時分析金融交易資料流，偵測與平常行為明顯不同的可疑紀錄」才是正解；
> 「預測旺季是否缺貨」「預測次日登入量」是迴歸／時間序列，「預測是否違約」是分類。
> **三者在官方指引裡都被列為鑑別式 AI 的任務目標，但不是同一種任務。**
> （補充：異常偵測若缺乏標註，實作上會改用孤立森林等非監督方法，
> 這不影響它在應用分類上仍屬鑑別式 AI 的範疇。）

## 38.3 輸入資料型態與處理前提

| 型態 | 來源 | 特性 | 進模型前要做什麼 |
|---|---|---|---|
| **結構化** | ERP／CRM／POS 的關聯式資料庫、感測器讀值 | 欄位明確、格式規範 | 直接轉成表格式特徵；數值標準化、類別編碼 |
| **半結構化** | JSON／XML 的 API 回傳、伺服器日誌、點擊流 | 有層次結構但**欄位可能動態變動** | **解析（Parsing）與展平（Flattening）** |
| **非結構化** | 文字（對話、評論、郵件）、影像（X 光、商品照、監控）、聲音（客服錄音） | 無固定結構 | **特徵萃取（Feature Extraction）**轉成數值表示（詞向量、CNN 特徵、ASR 轉錄） |
| **多模態** | 上述型態的組合，如用戶屬性＋評論文字＋商品圖 | 需要多輸入架構 | **特徵級融合**或多分支模型 |

> 半結構化最常被問的關鍵動作是**展平**（把巢狀 JSON 攤成欄位），
> 非結構化最常被問的是**特徵萃取**。這兩個動詞不要互換。

## 38.4 標註策略：四選一的判斷依據

鑑別式 AI 靠監督學習，**標籤的成本與品質直接決定專案可行性**。

| 策略 | 做法 | 優點 | 限制 | 什麼情境選它 |
|---|---|---|---|---|
| **人工標註** | 由具備專業的人逐筆標 | 準確度最高 | 成本高、耗時、**難以規模化** | 醫療影像、法律文件等**需要專業知識** |
| **弱監督式標註** | 用規則、啟發式或第三方資料（如情緒詞典）自動產生標籤 | 速度快、成本低、適合大規模 | **誤標風險高**、品質不穩定，需後續清理 | 社群貼文情感、商品粗分類等可先求有 |
| **群眾外包** | 透過 MTurk、Appen 等平台分散給大量非專業者 | 成本低、速度快 | 品質參差，需**一致性檢查與多工審核** | 圖片是否含某物件等**簡單任務** |
| **主動式學習** | 模型挑出**低置信度樣本**優先交人工標 | 用最少標註量換最大效益 | 需初始標註資料與迭代訓練，技術門檻高 | 標註**成本高且資料量大**（醫療影像、詐欺專家審核） |

```
標註策略決策流
  需要專業判斷？
    ├─ 是 ─→ 標註成本是瓶頸？
    │          ├─ 是 ─→ 主動式學習（只標模型不確定的）
    │          └─ 否 ─→ 人工標註
    └─ 否 ─→ 任務能寫成規則或查詞典？
               ├─ 是 ─→ 弱監督式標註
               └─ 否（需人眼但不需專業）─→ 群眾外包
```

> 官方舉的主動式學習例子很具體：詐欺偵測模型挑出**置信度 < 0.6** 的交易交專家標註。
> 記住「挑不確定的」這個動作，就不會和「隨機抽樣標註」混淆。

## 38.5 跨來源整合與資料品質

### 四類整合障礙

| 障礙 | 具體症狀 | 官方舉例 |
|---|---|---|
| **主鍵不一致** | 各系統的用戶 ID／裝置 ID／訂單編號定義不同，無法直接對應 | CRM 與 POS 用不同客戶 ID，資料合不起來 |
| **時間戳記與時區** | 時間欄位有延遲、格式差異或時區不一致 | 網站日誌用 UTC、POS 交易用台北時間 |
| **更新頻率不一致** | 一邊是即時串流、一邊是批次同步，時間視窗對不齊 | 即時點擊流 vs 每日更新的庫存資料 |
| **資料品質不均** | 缺失、格式不一致、單位不統一 | API 缺關鍵欄位；ERP 一邊寫「1,000 克」一邊寫「1 公斤」 |

### 五類資料品質問題各自傷害什麼

| 問題 | 對鑑別式模型的影響 | 對統計推論的影響 |
|---|---|---|
| **缺失值** | 特徵不完整，線性模型訓練失真 | 影響 t 檢定的均值估計 |
| **異常值** | 放大誤差、**扭曲決策邊界** | 影響獨立樣本 t 檢定 |
| **重複值** | **高估樣本權重**，類別比例失真 | 影響卡方檢定 |
| **一致性錯誤** | 格式不統一導致無法正確聚合特徵 | 影響 ANOVA 等檢定結果 |
| **邏輯錯誤（錯誤標籤）** | 模型**學到錯誤模式**，預測準確度直接下降 | 分組結論失效 |

> 考題很愛把「重複值」與「異常值」的後果對調。
> **重複值造成的是樣本權重被高估與比例失真，不是決策邊界被拉歪；
> 把決策邊界拉歪的是異常值。**

### 特徵一致性：多團隊共用的管理問題

當公司裡 A 隊做信用評分、B 隊做詐欺偵測，兩邊都要「使用者過去 30 天交易行為」時，
各做各的會導致**同一份特徵邏輯被實作兩次、定義一改要兩邊同步、訓練與線上口徑不一致**。
導入特徵平台統一管理共用特徵，主要目的是**消除跨團隊重複開發、降低長期維護成本**——
不是為了解決推論延遲、儲存空間或模型版本管理（後者屬於模型註冊表與實驗追蹤的範圍）。

## 38.6 不平衡大數據下的評估與切分（本節最高頻考點）

### 混淆矩陣與五個指標

```
                     預測為陽性      預測為陰性
  實際為陽性            TP              FN      ← 漏抓（偽陰性）
  實際為陰性            FP              TN
                        ↑ 誤報（偽陽性）

  scikit-learn 的 confusion_matrix(y_true, y_pred)：
      橫列（row）= 真實類別，直欄（column）= 預測類別
```

| 指標 | 公式 | 回答什麼問題 | 何時該看它 |
|---|---|---|---|
| **準確率 Accuracy** | (TP+TN)／全部 | 整體對了幾成 | 類別大致平衡時才有意義 |
| **精確率 Precision** | TP／(TP+FP) | **報警的裡面有幾成是真的** | 誤報成本高（誤凍結帳號、誤召回商品） |
| **召回率 Recall** | TP／(TP+FN) | **真的裡面被抓到幾成** | 漏抓成本高（詐欺、疾病、外掛） |
| **F1** | 2·P·R／(P+R) | 兩者的**調和平均** | 要同時兼顧，且不想被單一項偏高騙 |
| **AUC-ROC** | ROC 曲線下面積 | 跨所有門檻的整體區辨力 | 類別不至於極端不平衡時 |
| **PR-AUC** | PR 曲線下面積 | 對**少數類**的區辨力 | 正例比例極低時比 AUC-ROC 更敏感 |

**兩條曲線的軸，寫反就整題錯：**

```
ROC 曲線：X 軸 = FPR（假陽率）      Y 軸 = TPR（真陽率，即 Recall）
PR  曲線：X 軸 = Recall（召回率）   Y 軸 = Precision（精確率）
```

> ROC 曲線是**同一個模型**在門檻由高到低移動時描出的軌跡。門檻放寬時被判為陽性的樣本只增不減，
> 所以 TPR 與 FPR 都**單調不減**，曲線必定從 (0,0) 單調上升到 (1,1)，**中途不會下降**。
> 對角線 TPR = FPR 代表隨機猜測，AUC = 0.5。
>
> F1 用的是**調和平均**而非算術平均——只要 Precision 或 Recall 有一項偏低，F1 就會被拉低。
> 多類別時 `average="weighted"` 是**依各類別樣本數（support）加權**，
> `average="macro"` 才是各類別的算術平均，兩者在樣本數不均時結果不同。

### 準確率陷阱：官方反覆考的同一件事

在正常交易佔 99.5%、詐欺佔 0.5% 的資料上，
**一個永遠預測「正常」的空模型就有 99.5% 準確率，但詐欺的召回率是 0%。**
此時準確率幾乎只反映多數類的比例，**喪失區辨模型好壞的能力**。

正確的改善方向有三層，官方分別考過：

| 層次 | 做法 | 對應題目情境 |
|---|---|---|
| **評估層** | 改看 Precision／Recall／F1／PR-AUC，不再以 Accuracy 為唯一指標 | 反詐欺 99.5%、外掛偵測 99.95% |
| **學習層** | **Class Weight 或成本敏感學習（Cost-sensitive Learning）**，在損失函數中放大少數類誤判的懲罰 | 信用卡詐欺 99.6% 準確率卻攔不到詐欺 |
| **資料層** | 重抽樣（過採樣／欠採樣／SMOTE） | 罕見疾病確診樣本不到 1% |

> **只改看 Precision 不是解方。** 模型只要更保守、幾乎不發警報就能把 Precision 拉高，
> 反而讓真正的詐欺更攔不到。風控場景要壓的是**偽陰性**。

### 重抽樣三選一

| 方法 | 機制 | 最常見的副作用 |
|---|---|---|
| **隨機過採樣** | 直接**複製**少數類樣本 | **過擬合風險升高**（複製樣本與原樣本完全相同，模型容易死記） |
| **隨機欠採樣** | 刪掉部分多數類樣本 | **丟失多數類資訊**；少數類本就稀少時更不可取 |
| **SMOTE** | 在少數類**特徵空間插值**生成合成樣本 | 多樣性較高、過擬合風險較低，但**只能在訓練集上做** |

> **SMOTE 必須在訓練／測試切分之後、只對訓練集執行。**
> 若先對全體資料做 SMOTE 再切分，由測試集樣本插值產生的合成點會落進訓練集，
> 測試集資訊等同外洩，AUC 會虛高而不可信。
> 同樣的道理適用於**標準化與特徵篩選**：任何會「從資料學參數」的步驟，
> 都必須只用訓練集擬合、再套用到測試集。在含測試集的全體資料上算相關係數來刪特徵，
> 就是典型的資料洩漏（Data Leakage）。

### 門檻調整的方向

```
決策門檻 ↓（從 0.5 往下調）→ 更多樣本被判為陽性 → TP↑、FN↓ → Recall ↑
                                                   FP↑        → Precision 通常 ↓

決策門檻 ↑ → 模型更保守 → Precision ↑、Recall ↓
```

> 「寧可錯殺、不可放過」→ **降低門檻以最大化 Recall**，誤判的再交人工覆核。
> 「特異度（Specificity = TN／(TN+FP)）要 100%」則是相反的要求——
> 等於不許誤判任何正常樣本，模型幾乎不敢發警報，Recall 會被壓到極低。

### 切分方式要對症

| 資料特性 | 該用的切分 | 為什麼 |
|---|---|---|
| 類別不平衡（如 80% 為良性腫瘤） | **分層 K 折交叉驗證（Stratified K-Fold）** | 確保每一折的類別比例與整體一致，避免某折失衡造成評估偏差 |
| 同一個體有多筆紀錄（同一病患、同一用戶） | **分組交叉驗證（Group K-Fold）** | 避免同一個體同時出現在訓練與測試集而高估效能 |
| 時間序列（銷售、流量預測） | **依時間順序切分＋前進式驗證（Walk-Forward Validation）** | 隨機切分會讓未來資料混進訓練集，造成洩漏 |

> 降低 K 值、改用拔靴法（Bootstrap）、或刻意調整測試集的類別比例，
> **都不能修正類別失衡造成的評估偏差**——這三個是同一題的三個誘答。

## 38.8 易錯與陷阱

- [ ] 鑑別式學的是 **P(Y|X) 或決策邊界**，不是 P(X) 或 P(X,Y)；後者才是生成式
- [ ] **樸素貝氏是生成式模型**卻常用於文本分類，不是「生成式模型不能分類」
- [ ] **邏輯迴歸是鑑別式分類模型**，不是因為名字有「迴歸」就歸到迴歸任務
- [ ] 異常偵測找的是**偏離常態的少數樣本**，不是推估未來數值；後者是迴歸／時間序列
- [ ] 有可靠標註時，**監督式二元分類可以做異常偵測**；分群與離群值法是缺標註時的替代方案，不是唯一途徑
- [ ] 半結構化資料要做的是**解析與展平**，非結構化才是**特徵萃取**
- [ ] 主動式學習挑的是**模型低置信度的樣本**，不是隨機抽樣，也不是挑模型最有把握的
- [ ] 弱監督式標註靠**規則或詞典自動產標**，瓶頸是誤標；群眾外包靠**大量非專業人力**，瓶頸是品質參差——兩者卡的點不同
- [ ] **重複值**造成樣本權重高估與比例失真；**異常值**才是扭曲決策邊界的那一個
- [ ] 極不平衡時，光是「永遠猜多數類」就能拿到等於多數類比例的 Accuracy，**高準確率不等於模型有用**
- [ ] **Precision 是報警之中有幾成為真**（分母 TP+FP）；**Recall 是真的之中抓到幾成**（分母 TP+FN）
- [ ] **ROC 曲線 X 軸是 FPR、Y 軸是 TPR**；**PR 曲線 X 軸是 Recall、Y 軸是 Precision**
- [ ] ROC 曲線必定**單調不減**，中途下降的曲線不會是 ROC
- [ ] **F1 是調和平均**，不是算術平均；`average="weighted"` 依樣本數加權，`average="macro"` 才是算術平均
- [ ] **降低門檻是提高 Recall**、壓低偽陰性；提高門檻才是提高 Precision——「寧可錯殺」要往下調
- [ ] **隨機過採樣的主要副作用是過擬合**，不是收斂變慢，也不會減少資料總筆數
- [ ] **SMOTE、標準化、特徵篩選都必須在切分後只用訓練集擬合**，順序錯了就是資料洩漏
- [ ] 類別不平衡用**分層 K 折**；同一個體多筆紀錄要用**分組 K 折**；時間序列要**依時間切分**——三者處方不同
- [ ] 降低 K 值、改用拔靴法、調整測試集比例，**都不能修正類別失衡造成的評估偏差**
- [ ] 共用特徵平台的主要目的是**降低跨團隊重複開發成本**，不是解決推論延遲或模型版本管理
