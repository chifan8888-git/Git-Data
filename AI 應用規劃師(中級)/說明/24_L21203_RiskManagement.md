# 24. L21203 AI風險管理（50 分鐘）

> 一句話定位：本知識點是科目 1「AI 導入評估規劃」的收尾，把前面的可行性評估、資源盤點與流程規劃全部收束到一個問題上——**這套 AI 上線後會出什麼事？我事前怎麼擋、事後怎麼發現、出事後誰負責。**
> 與初級的落差：初級 L111 只要求認得「偏誤、可解釋性、EU AI Act」這些名詞；中級要求看到一段情境敘述，就能判斷**這是哪一類風險、該用哪一種手段、這個手段屬於事前預防還是事後追溯**。
> 本知識點在 114-2／115-1 兩份官方試題的實測命中率僅 **21%**，失分主因通常不是內容艱深，而是「風險徵狀 → 風險類型」的對應沒背熟，誘答一換包裝就選錯。

## 學習目標
- 依「技術層／組織人力層／法規層」三層架構，指認任一情境屬於哪一類 AI 風險
- 區辨資料漂移、模型漂移、概念漂移與訓練服務偏差四者的判別依據與對應作法
- 說出 GDPR、PDPA、HIPAA、PCI-DSS 的適用對象與核心要求，並判斷合規手段是否對症
- 為給定情境選出正確的風險控管策略（迴避／轉移／緩解／接受）與監控工具

## 24.1 風險徵狀 → 風險類型 → 對應手段（本節必背）

中級考題幾乎不會直接問「什麼是資料品質風險」，而是丟一段**徵狀描述**要你倒推類型與手段。下表是本知識點的核心對照，建議整張背下來。

| 題幹出現的徵狀 | 風險類型 | 層級 | 對應手段（正解方向） |
|---|---|---|---|
| 輸出不穩定且缺乏邏輯可解釋性 | **決策透明性風險**（透明度／可解釋性不足） | 技術／倫理 | 導入 SHAP、LIME、反事實解釋，提供個案層級的特徵貢獻說明 |
| 特定族群預測結果不公平 | **模型偏誤風險**（Bias / Fairness） | 技術／倫理 | 檢視資料分布與標註、分群評估、公平性約束訓練 |
| 輸入資料分佈長期改變、準確率緩降 | **概念漂移／資料漂移** | 技術 | 建置漂移監控（PSI、KL 散度）並觸發模型再訓練流程 |
| 資料缺值、標註錯誤、樣本不具代表性 | **資料品質風險** | 技術 | 資料清洗、標註品質稽核、補足代表性樣本 |
| 訓練集表現好、上線後表現差 | **模型穩定性風險**（過擬合／模型漂移） | 技術 | 交叉驗證、正則化、上線後持續監控與再訓練 |
| 業務單位與 IT 需求脫節、責任不清 | **跨部門溝通風險** | 組織人力 | 建立跨部門協作機制與明確角色分工 |
| 團隊缺乏資料科學／模型維運人員 | **技能短缺風險** | 組織人力 | 教育訓練、外部專家、關鍵角色補實 |
| 員工擔心被取代、系統使用率低落 | **變革抵制風險** | 組織人力 | 溝通 AI 定位、內部培訓、以人機協作而非取代為訴求 |
| 未取得使用者同意即使用個資 | **個資與隱私保護風險** | 法規 | 檢視個資使用的合法性、同意機制、資料最小化 |
| 生成內容疑似抄襲、使用第三方資料未授權 | **侵權風險** | 法規 | 從**訓練資料源頭**建立篩選與授權驗證機制 |
| 醫療／金融導入未符產業規範 | **產業特定監管法規風險** | 法規 | 對照 HIPAA／PCI-DSS／醫療器材管理法逐項合規 |
| 事後無法證明某筆決策由誰、何時做出 | **不可否認性／可稽核性不足** | 法規／資安 | 推論輸入輸出留存雜湊值並加數位簽章 |

### 三層風險地圖

```
AI 專案風險
├─ A. 技術層
│    ├─ 資料品質風險：資料遺漏、資料偏頗、不正確標註、資料漂移
│    │    案例：信用評分系統因歷史資料偏差，導致特定族群被歧視
│    ├─ 模型穩定性風險：模型漂移（Model Drift）、過擬合（Overfitting）
│    │    案例：製造業瑕疵辨識系統在產線微調後精準度下降，成本上升
│    └─ 概念漂移（Concept Drift）：資料背後的潛在關係改變
│
├─ B. 組織人力層
│    ├─ 跨部門溝通風險：資訊不透明、角色責任不清
│    ├─ 技能短缺風險：技能落差、人才流動過快
│    └─ 變革抵制風險：員工視 AI 為職位威脅，配合度低
│
└─ C. 法規層
     ├─ 個資與隱私保護風險：GDPR、台灣個資法
     ├─ 產業特定監管風險：HIPAA、PCI-DSS、醫療器材管理法
     └─ 侵權風險：第三方資料／演算法／開源授權條款
```

**考點提醒：** 官方明白指出 AI 風險「不同於傳統 IT 專案」之處，就在於 **B 與 C 之外，多了資料偏誤、模型不透明這種 A 層特有的風險**。看到題目問「AI 專案相較傳統 IT 專案額外要考量什麼」，答案往往落在資料品質、模型透明度、倫理合規。

## 24.2 四種「漂移」的辨別（最常被混淆的一組）

| 名稱 | 定義 | 判別關鍵（題幹會給的線索） | 對應作法 |
|---|---|---|---|
| **資料漂移** Data Drift | 輸入特徵的**分佈**隨時間改變 | 「輸入特徵分佈與訓練資料明顯不同」 | PSI、KL 散度偵測分佈差異；VAE 監控潛在空間 |
| **概念漂移** Concept Drift | 特徵與**目標標籤之間的關聯**改變 | 「特徵分佈**沒有**明顯變化」但真實風險性質已變 | 重新標註、再訓練、調整業務規則 |
| **模型漂移** Model Drift | 模型預測準確度隨時間變差（統稱現象） | 「上線後準確率逐漸下降」 | 效能監控 + 自動重新訓練 |
| **訓練服務偏差** Training-Serving Skew | 離線與線上**特徵處理邏輯不一致** | 「一上線就不對」，且改過特徵工程 | 統一特徵管線、Feature Store |

**最高頻的誘答設計：** 題幹寫「特徵分佈未出現明顯變化，但攔截率下降」——這是**概念漂移**，不是資料漂移。只要看到「特徵分佈沒變」五個字，立刻排除 Data Drift。

## 24.3 法規與合規性評估

### GDPR：資料主體的權利與企業義務

| 權利／原則 | 條文 | 白話理解 | 常見考法 |
|---|---|---|---|
| 刪除權（被遺忘權） | 第 17 條 | 要求企業刪除個資 | 注意：法律要求保留或公共利益時**不完全適用** |
| 修正權 | 第 16 條 | 資料錯誤或不完整可要求更正 | — |
| 資料可攜權 | 第 20 條 | 以結構化、機器可讀格式取回並轉移 | 易與「查閱權」混淆 |
| 反對自動化決策權 | 第 22 條 | 重大自動化決策可要求**人工介入** | 對應信用評分、招聘場景 |
| 查閱權 | 第 15 條 | 了解處理目的、類型、保存期限，**一個月內**（約 30 日）回覆，複雜案件可再延長兩個月 | 資料主體八項權利中唯一有明確期限者 |
| 處理限制權 | 第 18 條 | 爭議期間暫停處理，但不刪除 | — |
| 同意原則 | 第 6 條 | 明確、自由給予，且**可隨時撤回**（不溯及既往） | — |
| 資料最小化 | 第 5 條 | 只收集達成目的所必需的資料 | 對應「蒐集越多越好」的錯誤選項 |
| 問責制 | 第 5、24 條 | 必須能**證明**已落實措施並保留紀錄 | 對應稽核、文件化 |
| DPIA 資料保護影響評估 | 第 35 條 | 高風險處理前必須先做評估 | 屬**事前**機制 |
| 資料外洩通報 | 第 33 條 | 知悉外洩後 **72 小時內**通報監管機關 | 企業義務而非資料主體權利，與查閱權的一個月常被對調 |

### 各法規適用範圍對照

| 法規／標準 | 主管或來源 | 適用對象 | 核心要求 |
|---|---|---|---|
| **GDPR** | 歐盟 | 處理歐盟居民個資者，**不論企業是否在歐盟境內** | 上表八項權利與原則、DPIA |
| **PDPA**（台灣個資法） | 台灣 | 在台或涉台灣居民個資處理的組織 | 特定目的告知、查閱／複製／更正／刪除、停止蒐集處理使用、安全維護措施 |
| **CDPA** | 美國州法（如維吉尼亞州） | 特定州境內個資處理 | 查閱／修正／刪除／可攜；敏感資料更嚴格保護 |
| **HIPAA** | 美國 | 醫療機構、保險公司與第三方合作廠商 | 技術性（加密、存取控制、安全傳輸儲存）／實體性（設備管控、備份災復）／行政性（政策程序、員工培訓、定期風險評估）三類保護措施 |
| **PCI-DSS** | PCI SSC | 所有處理支付卡資訊的機構 | 防火牆與入侵偵測、TLS／AES 加密、多因素認證與權限最小化、弱點掃描與滲透測試、員工訓練與內部稽核 |
| **金融科技創新實驗條例** | 金管會 | 金融創新業務測試 | 沙盒審核、個資安全、試行合規確認 |
| **醫療器材管理法** | 衛福部 TFDA | 含醫療 AI 產品 | 上市許可、品質與安全標準 |
| **電信管理法** | NCC | 含 AI 通訊服務業者 | 網路安全、資安管理、消費者權益 |
| **智慧財產權法** | 經濟部智慧局 TIPO | AI 模型與資料集 | 著作權、專利、商標的取得與使用範圍 |

**記憶捷徑：** HIPAA 的三類保護措施（技術性／實體性／行政性）是最容易出「下列何者屬於行政性保護措施」的題型——**員工培訓、安全政策、定期風險評估屬行政性**，加密與存取控制屬技術性，機房與備份屬實體性。

## 24.4 偏見與倫理

### 偏見的四種來源

| 來源 | 成因 | 典型情境 |
|---|---|---|
| **資料分布不均** Imbalanced Data | 某群體樣本不足 | 醫療資料缺某性別／年齡層，診斷準確度不均 |
| **歷史偏見** Historical Bias | 歷史資料本身反映既有社會不公 | 過去信用審核紀錄含種族或性別偏見，模型繼承並放大 |
| **標註偏見** Labeling Bias | 標註者的主觀、文化背景或刻板印象 | 情緒標註對特定族群書寫風格判斷不一致 |
| **演算法偏見** Algorithmic Bias | 為整體效能最佳化而犧牲特定群體 | 推薦系統以多數用戶偏好為準，忽略少數群體 |

歧視性結果的兩大衝擊：**弱勢群體受到不公平待遇**（貸款、招聘、醫療資源分配）、**企業品牌與信譽損害**（輿論反彈、訴訟與監管處罰）。

### 四大倫理原則

```
透明度 Transparency   → 對外說明模型如何處理資料、如何決策、可能影響
可解釋性 Explainability → 對「這一筆」決策說出理由，讓當事人能理解並申訴
公平性 Fairness        → 積極避免對特定群體的歧視，最小化偏差
問責性 Accountability  → 明確的責任人、可快速識別與修正問題
```

**透明度 vs 可解釋性的分界（高頻誘答）：**
- 透明度 = **對整體系統**的公開揭露（用了什麼資料、運作邏輯、社會影響）
- 可解釋性 = **對單一決策**的理由說明（哪些特徵、貢獻多少、方向為何）
- 題幹若出現「對被拒絕的**每一筆**申請提供具體理由」→ 答案是**可解釋性**，不是透明度。

國際依據：歐盟《可信任 AI 倫理指導原則》（AI HLEG, 2019）、OECD《人工智慧高級準則》（2019）、聯合國／UNESCO、GPAI、ISO/IEC 標準。

### 企業內部倫理治理框架（四件事）

| 措施 | 做什麼 | 時機 |
|---|---|---|
| **倫理委員會** | 跨技術、法律、人權、風險管理的獨立審查組織 | 常設 |
| **AI 審查流程** | 風險評估、影響分析、預防措施建議 | **模型部署前**必經環節 |
| **內部教育訓練** | 提升員工對偏見、歧視等倫理風險的敏感度 | 定期 |
| **透明度與對外溝通** | 公開使用原則與社會影響，接受外部回饋 | 持續 |

## 24.5 風險緩解策略與工具

### 四種風險控管策略

| 策略 | 定義 | 適用時機 | 官方舉例 |
|---|---|---|---|
| **迴避** Avoidance | 不執行該活動，從根本避免 | 潛在損害嚴重且難以控制、法規限制嚴格 | 醫療 AI 訓練資料不足、誤診風險過高 → **暫緩專案**；金融機構無法符合新隱私法規 → 取消雲端部署 |
| **轉移** Transfer | 透過第三方承擔潛在損失 | 損失可量化、有市場化的承擔者 | 購買 **AI 系統故障保險**；與供應商簽 **SLA**，延遲超標由供應商賠償 |
| **緩解** Mitigation | 主動降低發生機率或影響（**最常見**） | 多數技術與法規風險 | 資料清洗移除異常值提升準確率；導入資料加密與合規培訓通過 HIPAA 審查；交叉驗證、持續監控 |
| **接受** Acceptance | 承認並持續監控，不額外投入 | **低衝擊**且控管成本高於效益 | 小規模資料漂移僅影響 1% 推薦準確率，修復成本高於收益 → 接受並監控 |

**判題訣竅：** 「損害嚴重且無法控制」→ 迴避；「找第三方賠」→ 轉移；「投入措施把風險壓下來」→ 緩解；「影響很小、修不划算」→ 接受。注意**接受 ≠ 不管**，仍須設定監控指標（如準確率下降閾值）以避免累積效應。

### 風險管理計畫必備四要素

```
1. 風險識別與評估結果 → 風險清單 + 影響評分
2. 風險對應措施       → 具體行動 + 時程
3. 責任人與分工       → 指定負責團隊（資安團隊負責加密、資料科學家調整偏誤）
4. 監控與回報機制     → 報告頻率與管道（如每週向管理層回報）
```

### MLOps 作為風險控管的執行載體

MLOps 把建置、部署、監控與修正流程自動化，管理模型**全生命週期**，是官方指引指定的風險監控手段。四類監控情境：

| 監控情境 | 偵測什麼 | 常用指標／工具 |
|---|---|---|
| **模型漂移監控** | 效能下降與其原因 | 準確率／AUC 趨勢、定期回收人工標註比對 |
| **資料漂移監控** | 輸入分佈與訓練資料的差異 | **PSI**（族群穩定度指數）、**KL 散度** |
| **效能異常警示** | 錯誤率超出閾值即時告警 | 預警閾值（如錯誤率 > 5%） |
| **自動重新訓練** | 偵測到漂移或效能下降後自動觸發 | 再訓練管線（Pipeline） |

**為什麼 PSI 是「最具預測效力」的預警指標？** 因為它在**標籤尚未回收前**就能發現輸入分佈偏移。CPU／記憶體使用率、API 延遲屬系統資源面，反映負載而非模型品質；置信度分佈變化雖有參考價值但較滯後且受校準影響。

### 上線階段的風險隔離手段

| 手段 | 做法 | 風險控管價值 |
|---|---|---|
| **漸進式部署** Phased Rollout | 從單一專科／低風險場域開始，逐步擴展 | 限縮影響範圍、便於收斂回饋 |
| **金絲雀發布** Canary Release | 導入 1～5% 真實流量 | 可控曝險下量測**真實業務指標**，可隨時回滾 |
| **影子模式** Shadow Mode | 新舊模型同時預測，僅顯示舊模型結果 | 安全比對輸出差異與系統負載，但**量不到真實互動行為** |
| **人機協作** HITL | AI 僅提供建議，人類審核簽署 | 人命攸關情境下確保**責任由人類承擔** |
| **回滾** Rollback | 退回前一版模型 | 需搭配 Model Registry 的版本可追溯性 |
| **分群監控** Segment Monitoring | 依區間／族群各自設定告警門檻 | 避免全域指標掩蓋少數族群或長尾案件的惡化 |

## 24.6 官方考過什麼

### A. 官方《學習指引》章末練習（本知識點直接相關 4 題）

| 考點 | 怎麼問 | 正解思路 |
|---|---|---|
| 決策透明性 | 模型輸出不穩定且缺乏邏輯可解釋性，帶來何種風險 | **決策透明性不足**；誘答刻意寫成「效率過高」「公平性過度提升」這種語意不成立的選項 |
| 模型偏誤 | 何者屬於 AI 模型偏誤造成的風險 | **特定族群預測結果不公平**；語法錯誤、格式錯誤、壓縮後效能下降都不是偏誤 |
| 法律與合規風險 | 企業應採取何種措施管理 | **檢視個資使用的合法性**；強化演算法複雜度、加速部署都與合規無關 |
| 概念漂移 | 長期輸入資料分佈改變導致效能下降，如何風險管理 | **建置概念漂移監控與觸發再訓練流程**；重啟伺服器、縮減層數與風險無關，冗餘模型雖有備援概念但不處理資料變異 |

### B. 114-2／115-1 官方公告試題（掃描出 15 題與本知識點相關）

| 題號 | 考點 | 怎麼問 | 正解思路 |

| 114Q2-22 | 資料漂移**偵測** | 懷疑顧客行為改變導致輸入分佈不同，如何確認 | **KL 散度**量化新舊分佈差異。重新訓練是「因應」不是「偵測」——問偵測就別選處置 |
| 114Q2-23 | 漸進式部署 | 醫院部署輔助診斷，何種 Phased Rollout 最合適 | **從單一專科或特定病房起步**，逐步擴展；急診風險高、夜班代表性不足 |

| 115Q1-27 | HITL | 人命攸關且責任須由人類承擔 | **人機協作架構由醫師最終審核**；信心低即自動關機反而在疑難案例上停擺，正解是轉人工複判 |

| 115Q1-48 | 概念漂移 | 特徵分佈未變、AUC 幾乎不變，但攔截率下降 | **概念漂移**（特徵與標籤關聯改變）；題幹已明講特徵分佈沒變，直接排除 Data Drift |

## 24.7 解題通則：正解長什麼樣子

本知識點的正解方向高度一致，選項讀不懂時可用下列四把尺篩：

```
尺 1：多層防禦 > 單點手段
      → 正解通常同時涵蓋「訓練期 + 推論期 + 流程面」，
        而非只加一道防火牆、只換一個模型。
      → 「選非」題的錯誤選項，常是層次錯置（用網路層手段解模型層問題）。

尺 2：從源頭處理 > 事後補救
      → 侵權風險看訓練資料授權，不是輸出端加浮水印。
      → 偏誤看資料分布與標註，不是調整輸出閾值。

尺 3：事前預防 > 事後追溯
      → DPIA、AI 審查流程、漸進式部署、對抗樣本訓練都屬事前。
      → 但題幹若明問「事後可稽核、可追蹤」，答案就換成
        雜湊＋數位簽章、版本紀錄、可重現的評估流程。
      → 判斷關鍵是題幹問的是「預防發生」還是「事後究責」。

尺 4：建立持續監控 > 一次性動作
      → 「定期重啟伺服器」「再訓練一次就好」「把準確率衝到 99%」
        這類一次性、與風險無關或治標的選項，幾乎都是誘答。
      → 正解常含「監控機制 + 告警閾值 + 觸發再訓練」的完整迴圈。
```

**額外兩條分辨題意的提醒：**
- 問「**偵測**」就別選處置手段（KL 散度 vs 重新訓練）；問「**因應**」才選再訓練。
- 問「**責任歸屬**」就找有人類節點的選項（HITL、審核簽署、角色分工），不要選純技術優化。

## 24.8 易錯與陷阱

- [ ] 概念漂移是**特徵與標籤的關聯**改變，不是輸入特徵分佈改變（那是資料漂移）。題幹寫「特徵分佈未明顯變化」就是概念漂移。
- [ ] 訓練服務偏差是**離線與線上特徵處理邏輯不一致**，通常一上線就出現，不是穩定運行一年後才發生。
- [ ] 可解釋性是對**單一決策**說明理由，透明度是對**整體系統**公開揭露；監理要求「每筆拒貸理由」考的是可解釋性。
- [ ] 「接受」風險不等於不處理，仍須設定監控指標；完全不管是漏洞不是策略。
- [ ] 迴避是**不做該活動**，不是「做但小心一點」——後者是緩解。
- [ ] 買保險、簽 SLA 是**轉移**，不是緩解；緩解是自己動手把風險壓下來。
- [ ] GDPR 的刪除權**不是絕對的**，法律要求保留或公共利益時不完全適用。
- [ ] **GDPR 的兩個天數不要對調**：查閱權是「**一個月內**回覆」（資料主體權利），外洩通報是「知悉後 **72 小時內**通報主管機關」（企業義務）。
- [ ] DPIA 是**事前**的高風險處理評估，不是出事後的調查報告。
- [ ] HIPAA 的員工培訓與定期風險評估屬**行政性**保護措施，不是技術性。
- [ ] 防火牆、VPN 屬網路層防護，**擋不住對抗樣本**，也不能讓原始資料「不離開」院內（那要靠聯邦學習）。
- [ ] 差分隱私防的是**隱私外洩與樣本記憶**，對**著作權侵權**的預防效果有限。
- [ ] 浮水印與數位指紋是**事後追溯**，不能預防侵權發生。
- [ ] 影子模式量不到真實互動行為（使用者看不到新模型結果）；要量 CTR、轉換率必須用**金絲雀發布**。
- [ ] 整體指標（RMSE、AUC）會被多數樣本主導而**掩蓋少數族群或長尾案件**的惡化，必須分群監控。
- [ ] 提高監控頻率解決不了「監控切面錯誤」的問題。
- [ ] Model Registry 管的是**版本與部署狀態**，上線後的漂移監控屬 Model Monitoring，兩者分工不同。
- [ ] AI 風險管理是**貫穿全生命週期**的前瞻機制，不是部署後才做的輔助工作。
