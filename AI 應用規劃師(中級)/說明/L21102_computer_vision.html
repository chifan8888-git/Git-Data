19.1

基礎概念與發展脈絡

電腦視覺（Computer Vision, CV）是讓機器從靜態影像或動態影片中擷取、辨識並解釋語意資訊的領域，本質是影像處理、模式辨識與深度學習的交集，不是單一技術。

三個技術階段

展開完整對照表（期間、特徵來源、代表技術、瓶頸）
階段期間特徵怎麼來代表技術瓶頸／突破
特徵工程主導1980s–2010人工設計（Handcrafted）Canny 邊緣偵測、SIFT／SURF／ORB 特徵點、色彩與紋理分析 + SVM／KNN／隨機森林無法自學高階語意，效能受特徵設計品質綁死
CNN 革命2012–2020模型自動學習AlexNet（2012 ImageNet 突破）、VGG、GoogLeNet、ResNet、DenseNet；任務擴至 YOLO／Faster R-CNN、FCN／U-Net、FaceNet需要大量標註資料與 GPU 算力
多模態與生成式融合2020–跨模態對齊 + 生成CLIP、ViT、DALL·E／Stable Diffusion／Midjourney、SAM從「看懂」走向「跨模態理解」與「創造」

分水嶺記法：2012 年 AlexNet 在 ImageNet 上的分類突破，是 CV 從手工特徵轉向自動特徵學習的起點；2020 年後 CLIP／ViT 把 NLP 的 Transformer 與對比學習搬進視覺，才出現零樣本（Zero-shot）與文字生成影像。

一定要背的一句話：電腦視覺任務的層級，是由「輸出的粒度」決定的：整張圖一個標籤 → 一組框 → 一張逐像素的類別圖 → 一張逐像素且帶實例編號的圖。

四大視覺任務的層次區辨

本節最穩定的考點。同一張街景，五種任務各自輸出什麼？切換看看，並注意右下角的標註成本。

標註成本
展開輸出型態與標註成本總表
任務輸出型態能定位嗎能分同類個體嗎涵蓋背景類別嗎標註方式標註成本
影像分類整張影像 → 1 個（或多個）類別標籤 + 機率✗✗—類別標籤（Label）最低
物件偵測N 組（類別, 邊界框座標, 信心分數）✓ 矩形框✓ 每框即一個實例✗ 只框可數物件邊界框（Bounding Box）中
語意分割與輸入同尺寸的類別圖，每個像素 1 個類別✓ 像素級✗ 同類併為一塊✓ 道路、天空等也標逐像素遮罩高
實例分割每個實例一組（類別, 框, 二值遮罩 Mask）✓ 像素級✓ 每個個體獨立遮罩✗ 通常不含背景像素遮罩 + 實例 ID最高
全景分割每個像素同時得到（類別, 實例 ID）✓ 像素級✓✓ 可數物件與背景全含語意 + 實例合併標註最高

標註成本的排序才是考點：類別標籤 < 邊界框 < 像素遮罩 < 遮罩＋實例 ID。標一張分類圖只要點一個類別，標一張分割圖要沿著物件輪廓畫多邊形，工時是數倍到數十倍 —— 所以「標註成本高」的情境題，答案往往是往上退一階（用偵測代替分割），或改用遷移學習／自動化標註。

19.4

關鍵技術與常用模型

卷積模擬器：卷積核怎麼掃過影像

左邊是 6×6 的灰階影像（示意數值），中間是 3×3 的垂直邊緣卷積核。按「滑動一步」，看特徵圖（Feature Map）一格一格被算出來。

組件做什麼備註
卷積層 Convolutional Layer以卷積核擷取局部特徵，產生特徵圖具平移不變性與空間局部性，這是影像模態選 CNN 的根本理由
池化層 Pooling Layer降維（如 Max Pooling），減少計算量增強對位移的容忍度
激活層 Activation Layer引入非線性（ReLU）沒有它，多層等同單層線性
全連接層 Fully Connected Layer把特徵整合成一維向量做最終分類輸入必須是二維張量
輸出層Softmax 轉成類別機率放在最後，不是放在全連接層之前

卷積輸出接全連接層的必經一步（115Q1 第 32 題）

選擇卷積層與全連接層之間要放什麼，看張量形狀（示意 B=8、C=64、H=W=7、10 類）。

PyTorch 不會自動轉換維度。全域平均池化（GAP）雖然也能把特徵圖壓成向量且參數更少，但那是另一種架構選擇，不是「卷積輸出與全連接層之間」的基本銜接操作 —— 這是官方設計過的誘答。

19.6

技術挑戰與風險

資料隱私與合規

影像常含個人識別資料（PII）；人臉屬高辨識性的敏感個資，受《個人資料保護法》與 GDPR 嚴格規範。

因應做法：去識別化（臉部遮蔽、模糊化、敏感區域遮罩）、設置攝影機前明示告知並取得同意、依資料最小化原則自動刪除或加密過期資料。倫理爭議的本質是「安全防護 vs 個人隱私」的平衡，例如校園人臉門禁若未取得學生與家長充分同意即有法律風險。

偏見與模型可靠度

偏見來源典型表現
資料來源不平衡訓練集族群（膚色、性別、年齡）集中，對其他族群辨識率明顯較低
標註偏誤標註者的主觀認知或文化偏見造成標準不一
拍攝條件偏差角度、光照、解析度差異拖垮泛化能力
誤檢 False Positive
醫療端：把健康者判為病患 → 導致不必要的檢查。
漏檢 False Negative
醫療端：延誤治療；製造端：瑕疵品流入市場。

誤檢與漏檢的產業後果不對稱。應對手段為偏見診斷測試（Bias Audit）、資料平衡與重加權（過採樣／欠採樣／增強），並以 AUC、精確率、召回率等多維度指標評估，而非只看準確率。

部署與維運

算力限制
邊緣裝置（智慧攝影機）資源有限 → 輕量模型（MobileNet、YOLO-Nano）、量化、蒸餾。
批次處理延遲
影像串流塞車影響即時性 → 動態批次（Dynamic Batching）調校。GPU 使用率卡在中段且 kernel 間有明顯空檔，通常是排程與批次大小設定不當，不是硬體效能不足。
版本管理困難
不同版本推論結果不一致引發爭議 → MLOps：CI／CD 管線 + 模型註冊（Model Registry），可追溯、可回滾。
資料漂移 Data Drift
光照、鏡頭、場景改變導致輸入分佈變化 → 線上監控 PSI 等漂移指標、定期再訓練。
部署測試不足
忽略實地光照變化與影像模糊 → 影像品質監測、預設容錯與回退機制。

線上監控 or 離線實驗追蹤？

MLOps 的核心角色是「把訓練→測試→部署→監控→再訓練工程化並版本化」，不是資料標註品質控管（那是資料治理），也不是自動化調參（那是 AutoML）。把下列項目放到正確的地方。
