## 47.1 從人工神經元到訓練迴圈

### 一個神經元只做兩件事

```
輸入 x₁ x₂ … xₙ
   ↓ 各乘上權重 w，再全部加總，最後加偏置 b
Z = w₁x₁ + w₂x₂ + … + wₙxₙ + b       ← 線性部分（加權求和）
   ↓ 送進激活函數 A
Output = A(Z)                          ← 非線性部分（決定是否「激活」）
```

- **權重（Weight）** 代表該輸入的重要性；**偏置（Bias）** 讓神經元在沒有輸入時也能被激活，等於調整激活門檻。
- **感知器（Perceptron）** 是 1957 年 Rosenblatt 提出的最簡化版本，激活函數用**步階函數（Step Function）**，只能做二元分類，且**只能處理線性可分問題**，著名的反例是 XOR。
- 現代人工神經元把步階函數換成 ReLU／Sigmoid／Tanh 等可微分的非線性函數，才讓反向傳播成立。

### 前向傳播與反向傳播：一個做預測，一個修參數

| | 前向傳播（Forward Propagation） | 反向傳播（Backpropagation） |
|---|---|---|
| 目的 | **做預測** | **算梯度、修參數** |
| 方向 | 輸入層 → 輸出層 | 輸出層 → 輸入層 |
| 核心數學 | 加權求和 + 激活函數 | 微積分**連鎖律（Chain Rule）** |
| 產出 | 預測值 ŷ | 損失對每個 w、b 的偏導數 |
| 常見誤解 | — | 反向傳播**只負責算梯度**，真正更新參數的是**優化器** |

RNN 因為有時間維度，用的是特殊形式的 **BPTT（Backpropagation Through Time）**：把序列沿時間軸展開成一個無迴圈的深層網路，再從最後一個時間步的損失往回推。

### 損失函數：任務型態決定選誰

| 任務 | 損失函數 | 關鍵特性 |
|---|---|---|
| 迴歸 | **MSE（均方誤差）** | 誤差取平方 → 大誤差懲罰被放大、梯度與誤差成正比，**對離群值最敏感** |
| 迴歸 | **MAE（平均絕對誤差）** | 線性懲罰、梯度近似定值，**刻意壓低離群值影響** |
| 迴歸 | **Huber Loss** | 小誤差平方、大誤差轉線性，介於 MSE 與 MAE 之間 |
| 二元分類 | **Binary Cross-Entropy** | 輸出一個機率 |
| 多類別分類 | **Categorical Cross-Entropy** | 衡量預測機率分佈與真實分佈的距離 |

> 這組對照是 115-1 第 2 題與第 10 題的正解依據。**「希望模型對極端值更敏感」→ MSE；「希望降低離群值影響」→ MAE 或 Huber**，方向搞反就全錯。

### 優化器：梯度怎麼變成參數更新

```
W_new = W_old − 學習率 α × ∂L/∂W

α 太大 → 在最低點兩側來回跨越 → 損失震盪甚至發散（Divergence）
α 太小 → 收斂慢、遲遲達不到最佳準確率
```

| 優化器 | 一階動量（Momentum） | 自適應學習率 | 一句話 |
|---|---|---|---|
| SGD | ✗ | ✗ | 最陽春，所有參數共用同一個學習率 |
| SGD + Momentum | ✓ | ✗ | 沿歷史梯度方向平滑前進，抑制震盪 |
| Adagrad | ✗ | ✓ | 依歷史梯度平方累積縮放步長，後期學習率會過度衰減 |
| RMSProp | ✗ | ✓ | 改用指數移動平均，修正 Adagrad 的衰減問題 |
| **Adam** | **✓** | **✓** | **同時整合兩者，逐參數自動調步長，實務首選** |

批次大小的取捨（115-1 第 11 題的完整推理鏈）：

| 策略 | 梯度穩定性 | GPU 吞吐量 | 結論 |
|---|---|---|---|
| Full-batch GD | 最穩 | 每次更新極慢 | 大模型不可行 |
| SGD（單樣本） | 雜訊極大、曲線劇烈震盪 | 快但無法平行 | 不穩 |
| **Mini-batch GD（如 256–2048）** | **樣本平均抵銷雜訊** | **一次前向反向充分平行** | **業界標準解** |

### 過擬合與正則化

**症狀判讀是考試的第一步**：

| 觀察到的現象 | 診斷 | 對策方向 |
|---|---|---|
| 訓練損失低、驗證損失高且拉開 | **過擬合** | 降複雜度、加資料、正則化 |
| 訓練與驗證**都**偏低 | 欠擬合 | 加深加寬、換更強架構 |
| **訓練損失反而比淺層版本更高** | **最佳化失敗（梯度消失）** | 殘差連接、換激活函數、正規化 |
| 調高學習率後訓練損失震盪 | 學習率過大 | 調小 lr、梯度裁剪 |

正則化技術一覽：

| 技術 | 做法 | 特色 |
|---|---|---|
| **L1（Lasso）** | 損失 += λΣ\|W\| | 產生**稀疏解**，部分權重歸零 → 自動特徵選擇；面對高度相關特徵時會**隨機只留一個**，導致重要特徵清單不穩定 |
| **L2（Ridge／Weight Decay）** | 損失 += λΣW² | 壓小權重但**不歸零**，把相關特徵的權重**平均分攤**，表現較穩定 |
| Elastic Net | L1 + L2 | 兼顧特徵選擇與平滑 |
| **Dropout** | 訓練時隨機把部分神經元輸出**設為 0** | 打斷神經元共適應，等同集成效果 |
| **Early Stopping** | 監控**驗證集**損失，設 **Patience** | 連續多輪未改善才停，避免被單次波動誤判 |
| Batch Normalization | 對每批次激活值標準化 | 穩定各層輸入分佈、緩解梯度消失與爆炸 |

## 47.2 激活函數（本知識點最高頻考點）

### 四大激活函數對照

| 激活函數 | 數學式 | 輸出範圍 | 主要用途 | 主要缺點 |
|---|---|---|---|---|
| **Sigmoid** | 1/(1+e⁻ˣ) | (0, 1) | **二元分類輸出層**、LSTM 門控 | 兩端飽和導致**梯度消失**；輸出非零中心 |
| **Tanh** | (eˣ−e⁻ˣ)/(eˣ+e⁻ˣ) | (−1, 1) | RNN 隱藏狀態 | 仍會飽和，但梯度優於 Sigmoid |
| **ReLU** | max(0, x) | [0, ∞) | **隱藏層預設值** | **Dying ReLU**：神經元輸出恆為 0、停止更新 |
| **Softmax** | eᶻⁱ/Σeᶻʲ | (0, 1)，**總和為 1** | **多類別單標籤輸出層** | 只能用於單標籤，多標籤不適用 |

### 三個必須分清楚的誤區

**誤區一：沒有非線性激活 = 疊幾層都沒用。**
線性激活函數的組合仍是線性，無論堆多少卷積層，整個網路的表達能力等同單層線性模型。114-2 第 27 題就把「再加深卷積層」設為誘答——**只要激活仍是線性，加深毫無幫助，正解是改用 ReLU**。

**誤區二：Sigmoid 不是萬用解。**
Sigmoid 雖有非線性，但在飽和區導數趨近 0，**深層網路用 Sigmoid 會讓梯度消失更嚴重**。115-1 第 17 題把「ReLU 改 Sigmoid 改善梯度傳遞」設成誘答，方向完全相反。

**誤區三：Softmax vs Sigmoid 的分界是「單標籤 vs 多標籤」。**

| 情境 | 輸出層神經元 | 激活 | 為什麼 |
|---|---|---|---|
| 二元分類 | 1 | **Sigmoid** | 一個機率就夠 |
| **多類別「單標籤」** | **類別數 C** | **Softmax** | C 個輸出總和為 1，互斥 |
| 多標籤（一張圖可同時有貓和狗） | C | **Sigmoid** | 每類獨立輸出 0~1，**總和不為 1** |
| 迴歸 | 1 或 k | **不加**（線性） | 輸出是連續數值，不是機率 |

### 激活函數之外的「非線性來源」辨識

池化層（Max Pooling）雖然不是線性運算，但它的**設計目的是降維、不是提供非線性**。115-1 第 18 題就用這點設陷阱：池化層解決的是**參數量與計算量**問題，非線性表達能力來自 ReLU，緩解梯度消失靠的是 BatchNorm 與殘差連接。

## 47.3 深度學習模型架構

### 五種架構的問題空間

| 架構 | 假設的資料結構 | 核心機制 | 典型任務 | 致命弱點 |
|---|---|---|---|---|
| **MLP** | 特徵彼此獨立 | 全連接 + 非線性 | 表格資料分類／迴歸 | 攤平後**丟失空間與順序資訊**；參數量爆炸 |
| **CNN** | 局部空間相關 | 卷積 + 權重共享 + 池化 | 影像分類、瑕疵檢測、影像分割 | 需大量標註資料、算力需求高 |
| **RNN** | 時間順序依賴 | 循環連接 + 隱藏狀態 | 時間序列預測、語音 | **梯度消失／爆炸**、序列計算**無法平行** |
| **LSTM／GRU** | 長期時序依賴 | 門控機制 + 細胞狀態 | 電力需求預測、機器翻譯 | 仍然難以平行、超長序列仍吃力 |
| **Transformer** | 任意位置皆可能相關 | 自注意力 + 位置編碼 | NLP、長文件、ViT | 複雜度 **O(L²)**、記憶體吃重、需大量資料 |

### CNN 的四種層各司其職

```
輸入影像 (32, 32, 3)
  ↓
[卷積層 Conv2d]  ← 自動提取局部特徵（邊緣、紋理、角點）；權重共享 → 參數少
  ↓
[激活層 ReLU]    ← 引入非線性（無可訓練參數）
  ↓
[池化層 Pooling] ← 降採樣，縮小特徵圖空間維度、減少參數與計算量（無可訓練參數）
  ↓
  … 重複數次，特徵由低階 → 高階抽象 …
  ↓
[Flatten]        ← 三維特徵圖攤平成一維向量
  ↓
[全連接層 Linear]← 組合特徵做最終分類（參數量最大的地方）
  ↓
[輸出層 Softmax]
```

**CNN 為何比全連接網路有效率？** 兩個機制：**區域感知（Local Receptive Field）** 讓每個神經元只連結局部區域，**參數共享（Parameter Sharing）** 讓同一個卷積核掃過整張影像。這是 114-2 第 6 題的正解，誘答則是「自動具備旋轉與比例不變性」——CNN 對小幅平移較穩健，但**旋轉與尺度不變性並非天生具備**，仍需資料增強。

**CNN 衍生架構**：

| 架構 | 年份 | 關鍵貢獻 |
|---|---|---|
| AlexNet | 2012 | ImageNet 冠軍；ReLU + Dropout + GPU 訓練 |
| **VGG** | 2014 | 堆疊多個 **3×3 小卷積核**取代大卷積核，結構規則 |
| GoogLeNet（Inception） | 2014 | Inception 模塊並行多尺度卷積核 |
| **ResNet** | 2015 | **殘差／跳躍連接（Skip Connection）**，讓梯度跨層直傳 → **能訓練 50 層以上** |
| DenseNet | 2016 | 每層連接所有前層，特徵重用 |
| MobileNet / EfficientNet | 2017+ | 深度可分離卷積／複合縮放，輕量化部署 |

> **「超過 50 層又怕梯度消失」→ ResNet**，這是 115-1 第 49 題的固定考法。VGG 只是單純堆疊、本身沒有緩解梯度消失的機制；GoogLeNet 的 Inception 是提升參數效率而非治本。

### RNN 家族的門控機制

| 模型 | 門的數量與名稱 | 特色 |
|---|---|---|
| 標準 RNN | 無 | 記憶短，梯度沿時間步指數衰減 |
| **LSTM** | **3 門**：遺忘門、輸入門、輸出門 + **細胞狀態** | 選擇性保留／遺忘資訊，解決長期依賴 |
| **GRU** | **2 門**：更新門、重置門 | LSTM 簡化版，參數更少、效能相當 |
| Bi-RNN | — | 正向 + 反向各跑一次，同時看過去與未來上下文 |

> 114-2 第 7 題的辨識點：**「預測未來七天的電力需求趨勢」= 時間序列 → LSTM**。誘答分別對應 CNN（物件辨識）、聚類（自動分群）、自編碼器（高維壓縮成低維）。

### Transformer 的五個組件

| 組件 | 功能 | 常考重點 |
|---|---|---|
| **自注意力（Self-Attention）** | 每個 token 對序列所有其他 token 算相關性權重 | Q（我在找什麼）／K（我能提供什麼）／V（被關注時提供什麼）；**任意兩位置直接建立關聯，不受距離限制** |
| **多頭注意力（Multi-Head）** | 拆成 h 個頭在不同**表示子空間**並行計算 | 目的是**同時捕捉多樣化關聯**，**不是**為了減少參數或加速 |
| **位置編碼（Positional Encoding）** | 用正弦餘弦把位置資訊加進詞嵌入 | 因為拋棄了循環結構，模型本身無法感知順序 |
| **殘差連接 + 層歸一化（LayerNorm）** | 緩解梯度消失、穩定訓練 | **LayerNorm 不依賴批次大小**，故比 BatchNorm 更適合序列模型 |
| 前饋網路（FFN） | 兩層線性 + ReLU，逐位置獨立套用 | — |

編碼器 vs 解碼器：

```
編碼器 Encoder ── 「理解者」：把輸入序列轉成富含上下文的表示
   └─ 多頭自注意力 + FFN                    → BERT（雙向、擅長理解）

解碼器 Decoder ── 「生成者」：自迴歸逐字產生輸出
   ├─ 帶遮罩多頭自注意力（不能偷看未來）    → GPT 系列（單向、擅長生成）
   ├─ 編碼器-解碼器注意力
   └─ FFN

完整 Encoder-Decoder                          → T5（所有任務統一成 Text-to-Text）
圖像切 Patch 當 token 餵進 Transformer        → ViT
稀疏／局部注意力降低 O(L²)                    → Longformer、Reformer、Performer
```

> 115-1 第 19 題：合約首頁定義條款要比對第 20 頁責任條款，Bi-LSTM 效果差 → 換 Transformer。正解是 **Self-Attention 讓任意 token 直接建立關聯且可平行運算**。誘答「內建位置編碼使模型天生理解章節結構」是張冠李戴——位置編碼只提供順序資訊。

### 生成式模型

| 模型 | 結構 | 訓練目標 | 適用 |
|---|---|---|---|
| **自編碼器（Autoencoder）** | 編碼器 → 瓶頸層 → 解碼器 | 最小化**重構誤差** | 降維、特徵學習、**去噪**、**異常偵測**（重構誤差大 = 異常） |
| **GAN** | 生成器 + 判別器，零和博弈 | 對抗至納許均衡 | 逼真影像生成、資料增強、風格遷移、超解析度 |

GAN 的三大缺點要記牢：**訓練不穩定（模式崩潰 Mode Collapse）**、**超參數敏感**、**缺乏客觀量化指標**（只能靠 IS／FID 或人工判斷）。

## 47.4 模型摘要表判讀（附圖題主戰場）

L23 官方公告試題 100 題中有 **23 題附圖**，其中影像多為程式碼截圖或 `summary()` 輸出表。以下兩條公式必須背到能心算。

### 參數量公式

```
全連接層 Linear/Dense：
    Param = 輸入維度 × 神經元數 + 神經元數（bias）

卷積層 Conv2d：
    Param = (卷積核高 × 卷積核寬 × 輸入通道數 + 1) × 輸出通道數

ReLU、MaxPool2d、AdaptiveAvgPool2d、Flatten、Dropout：
    Param = 0（完全沒有可訓練參數）
```

### VGG16 的實際數字（114-2 第 42~45 題組）

| 層別 | 參數量 | 佔比 | 說明 |
|---|---|---|---|
| 13 層卷積層合計 | 約 **1,470 萬** | ~11% | 層數最多，但權重共享使參數少 |
| **Linear-33（第一個全連接層）** | **102,764,544** | **~74%** | 25088 × 4096 + 4096 |
| 3 層全連接層合計 | 約 **1.23 億** | ~89% | 參數量的絕大部分 |
| ReLU / MaxPool / AdaptiveAvgPool | **0** | 0% | 無可訓練參數 |
| **Total params** | **138,357,544（約 138.36M）** | 100% | VGG16 = 13 conv + 3 FC |

**這個題組同時考了四件事，四個結論都要記：**

1. **參數量最多 → 全連接層**（Linear）。
2. **FLOPs（運算量）最多 → 卷積層**。卷積層參數雖少，但要在**每個空間位置重複運算**、輸出特徵圖尺寸大；全連接層參數多卻只做一次矩陣乘法。**「參數多」與「算得久」是兩回事**。
3. **攤平維度**：VGG16 的 `AdaptiveAvgPool2d` 固定輸出 **7×7**，攤平後是 **512 × 7 × 7 = 25088**，不是 4×4 的 8192。
4. **`Estimated Total Size` 不等於訓練所需顯存**。摘要中的 624.98 MB 只含參數與激活值，**訓練還要額外存梯度與 optimizer state**，1 GB 顯示卡不夠用。

### Keras 摘要表填空的推算法

Keras 的 `model.summary()` 會列出 `Output Shape` 與 `Param #`，考題常挖空要你回填。用同一條公式雙向推算：

```
輸入 784 維 → Dense(64, relu)   Output (None, 64)   Param = 784×64 + 64 = 50,240
             → Dense(10, ...)    Output (None, 10)   Param =  64×10 + 10 =    650

反推：若某層 Output 為 (None, 10)、Param 為 110
     → 110 = in × 10 + 10 → in = 10，代表前一層輸出也是 10 維
```

114-2 第 49 題正是這種「空格 1 = 100、空格 2 = 110」的推算題，**空格互換就是最主要的誘答**，務必逐格驗算不要憑印象。

### 必備語法一：Keras 輸出層搭配（固定考法）

```python
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import Dense
from tensorflow.keras.utils import to_categorical

# 手寫數字 28×28 攤平為 784 維，分 0~9 共 10 類，標籤已轉 One-Hot
y_train = to_categorical(y_train, 10)

model = Sequential([
    Dense(64, activation='relu', input_shape=(784,)),
    Dense(10, activation='softmax'),          # ← (A) 多類別單標籤 → softmax
])
model.compile(optimizer='adam',
              loss='categorical_crossentropy',  # ← (B) One-Hot 標籤 → categorical
              metrics=['accuracy'])
```

**Keras 輸出層／損失函數配對總表（背這張就夠）：**

| 任務 | 輸出層神經元 | 激活函數 | 損失函數 |
|---|---|---|---|
| 二元分類 | 1 | `sigmoid` | `binary_crossentropy` |
| **多類別單標籤（One-Hot 標籤）** | **C** | **`softmax`** | **`categorical_crossentropy`** |
| 多類別單標籤（**整數索引**標籤） | C | `softmax` | `sparse_categorical_crossentropy` |
| 多標籤（可同時屬多類） | C | `sigmoid` | `binary_crossentropy` |
| 迴歸 | 1 或 k | 不設（線性） | `mse` / `mae` / `huber` |

> `categorical_crossentropy` 與 `sparse_categorical_crossentropy` 的差別**只在標籤格式**：前者吃 One-Hot，後者吃整數索引。115-1 第 40 題的誘答 (D) 就是把 `sparse_` 配上 One-Hot 標籤。

### 必備語法二：PyTorch 輸出層（與 Keras 相反的坑）

```python
import torch.nn as nn

criterion = nn.CrossEntropyLoss()   # 內部已串接 LogSoftmax + NLLLoss
model_head = nn.Linear(512, 3)      # 貓/狗/鳥三分類：輸出維度 = 3
# 輸出層「不要」再加 softmax，直接輸出未正規化的 logits
```

| PyTorch 損失函數 | 內建的激活 | 輸出層該給什麼 |
|---|---|---|
| `nn.CrossEntropyLoss()` | **內含 LogSoftmax** | **原始 logits，維度 = 類別數，不加 softmax** |
| `nn.BCEWithLogitsLoss()` | **內含 Sigmoid** | 原始 logits |
| `nn.BCELoss()` | 無 | 必須先自己過 `sigmoid` |
| `nn.MSELoss()` | 無 | 連續值 |

> 115-1 第 20 題的核心：**在 `CrossEntropyLoss` 前再加一次 softmax 是最常見的實作錯誤**，會讓分布過度平滑、梯度變小而拖累訓練。誘答 (D) 看起來最「正確」，其實是陷阱。

### 必備語法三：遷移學習（凍結卷積層）

```python
import torch, torch.nn as nn
from torchvision import models

# ── 寫法 A：VGG16，凍結 features（卷積部分），只訓練 classifier ──
model = models.vgg16(pretrained=True)
for param in model.features.parameters():   # ← 關鍵：凍結 features
    param.requires_grad = False
model.classifier[6] = nn.Linear(4096, num_classes)
optimizer = torch.optim.Adam(model.classifier.parameters(), lr=1e-4)

# ── 寫法 B：ResNet50，凍結全部主幹，換掉分類頭 ──
model = models.resnet50(pretrained=True)
for p in model.parameters():
    p.requires_grad = False
model.fc = nn.Linear(2048, 2)               # 只有 fc 是新的、可訓練
optimizer = torch.optim.Adam(model.fc.parameters(), lr=1e-4)
```

**三個必考判斷：**

1. **凍結對象是 `model.features`（VGG）或全部參數（ResNet），不是 classifier。** 凍錯位置就等於把要訓練的層鎖死。
2. **凍結主幹 + 只訓分類頭 = 特徵萃取（Feature Extraction）**，不是全面微調（Full Fine-Tuning）、不是零樣本學習、更不是知識蒸餾（後者需要教師與學生兩個模型）。
3. **微調時學習率要設很小（如 1e-4）**，原因是**避免更新步伐過大破壞預訓練已學好的良好特徵表示**——不是為了省記憶體，也不是為了加速收斂。

### 必備語法四：資料增強的語義陷阱

```python
from torchvision import transforms

transform = transforms.Compose([
    transforms.RandomHorizontalFlip(p=0.5),   # ⚠ OCR / 字母辨識的地雷
    transforms.RandomRotation(15),
    transforms.ColorJitter(brightness=0.2),
    transforms.ToTensor(),                     # 幾何變換之後才轉張量
    transforms.Normalize(mean, std),
])
```

**`RandomHorizontalFlip` 會破壞方向語義**：`b` 鏡像後變 `d`、`p` 變 `q`，但**標籤不會跟著改**，等於餵進大量錯誤標註。更陰險的是——訓練與驗證套用同一組 transform，所以**驗證損失看起來一路下降，問題要到部署後才爆發**。

| 誘答 | 為何錯 |
|---|---|
| `RandomRotation(15)` 角度過大 | 旋轉 15 度不會讓字母互換身分，屬合理幅度 |
| `ColorJitter` 使邊緣特徵失真 | 只調亮度，不改變筆畫形狀語意 |
| `ToTensor()` 應放在幾何變換之前 | **相反**，torchvision 規範是幾何變換作用在 PIL 影像上，`ToTensor()` 放最後 |

**判準**：資料增強必須**保持標籤語義不變**。水平翻轉對貓狗分類無害，對字母、數字、交通標誌則是災難。

### 必備語法五：訓練迴圈與梯度裁剪的插入位置

```python
for inputs, labels in dataloader:
    optimizer.zero_grad()                       # 位置 1：清空舊梯度
    outputs = model(inputs)                     # 位置 2：前向傳播
    loss = criterion(outputs, labels)           # 位置 3：計算損失
    loss.backward()                             # 位置 4：反向傳播，產生 .grad

    torch.nn.utils.clip_grad_norm_(             # ★ 梯度裁剪插在 4 與 5 之間
        model.parameters(), max_norm=1.0)       #   梯度已算出、尚未套用

    optimizer.step()                            # 位置 5：更新權重
```

**為什麼只能插在 4 與 5 之間？** 裁剪的對象是**參數的 `.grad`**：位置 3 之前梯度根本還沒算出來；位置 5 之後權重已經更新完畢，為時已晚。作用是**限制梯度範數、避免單次更新步幅失控導致 Loss 飆成 NaN**——不是限制 Loss 數值，也不是用來處理梯度消失。

### 必備語法六：Keras CNN 與前處理

```python
from tensorflow.keras import Input, Sequential
from tensorflow.keras.layers import (Conv2D, BatchNormalization,
                                     MaxPooling2D, Dropout, Flatten, Dense)

x_train = x_train / 255.0            # 像素 0~255 線性縮放到 0~1（不是 z-score！）
y_train = to_categorical(y_train, 10)  # 整數標籤 → 10 維 One-Hot

model = Sequential([
    Input(shape=(32, 32, 3)),        # 僅宣告輸入形狀，不做任何標準化
    Conv2D(32, (3, 3), padding='same', activation='relu'),  # → (32, 32, 32)
    BatchNormalization(),            # 穩定各層輸入分佈，緩解梯度消失／爆炸
    MaxPooling2D((2, 2)),
    Dropout(0.25),                   # 訓練時隨機把神經元輸出設為 0（不是設為 1）
    Flatten(),                       # 三維特徵圖 → 一維向量
    Dense(128, activation='relu'),
    Dense(10, activation='softmax'),
])
model.compile(optimizer='adam', loss='categorical_crossentropy',
              metrics=['accuracy'])
```

**四個常被設成錯誤描述的點**（115-1 第 46、47 題）：

- 除以 255.0 是把上界縮到 **1**，不是 31；且這是**縮放不是 z-score 標準化**（z-score 要減平均再除標準差）。
- 縮放到一致尺度有助泛化，也能**避免數值過大造成梯度爆炸、過小造成梯度消失**。
- `Conv2D(32, padding='same')` 輸入 (32,32,3) → 輸出 **(32, 32, 32)**：長寬因補零維持，**通道數變成濾波器數量 32**。
- `Dropout` 是把選中的神經元輸出**設為 0**，不是設為 1。

## 47.7 易錯與陷阱

- [ ] **參數量最多的是全連接層，運算量（FLOPs）最多的是卷積層**——兩題連著考，答案不同。
- [ ] **Softmax 用於多類別「單標籤」；Sigmoid 用於二元分類或「多標籤」**。判準是「輸出總和是否為 1」，不是「類別有幾個」。
- [ ] **Keras 要在輸出層明確寫 `activation='softmax'`；PyTorch 用 `CrossEntropyLoss` 時反而「不能」加 softmax**。兩套框架的慣例相反，這是最容易張冠李戴的地方。
- [ ] **`categorical_crossentropy` 配 One-Hot 標籤，`sparse_categorical_crossentropy` 配整數索引標籤**。差別只在標籤格式，不在類別數。
- [ ] **反向傳播只負責「算梯度」，更新參數的是優化器**。不是「反向傳播更新權重」。
- [ ] **學習率、批次大小、層數是超參數；權重值、神經元輸出、梯度是訓練產生的結果**，後者不可「調整」。
- [ ] **「加深網路後訓練損失反而比淺層更高」是最佳化失敗（梯度消失／退化），不是過擬合** —— 過擬合是訓練損失低、驗證損失高。若題幹改成「調高學習率後損失震盪」，那是學習率問題，與梯度消失無關。
- [ ] **加深網路不能解決「激活函數是線性」的問題**——線性的組合仍是線性，要換成 ReLU。
- [ ] **Sigmoid 不能拿來「改善梯度傳遞」**，它飽和區導數更小，會讓梯度消失更嚴重。
- [ ] **池化層的目的是降維省算力，不是提供非線性、也不是治梯度消失。**
- [ ] **Dropout 是把神經元輸出設為 0，不是設為 1，也不是把權重設為 0。**
- [ ] **Early Stopping 要監控「驗證集」並設 Patience**；用訓練集會過擬合，用測試集會洩漏測試資訊。
- [ ] **L1 產生稀疏解、面對相關特徵時隨機留一個（不穩定）；L2 壓小但不歸零、把權重平均分攤（穩定）。**
- [ ] **MSE 對離群值最敏感（適合「希望更敏感」）；MAE 與 Huber 刻意降低離群值影響。**
- [ ] **Adam ＝ 動量 + 自適應學習率；Adam 不內建梯度裁剪**，梯度裁剪是另一項獨立技巧。
- [ ] **`clip_grad_norm_` 必須插在 `loss.backward()` 之後、`optimizer.step()` 之前。**
- [ ] **遷移學習「凍結」的是 `features`／主幹，不是 classifier；凍結主幹只訓分類頭叫特徵萃取，不叫全面微調。**
- [ ] **微調的小學習率是為了保護預訓練特徵，不是為了省顯存或加速。**
- [ ] **資料增強必須保持標籤語義**：水平翻轉對貓狗無害，對 b/d/p/q、數字、文字是災難；而且訓練與驗證用同一組 transform 時，驗證損失看不出問題。
- [ ] **`ToTensor()` 放在幾何變換「之後」**（幾何變換作用在 PIL 影像上）。
- [ ] **除以 255 是縮放到 0~1，不是 z-score 標準化**；z-score 要減平均再除標準差。
- [ ] **`Conv2D(32, padding='same')` 的輸出通道數等於濾波器數量**，長寬才是靠補零維持。
- [ ] **LayerNorm 不依賴批次大小，所以適合 Transformer／RNN；BatchNorm 依賴批次**。
- [ ] **多頭注意力是為了「捕捉多樣化關聯」，它會增加而非減少參數量，也不是為了加速或治梯度消失。**
- [ ] **Transformer 的位置編碼只提供順序資訊**，不會讓模型自動理解章節或文件結構。
- [ ] **自編碼器是「重構」不是「生成全新樣本」**；能憑空生成多樣化新樣本的是 GAN。
- [ ] **`Estimated Total Size` 不等於訓練所需顯存**——訓練還要存梯度與 optimizer state。
