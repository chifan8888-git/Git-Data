模型訓練、評估與驗證

初級只要你背得出 Accuracy、Precision、Recall、F1 四個名詞；中級要你在情境題裡算出數字、看懂附圖程式碼在算哪個指標、判斷該調高還是調低決策門檻，並選對交叉驗證方法。這是科目 3 命中率最高的知識點之一。

學完這一課，你應該能夠

寫出混淆矩陣四格與 Accuracy／Precision／Recall／F1 公式，並在給定數值時完成計算
依「漏抓成本」與「誤判成本」，選出正確指標與決策門檻調整方向
分辨 MAE／MSE／RMSE／R² 的運算結構，從 NumPy 或 scikit-learn 程式碼反推它在算哪一個
依資料量、類別平衡與時間性，在 Hold-out／K-Fold／Stratified K-Fold／LOOCV／時序驗證之間選出最合理的方案

50.3
分類評估指標與混淆矩陣

  
固定讀法：先鎖定「正類」是誰，再用「第一個字母＝預測對不對，第二個字母＝預測成什麼」拆解。FN＝預測成負、其實是正＝漏抓（型二錯誤）；FP＝預測成正、其實是負＝誤報（型一錯誤）。

  
混淆矩陣計算機

  

    
用 ＋／− 改四格數字，指標即時重算。按「肺癌篩檢：全部預測正常」看 Accuracy 怎麼說謊。

    

      
      
    

    

    

    

  

  

    

      
指標公式分母是什麼關心什麼

      
準確率 Accuracy(TP+TN) / (TP+TN+FP+FN)全部樣本整體對了幾成

      
精確率 PrecisionTP / (TP+FP)預測為正的全部說是正的，有幾成真的是正

      
召回率 RecallTP / (TP+FN)實際為正的全部實際的正，抓到幾成

      
F1 分數2·P·R / (P+R)—兩者的調和平均

    

  

  
注意：官方《學習指引》原文在 Recall 這一條把分母誤植成 TP+FP（與 Precision 相同）。正確的分母是 TP+FN——記法是「Recall 是站在實際那一側看，所以分母是實際為正的全部」。

  
特異度與假正率（畫 ROC 要用）：Specificity＝TN／(TN+FP)；FPR＝FP／(FP+TN)＝1 − Specificity；TPR＝Recall。


  
F1 為什麼是調和平均？拖動看看

  

    
Precision0.80

    
    
Recall0.60

    
    

    

    

  

  
114Q2 第 16 題：F1 = 2 × (0.8 × 0.6) / (0.8 + 0.6) = 0.96 / 1.4 ≈ 0.686。誘答 0.700 是算術平均。調和平均恆小於算術平均（兩者不相等時），答案一定低於 0.7，可秒殺選項。
115Q1 第 32 題正解敘述：調和平均只要有一項偏低，整體就被明顯拉下，逼模型不能犧牲一方換另一方的高分。

  
需要偏重某一方時用 F-beta：Fβ = (1+β²)·P·R / (β²·P + R)。β > 1 偏重 Recall（如 F2），β < 1 偏重 Precision。F1 是 β=1 的特例，兩者等權。

  
Accuracy 的致命陷阱考了兩次：114Q2 第 19 題「哪種作法最不適合提升少數類預測能力」→ 使用 Accuracy 作為評估指標（SMOTE、類別權重、欠採樣多數類都是正當手段）；115Q1 第 12 題「僅以 Accuracy 評估最嚴重的缺陷」→ Accuracy 對類別不平衡不敏感，無法反映對陽性的偵測能力，漏診風險被徹底掩蓋。







  
50.4
指標選擇與決策門檻（Threshold）

  
判準記法：問自己「這個錯誤讓誰受傷」。漏掉一個癌症病人 → Recall；把正常信誤判成垃圾信 → Precision。

  

    
配對：業務場景 → 主要指標

    
先點場景，再點指標。

    

    

  

  

    展開成本判準完整表
    

      

        
業務痛點要壓低的錯誤主要指標典型場景

        
漏抓成本高（漏掉就出大事）FNRecall癌症篩檢、詐欺偵測、設備故障預警、瑕疵檢測

        
誤判成本高（誤報就擾民／賠錢）FPPrecision垃圾郵件過濾、帳號凍結、推播行銷、司法輔助

        
兩者都不能犧牲FN 與 FPF1 / F-beta詐欺偵測（既怕漏放也怕誤凍結）

        
要比較整體區分能力—ROC-AUC需要跨門檻比較多個候選模型

      

    

  


  
門檻模擬器：方向是固定的

  

    
模型對每個樣本輸出「是正類的機率」。上方紅點是實際為正、下方灰點是實際為負。拖動門檻，門檻右邊的都判為正。（樣本為示意）

    
門檻 Threshold0.50

    
    

    

      
      
    

    

    

  

  

    
調低門檻 0.5 → 0.3
更多樣本被判為正 → TP↑、FN↓ → Recall ↑
同時 FP↑ → Precision ↓
適用：零容忍漏抓（癌症、詐欺、公安、瑕疵流出）

    
調高門檻 0.5 → 0.7
只有很有把握才判正 → FP↓ → Precision ↑
同時 TP↓、FN↑ → Recall ↓
適用：誤判成本高（凍結帳號、發出告警、自動拒貸）

  

  
背這一句就夠：「零容忍漏抓 → 調低 Threshold → 拉高 Recall」。反過來「怕誤報 → 調高 Threshold → 拉高 Precision」。門檻預設 0.5 只是慣例，不是最佳值；調門檻不需要重新訓練模型，它是推論階段的後處理。

  

    

      
曲線橫軸縱軸特性

      
ROCFPR（假正率）TPR（＝Recall）橫軸分母是負類總數，極不平衡時會顯得過於樂觀

      
PR 曲線RecallPrecision不看 TN，極不平衡時鑑別力較佳

    

  

  
AUC 的意義：隨機取一個正樣本與一個負樣本，模型給正樣本較高分數的機率。AUC = 0.5 等同亂猜，越接近 1 越好。AUC 的價值：它是「跨所有門檻」的綜合指標，比較模型時不受單一門檻選擇影響。

  
官方兩份試卷沒有直接考門檻計算，但把它藏在情境裡：115Q1 第 12 題的漏診疑慮、115Q1 第 32 題的 Precision-Recall Tradeoff，本質都是門檻思維的敘述版本。主題庫則有直接問「零容忍漏抓該怎麼調門檻」的題型，方向與上面完全一致。







  
50.5
迴歸評估指標

  
MAE 取絕對值、MSE 取平方、RMSE 在 MSE 之上再開根號。加入一個離群值，看誰反應最大。

  

    

      6 筆房價預測（單位：百萬元，示意）
      
    

    
    

    

  

  

    

      
指標公式對誤差的處理單位對離群值

      
MAE(1/n)·Σ|yᵢ − ŷᵢ|取絕對值與 y 相同不敏感（線性懲罰，梯度近似固定）

      
MSE(1/n)·Σ(yᵢ − ŷᵢ)²取平方y 的平方（如「元²」）高度敏感（平方放大，梯度與誤差成正比）

      
RMSE√MSE平方後開根號與 y 相同敏感，但單位可讀

      
R²1 − RSS/TSS殘差平方和 ÷ 總變異無單位（比例）—

    

  

  
恆成立的性質：RMSE ≥ MAE（唯有所有誤差絕對值相等時兩者才相等）。兩者差距越大，代表誤差分布越不均勻、存在少數極端偏差。

先點左邊的程式碼，再點右邊的指標。

    

    

  

  
scikit-learn 對應：mean_absolute_error、mean_squared_error、r2_score；RMSE 在較新版本有 root_mean_squared_error，舊版則寫成 mean_squared_error(y_true, y_pred, squared=False)。


  
R² 判讀（點卡片翻面）

  

  
114Q2 第 15 題：R²=0.85 代表 85% 的變異可被模型解釋。四個誘答分別是準確率、誤差百分比、信心水準——全都是把「解釋變異的比例」誤讀成其他統計量。另外，不同任務或不同資料集之間的 R² 不可直接比較。


  
損失函數選擇：跟著「要不要放大離群值」走

  

    

    

      
題幹：豪宅房價，要對極端高價物件誤差更敏感、產生較大梯度更新（115Q1 第 2 題）

      

    

  

  

    

      
需求選擇理由

      
要模型對極端值更敏感MSE平方懲罰放大大誤差，梯度與誤差成正比

      
要壓低離群值影響MAE線性懲罰，梯度近似固定

      
想折衷Huber Loss小誤差用平方、大誤差轉線性

      
分類任務交叉熵 Cross-Entropy衡量機率分布差異，迴歸不適用

    

  

  
另有題目考「App 使用時長（連續值）配 MSE、是否流失（二元）配 Binary Cross-Entropy」，兩者對調就是錯的。

114Q2 第 34 題：150 筆、陽性不到 8%，要「兼顧資料利用率」與「各類別在驗證折中的比例一致性」→ 分層留一法（Stratified LOOCV）。一般 5-Fold 在小樣本下訓練資料被切掉太多且未必分層；標準 LOOCV 利用率高卻不保證類別比例；隨機交叉驗證更不控制分層。

115Q1 第 27 題：前 52 週訓練、第 53 週測試，半年後第 80 週明顯衰退 → 滾動窗口驗證（Rolling Window / Time Series Split），永遠以過去預測未來且每輪納入最新資料。K-Fold 與 LOOCV 會打散時間順序造成洩漏；Stratified K-Fold 處理的是類別不平衡不是時間順序。

動手驗證：用 scikit-learn 的 digits 或 iris 資料集，親手跑一次 KFold 與 StratifiedKFold 的結果差異，並把 StandardScaler 分別放在 Pipeline 內、外各跑一次，觀察準確率的落差——這就是附圖程式碼題的實作版本。
