# 20. L21103 生成式AI技術與應用（50 分鐘）

> 一句話定位：這是 L21 科目一裡「與初級落差最大」的知識點 —— 初級 L114／L122 考的是「知道有哪些生成式 AI 工具、會下提示詞」，中級考的是「**看到一個生成失敗的現象，能回推是哪一層技術機制出問題**」，以及「**在一堆看起來都合理的技術名詞中，挑出真正對症的那一個**」。

## 學習目標
- 區辨生成式 AI 與鑑別式 AI 的目標、訓練方式與適用情境，並能判斷題目要的是哪一條路徑
- 說明 VAE、GAN、擴散模型、自迴歸模型四大家族的核心機制、典型故障模式與辨識關鍵字
- 由生成結果的異常現象（顏色錯誤、顆粒化、樣本重複、能力退化）回推對應的技術成因與修正手段
- 精準區辨 LoRA、Prompt Tuning、全參數微調、知識蒸餾、剪枝、量化六種模型客製化／壓縮策略

## 20.1 生成式 vs 鑑別式：先切對這一刀

### 核心區別

| 維度 | 生成式 AI（Generative AI） | 鑑別式 AI（Discriminative AI） |
|---|---|---|
| **學什麼** | 學資料的**分佈** P(x) 或 P(x\|y) | 學決策邊界 P(y\|x) |
| **目標** | 產生**新的資料樣本** | 分類、辨識、預測 |
| **輸出** | 文字、圖像、音訊、影片、程式碼 | 類別標籤或數值 |
| **代表模型** | GPT、VAE、GAN、Diffusion | SVM、決策樹、隨機森林、邏輯迴歸、BERT Classifier |
| **代表應用** | ChatGPT 對話、DALL·E 生圖 | ResNet 影像分類、HMM 語音辨識 |
| **資料效率** | 可用無標註語料大規模預訓練，低資源時退化較慢 | 依賴標註資料，標註少時效能掉得快 |

### 為什麼考題愛用「同時要預測又要生成」當誘答

官方試題出現過兩種典型切法：

```
切法一：只要判斷 → 鑑別式就夠
  「客服郵件分類成投訴/詢問/表揚」→ BERT Classifier

切法二：判斷之外還要「生成虛擬樣本」→ 必須生成式
  「預測顧客流失，並模擬不同促銷策略下的行為，
    產生多樣化虛擬樣本做 A/B 測試」
  → 隨機森林、邏輯迴歸都只能判別，答案是 VAE 或 GAN
```

**判讀口訣**：題幹只要出現「產生新樣本／模擬情境／擴充資料／合成」等字眼，
鑑別式模型（隨機森林、邏輯迴歸、SVM）一律出局，不管它們的準確率被寫得多好聽。

### 生成式 AI 在 AI 演進四階段中的位置

官方指引引用 NVIDIA 執行長黃仁勳於 2025 年 CES 提出的四階段分法：

| 階段 | 能力 | 代表 |
|---|---|---|
| 感知 AI（Perception AI） | 理解影像、語音、文字 | 影像辨識、語音轉文字 |
| **生成式 AI（Generative AI）** | **主動產生多模態內容** | ChatGPT、Stable Diffusion |
| 代理式 AI（Agentic AI） | 具推理與計畫能力，自動完成複雜任務 | AI Agent、工具調用 |
| 物理 AI（Physical AI） | 在真實世界移動、操控與互動 | AI 機器人、自駕車 |

考點在於**順序與分界**：生成式是第二階段（會創造），代理式是第三階段（會規劃並調用工具），不要把「能呼叫 API、能自主分解任務」的敘述當成生成式 AI 的定義。

## 20.2 四大生成模型家族

### 機制與故障模式對照

| 模型 | 核心機制 | 辨識關鍵字 | 優勢 | 典型故障 |
|---|---|---|---|---|
| **VAE** | 編碼器把資料壓到**顯式潛在分佈**，解碼器從潛在向量重建 | 「潛在空間」「變分推斷」「機率建模」 | 潛在空間連續可控、易做跨模態語意對齊 | 生成**模糊**、解析度有限 |
| **GAN** | 生成器與判別器**對抗訓練**，動態逼近真實分佈 | 「兩個網路互相對抗」「判別器」 | 寫實度高、細節銳利 | **模式崩潰**、訓練不穩、對超參數敏感 |
| **擴散模型** | 前向加噪 → 反向**逐步去噪**還原 | 「逐步去噪」「取樣步數」「噪聲」 | 高保真、穩定、多樣性佳 | 取樣步數不足 → 細節不全；推論慢 |
| **自迴歸模型（GPT 類）** | 逐 token 依條件機率生成 | 「由左至右」「逐字生成」「next token」 | 長文連貫、可指令驅動 | **幻覺**、長文邏輯漂移 |

### 官方最愛考的一句話：三者的根本差異

官方 114-2 直接出過「VAE / GAN / Diffusion 在潛在空間對齊與生成策略上的根本差異」，正解就是這三句：

```
VAE   → 顯式潛在變數建模，利於捕捉整體語意結構，但生成解析度有限
GAN   → 以對抗損失學習分佈映射，生成品質高但訓練穩定性差
擴散  → 以條件化去噪（Conditional Denoising）逐步反推，
        兼具高保真、穩定性與多樣性
```

誘答的做法是**張冠李戴**：把 VAE 說成隱式／對抗式、說 VAE 與 GAN 用馬可夫鏈、
或宣稱三者「共用同一潛在空間，只差在解碼器」。看到這類敘述先刪。

### 擴散模型的生成流程（考「取樣參數」必備）

```
文字提示 Prompt
   │
   ▼ 文字編碼器（CLIP text encoder）
文字嵌入向量 ───┐
                │ cross-attention 注入條件
隨機噪聲 z_T ───┴─► 去噪網路（U-Net）
   │  重複 T 次（取樣步數 Sampling Steps）
   ▼
潛在表徵 z_0 ─► 解碼器 ─► 最終影像
```

| 參數 | 控制什麼 | 調太低 | 調太高 |
|---|---|---|---|
| **取樣步數（Steps）** | 去噪過程是否充分 | 顆粒化、邊緣模糊、細節不全 | 邊際效益遞減、生成變慢 |
| **取樣器（Sampler）** | 每一步的數值解法品質 | 低品質取樣器導致同樣步數下細節較差 | — |
| **CFG（Classifier-Free Guidance）** | 對提示的**遵循強度** | 生成偏離提示 | **過飽和、假影（artifact）**、多樣性下降 |

> **高頻陷阱**：4K 圖「邊緣顆粒化、細節模糊」的正解是**增加取樣步數並改用高品質取樣器**，
> 不是「提高 CFG」。CFG 管的是「聽不聽提示的話」，不是「畫得清不清楚」。

### GAN 的模式崩潰（Mode Collapse）

```
症狀：生成器只吐出少數幾種重複樣本，多樣性消失
成因：生成器找到能騙過判別器的「捷徑」，原始 GAN 損失梯度飽和
主流解法：改用 Wasserstein 距離（WGAN 損失）取代原始 GAN 損失
          → 提供更平滑、不易飽和的梯度訊號
輔助手段：梯度懲罰（WGAN-GP）、多尺度判別器、潛在向量加擾動
          → 有幫助，但不是「最主流、最直接」的解
```

官方 114-2 第 20 題就是這個設計：四個選項全都是真實可用的技術，
但只有 **WGAN 損失**是針對模式崩潰的根本解，其餘是穩定訓練的輔助。

## 20.3 從現象推機制（本知識點的最大落差）

中級題型幾乎都長這樣：**給你一個生成結果的異常描述，問你「從技術機制分析，最可能的原因是什麼」**。
初級只要認得工具名字，中級必須把「症狀」對回「哪一層壞掉」。

### 症狀 → 成因 → 對策 對照表

| 症狀描述 | 真正的技術成因 | 正確對策 | 常見誘答 |
|---|---|---|---|
| 主題與場景正確，但**品牌標誌顏色錯、手部姿勢不自然** | **CLIP 的文字編碼器與影像編碼器在語意嵌入空間未充分對齊**，跨模態理解偏差 | 加強圖文對齊訓練／改用可控生成（ControlNet）／後製修正 | 「去噪過程隨機梯度漂移」「提示語超出位置編碼上下文限制」 |
| 高解析度圖**邊緣顆粒化、細節模糊** | 去噪過程不充分（取樣步數不足／取樣器品質差） | 增加取樣步數 + 高品質取樣器 | 提高 CFG、降低輸入解析度 |
| 人臉生成**只有少數幾種樣式、缺乏多樣性** | GAN 模式崩潰 | 改用 WGAN（Wasserstein 距離）損失 | 只加梯度懲罰／只加多尺度判別器 |
| 微調後**醫療問答變強，但通用能力退化** | 災難性遺忘：微調大幅改寫了承載通用知識的預訓練權重 | 凍結大部分參數，僅訓練 LoRA 等少量新增模組，限制更新範圍 | 提高學習率縮短步數、只用領域語料多輪訓練、加大 Batch Size |
| 生成內容**通順但與事實不符** | 幻覺：自迴歸模型本質是機率式的下一 token 預測，不是知識查詢 | RAG 檢索增強、要求引用來源、人工覆核 | 「只要把模型參數再放大就會好」 |
| 導入資料增強後**效能反而下降** | 增強後樣本的**特徵分佈偏離原始資料**，引入分佈偏移 | 檢查並調整增強策略，維持語意一致性 | 提高增強比例、改用半監督重新校正標註 |
| 多模態推論時**某一模態缺失**（有影像沒文字） | 融合層無法取得完整輸入 | 訓練**具模態缺失感知能力**的模型，動態調整融合權重 | 零向量填充、用生成模型補全、直接丟棄樣本 |

### 為什麼「CLIP 對齊不足」是那一題的正解

把品牌標誌顏色錯誤這件事拆開看：

```
提示文字：「品牌標誌」「海邊夕陽」「模特兒手持飲料」
         │
         ▼ 文字編碼器 → 文字嵌入
                           ？ 兩個空間對得準不準
         ▲ 影像編碼器 → 影像嵌入
生成影像：主體(模特兒/飲料/夕陽) ✓  細部屬性(標誌顏色/手指結構) ✗

粗粒度語意（有沒有人、有沒有夕陽）對齊得好 → 主題正確
細粒度語意（特定色碼、手部關節結構）對齊不足 → 細節出錯
```

**判讀邏輯**：現象是「**語意層級的偏差**」（該藍的變綠、手指多一根），
不是「像素層級的隨機雜訊」，也不是「整張圖亂掉」。
語意對不上 → 責任在跨模態對齊，也就是 CLIP 那一層。

反過來檢查誘答為什麼錯：

- 「去噪過程隨機梯度漂移」：擴散的隨機性會影響構圖細節，但不會系統性地把**特定語意屬性**弄錯。
- 「提示語過長超出上下文限制」：這句提示只有二十幾個字，前提就不成立。
- 「未採用對比學習損失」：**太絕對**。CLIP 本來就是用對比學習訓練的，問題在對齊**程度**不足，不是完全沒有對齊機制。

> **這是中級最典型的誘答設計**：用一個「敘述本身沒錯、但與題幹現象對不上」的選項，
> 以及一個「說得太死、把程度問題寫成有無問題」的選項來分高下。

## 20.4 客製化與壓縮：六種策略的精準區辨

這是 L21103 除了「現象推機制」之外第二高頻的考區，115-1 就連續考了三題。

### 第一刀：先分清楚「省訓練成本」還是「省推論成本」

```
省訓練成本（PEFT，參數高效微調）
  ├─ LoRA / QLoRA ······ 凍結原權重，旁路加低秩矩陣
  └─ Prompt / Prefix Tuning ··· 凍結原權重，只學輸入端軟提示

改變模型本身
  ├─ 全參數微調（SFT） ··· 更新全部權重
  └─ RLHF / 偏好對齊 ····· 依人類回饋調整輸出傾向

省推論成本（模型壓縮）
  ├─ 知識蒸餾 ··········· 大模型當老師，另外訓練小的學生模型
  ├─ 剪枝 ··············· 移除低重要性參數或結構
  └─ 量化 ··············· 降低數值精度（FP16 → INT8 / INT4）
```

### 六種策略完整對照

| 策略 | 動原始權重嗎 | 新增什麼 | 主要解決 | 典型題幹關鍵字 |
|---|---|---|---|---|
| **LoRA** | **不動（凍結）** | 各層旁路的**低秩分解可訓練矩陣** | 可訓練參數量與 GPU 記憶體 | 「GPU 記憶體有限」「凍結原模型」「僅訓練少量額外參數」 |
| **QLoRA** | 不動（並額外做 4-bit 量化） | 低秩矩陣 | 單卡也能微調超大模型 | 「單張顯卡微調 70B」 |
| **Prompt / Prefix Tuning** | **不動（凍結）** | 輸入端**可學習的連續向量（Soft Prompt）** | 靠改變**輸入表示**引導既有模型行為 | 「在輸入端加入軟提示」 |
| **全參數微調（SFT）** | **會更新全部權重** | 產生一份新的模型參數 | 深度改變模型行為 | 「以標註問答資料調整模型」 |
| **RLHF** | 會更新 | 獎勵模型 + 策略更新 | 與人類偏好／價值對齊 | 「安全性」「拒答」「對齊」 |
| **知識蒸餾** | 不動老師，**另訓練一個小的學生模型** | 一個全新的小模型 | 降低**推論**成本與模型體積 | 「壓縮成較小模型」 |
| **剪枝（Pruning）** | **會移除參數** | — | 減少參數量、加速推論 | 「移除低重要性參數」 |
| **量化（Quantization）** | **會降低數值精度** | — | 降記憶體與延遲，利於邊緣部署 | 「INT8」「地端／邊緣裝置」 |

### 三組最容易被混為一談的對比

**LoRA 與知識蒸餾**
LoRA 是在**原模型上掛小模組**，模型還是那個 70B；知識蒸餾是**另外做一個小模型**，
而且蒸餾過程仍需大模型完整前向推論，資源需求並不低。
題幹說「凍結原模型、只訓練少量額外參數」→ 一定是 LoRA，不可能是蒸餾。

**LoRA 與剪枝**
剪枝**會改動原模型的參數**，與「凍結原權重」的前提直接衝突。
只要題幹寫了「凍結」，剪枝就自動出局。

**Prompt Tuning 與 Fine-Tuning**
本質差異只有一句：**微調更新的是模型權重，提示微調改的是輸入表示**。
誘答常寫成「提示微調是為了降低推論延遲」——錯，它省的是**訓練與模型儲存成本**，
額外前綴反而會略微增加輸入長度。另一個誘答「兩者本質相同，只差學習率」也是純粹的湊數選項。

### 災難性遺忘（Catastrophic Forgetting）的標準解法

```
成因：SFT 大幅改寫承載通用知識的預訓練權重
錯誤做法：
  ✗ 提高學習率縮短步數 → 權重偏移更劇烈，遺忘更嚴重
  ✗ 只用領域語料反覆訓練 → 這正是造成遺忘的典型作法
  ✗ 加大 Batch Size → 只讓梯度更平穩，對保留舊知識沒有實質作用
正確做法：
  ✓ 凍結大部分預訓練參數，僅微調少量新增模組（如 LoRA 層）
    → 把更新限制在低秩子空間，原始權重不被覆寫
  ✓ 資源允許時可再混入通用語料（replay）
```

### 客製化路徑的選型順序

```
需求是「補最新／私有知識」嗎？
  YES → RAG（檢索增強生成）：不動模型，知識可即時更新
  NO  ↓
需求是「改變輸出格式、語氣、任務行為」嗎？
  YES → 先試提示工程 → 不夠再上 LoRA / Prompt Tuning
  NO  ↓
需求是「深度改變模型能力，且資料與算力都充足」？
  YES → SFT（必要時再 RLHF 對齊）
  NO  ↓
需求是「降低上線後的推論成本／要塞進邊緣裝置」？
  YES → 量化 → 蒸餾 → 剪枝
```

## 20.5 三大應用領域與評估指標

### 文本、圖像、語音的工具地圖

| 領域 | 代表模型／技術 | 代表工具平台 | 官方點名的應用情境 |
|---|---|---|---|
| **文本生成** | GPT 系列、Claude、Gemini、LLaMA、Mistral、Command-R | ChatGPT、GitHub Copilot | 自動化客服、郵件撰寫、法律／醫療文書草擬、程式碼補全、教學內容生成 |
| **圖像生成** | Diffusion（Stable Diffusion、DALL·E 2、Imagen）、GAN（StyleGAN、BigGAN）、ControlNet / InstructPix2Pix | Midjourney、Stable Diffusion WebUI、Adobe Firefly、Canva AI | 品牌視覺設計、社群圖文素材、遊戲角色與場景、影片預視化、風格模仿 |
| **語音合成（TTS）** | Tacotron 2、FastSpeech 2、VITS；Whisper（語音辨識，常與 TTS 搭配成雙向流程） | ElevenLabs、Azure TTS、Google Cloud TTS、Amazon Polly | 語音教材、有聲書、遊戲配音、虛擬偶像、語音客服、智慧家居 |

幾個容易被考的工具特性：

- **Stable Diffusion WebUI**：開源、**可本地部署**，支援 **LoRA 微調**與 **ControlNet** 邊緣／姿態控制 —— 關鍵字是「可控、可客製」。
- **Midjourney**：雲端服務，以**高美學風格**著稱，透過 Discord 或官網下指令。
- **Adobe Firefly**：整合進 Photoshop／Illustrator，強調與專業工作流的相容。
- **Canva AI**：面向**非專業設計者**，強調易用與快速產出。
- **ControlNet / InstructPix2Pix**：控制姿態、邊緣、遮罩或局部修改 —— 看到「要精準控制構圖」就是它們。
- **FastSpeech 2** 是**非自迴歸**設計，比 Tacotron 2 生成更快、穩定性更佳；**VITS** 結合 VAE 與 GAN，端到端從文字直出波形。

### 評估指標對照

| 指標 | 衡量什麼 | 優勢 | 局限 | 適用情境 |
|---|---|---|---|---|
| **BLEU** | 生成與參考文本的 **n-gram 重疊**（含簡短懲罰 Brevity Penalty） | 自動化、計算快 | 忽略語意與流暢性 | 機器翻譯、文本生成 |
| **ROUGE** | 生成對參考文本的**召回率**（ROUGE-N / ROUGE-L 最長公共子序列 / ROUGE-S） | 關注關鍵內容覆蓋 | 無法衡量創新性 | 自動摘要、問答 |
| **人工評估** | 流暢性（Fluency）與準確性（Accuracy），常用 1–5 分制或排序法 | 捕捉語意與語用 | 主觀性強、成本高 | 對話、創意寫作 |
| **MOS** | 語音自然度的人工平均分數（1–5 分） | 直接反映聽感 | 需受測者、成本高 | 語音合成 |
| **WER** | 語音內容的**字詞錯誤率** | 客觀量化 | 只看正確性不看自然度 | 語音辨識／合成內容正確性 |
| **生成延遲** | 從輸入到輸出的時間 | 直接對應使用體驗 | — | 即時語音、互動應用 |

**記憶點**：BLEU 偏**精確率**、看**翻譯**；ROUGE 偏**召回率**、看**摘要**。
兩者都只比字面重疊，都測不出「語意正確」與「有沒有幻覺」——這就是為什麼高風險場景還是要人工評估。

### 語音合成的三大挑戰

情感表達自然度（避免機械感）、多語言與方言的品質一致性、**語音複製（Voice Clone）的隱私與偽造倫理風險**。

## 20.6 風險、治理與趨勢

### 五大風險與對應緩解

| 風險 | 具體樣態 | 緩解手段 | 性質 |
|---|---|---|---|
| **內容真偽與可信度** | 幻覺、偽造新聞、合成語音詐騙 | RAG、引用來源、人工覆核、事實查核 | 事前＋事中 |
| **智慧財產權爭議** | 訓練資料含受著作權保護內容 | **建立訓練資料篩選與授權驗證機制，從源頭排除未授權來源** | **事前（最有效）** |
| **偏見放大** | 訓練資料的性別／種族／文化偏見被延續甚至強化 | 資料去偏、公平性指標、分群評估 | 事前＋事後 |
| **深偽（Deepfake）濫用** | 詐騙、假訊息 | 偵測技術、浮水印／數位指紋、法律規範 | 事後偵測與追溯 |
| **可控性與輸出不確定性** | 提示引導不足導致輸出不相關或不適當 | 提示工程、輸出格式約束、護欄與人工審核 | 事中 |

> **著作權題的固定考法**：四個選項都是真的做法（語意相似度比對、資料授權驗證、差分隱私、浮水印），
> 但題目問的是「**最能有效預防**侵權問題產生」。
> 相似度比對與浮水印都是**事後偵測／追溯**，擋不住侵權發生；
> 差分隱私主要防的是**記憶特定樣本與隱私外洩**，不是著作權。
> 只有**從訓練資料源頭做授權驗證**才是預防。
> 記住這個判準：**問「預防」找源頭，問「追溯」才找浮水印。**

### 五大技術趨勢

| 趨勢 | 內涵 |
|---|---|
| 多模態生成崛起 | 從單一模態走向文字＋圖像＋影片＋語音＋3D 的整合創作系統 |
| 可控生成與提示工程深化 | 能對語氣、風格、長度、格式做多層次調整；提示工程成為關鍵技能 |
| **小型化與邊緣部署** | 因應算力成本與**資料隱私**，模型朝可在地端執行發展（手機、PC、IoT） |
| 模型對齊與安全防護進化 | RLHF、紅隊測試（Red Teaming）強化輸出安全與合規 |
| 法規與全球治理成形 | 歐盟 AI 法案（EU AI Act）、美國 AI 政策框架、國際技術標準 |

### 合成資料（Synthetic Data）的正確定位

```
✓ 在可控條件下大量產生真實世界難以蒐集的長尾場景（大雨、濃霧），
  且生成當下即帶有精確標註 → 擴充訓練資料、提升泛化能力
✗ 不能完全取代真實資料：存在領域差距（Domain Gap），
  實務上必須與真實資料混合並搭配領域自適應
✗ 與推論成本無關：要降低推論成本請用量化或蒸餾
✗ 不限於文字任務：影像領域（自駕模擬平台、渲染引擎）應用極為成熟
```

## 20.7 官方考過什麼

從 114-2 與 115-1 共 100 題官方公告試題中，與本知識點直接或高度相關者共 **16 題**（114-2 佔 11 題、115-1 佔 5 題），密度相當高。

| 題號 | 考點 | 怎麼問 | 正解思路 |
|---|---|---|---|
| 114-2 第 9 題 | 資料增強失效 | 訓練生成式 AI 時做資料增強，效能反而下降 | 增強後**特徵分佈偏離原始資料**，應調整增強策略維持**語意一致性** |
| 114-2 第 20 題 | GAN 模式崩潰 | 人臉生成出現 Mode Collapse 的最常用解法 | 改用 **Wasserstein 距離（WGAN 損失）**；梯度懲罰／多尺度判別器只是輔助 |
| 114-2 第 21 題 | 模態缺失 | 多模態推論時缺少某一模態 | 訓練**具模態缺失感知能力**的模型；補零／生成補全／丟棄樣本都不是根本解 |
| 114-2 第 25 題 | 著作權風險 | 生成內容疑似侵權，最能**預防**的策略 | **訓練資料篩選與授權驗證**（事前）；浮水印與相似度比對只是事後追溯 |
| 114-2 第 35 題 | CLIP 零樣本 | 只靠文字提示就能辨識影像內容的關鍵特性 | **圖文對比式學習映射到共同嵌入空間**，以語意相似度做零樣本分類 |
| 114-2 第 37 題 | 訓練資源限制 | 語音合成模型多 GPU 訓練記憶體不足，架構與硬體都不能換 | **縮小批次大小 + 資料分片**；減資料、調學習率、拿測試集訓練都是錯 |
| 114-2 第 38 題 | 擴散取樣參數 | Stable Diffusion 4K 圖顆粒化模糊，只能在生成階段調整 | **增加取樣步數 + 高品質取樣器**；提高 CFG 反而造成過飽和與假影 |
| 114-2 第 40 題 | 三大模型根本差異 | VAE／GAN／Diffusion 在潛在對齊與生成策略上的差異 | VAE 顯式潛在變數但解析度有限、GAN 對抗損失品質高但不穩、擴散條件化去噪兼具保真與穩定 |
| 114-2 第 43 題 | 生成式 vs 鑑別式 | 如何設計實驗凸顯 VAE 路徑與 BERT Classifier 的本質差異 | **低資源情境下逐步減少標註比例（100%/50%/10%）比較 F1**，看資料利用效率 |
| 114-2 第 44 題 | 選型：要生成 | 既要預測流失又要產生虛擬樣本做 A/B 測試 | **VAE 或 GAN**；隨機森林與邏輯迴歸只能判別，RL 是序貫決策 |
| 114-2 第 50 題 | **現象推機制（旗艦題）** | 主題正確但品牌標誌顏色錯、手部姿勢不自然 | **CLIP 文字編碼器與影像編碼器在語意嵌入空間未充分對齊** |
| 115-1 第 2 題 | LoRA 機制 | GPU 記憶體有限，要凍結 Llama3 70B 只訓練少量參數 | **凍結原權重，各層加入低秩分解可訓練矩陣**；蒸餾要另訓小模型、剪枝會動原權重 |
| 115-1 第 13 題 | Prompt Tuning vs Fine-Tuning | 兩方案最本質的技術差異 | **微調更新模型參數，提示微調改變輸入表示**；不是為了降低推論延遲 |
| 115-1 第 14 題 | 災難性遺忘 | SFT 後通用能力退化，資源有限如何緩解 | **凍結大部分參數、只訓練 LoRA 等新增模組**；提高學習率／只用領域語料／加大 batch 都錯 |
| 115-1 第 21 題 | 生成式 AI 成本優化 | RAG 系統要把 token 成本降到 60%，成本集中在輸入端 | **System Prompt 走 Prompt Caching + 對話歷史摘要壓縮**；壓 max_tokens 與提示「講簡短」都只動到輸出端 |
| 115-1 第 33 題 | 合成資料定位 | 自駕惡劣天氣資料不足，改用合成資料 | **可控條件下產生多樣化場景、擴充訓練資料並提升泛化**；不能完全取代真實資料 |

## 20.8 易錯與陷阱

- [ ] LoRA 是「**凍結原權重、旁路加低秩矩陣**」，不是把大模型壓成小模型（那是知識蒸餾），也不是移除參數（那是剪枝）
- [ ] LoRA／Prompt Tuning 省的是**訓練成本**；蒸餾／剪枝／量化省的是**推論成本**。題幹說「GPU 記憶體不足、無法反向傳播」是訓練問題，說「邊緣裝置跑不動」才是推論問題
- [ ] Prompt Tuning 的目的是**省訓練與儲存成本**，不是「降低推論延遲」——軟提示反而讓輸入變長
- [ ] 擴散模型是「**從噪聲逐步去噪**」，不是「照著文字直接畫」；文字只是透過交叉注意力注入的**條件**
- [ ] **CFG 管遵循提示的強度，取樣步數管細節清晰度**。圖糊了要加步數，不是加 CFG；CFG 拉太高會過飽和與產生假影
- [ ] GAN 模式崩潰的主流解是 **WGAN 損失**，梯度懲罰（WGAN-GP）是搭配它使用的穩定化手段，不是獨立主解
- [ ] 生成細節出錯若屬**語意層級**（顏色錯、結構怪），成因指向**跨模態對齊不足**；若整張圖隨機雜訊才輪到去噪過程
- [ ] 「未採用對比學習」這種**把程度問題寫成有無問題**的選項，通常是誘答 —— CLIP 本來就用對比學習
- [ ] 著作權要從**源頭**（訓練資料授權驗證）預防，浮水印與數位指紋只是**事後追溯**；差分隱私防的是記憶特定樣本與隱私外洩
- [ ] 幻覺的成因是**自迴歸的機率式生成機制**，不是「資料量不夠」；解法是 RAG 與人工覆核，不是單純把模型放大
- [ ] 災難性遺忘不能靠「提高學習率縮短訓練」解決 —— 學習率越高權重偏移越大，遺忘只會更嚴重
- [ ] 合成資料**不能完全取代真實資料**（存在 Domain Gap），也與推論成本無關
- [ ] 題幹只要要求「**產生新樣本／模擬情境**」，隨機森林、邏輯迴歸、SVM 一律出局
- [ ] BLEU 看 n-gram 精確率（翻譯）、ROUGE 看召回率（摘要）、MOS 看語音自然度（1–5 分）、WER 看字詞錯誤率 —— 四個不要互換
- [ ] 生成式 AI 是四階段中的**第二階段**；「會規劃任務、會調用工具」屬於代理式 AI，不要當成生成式 AI 的定義
