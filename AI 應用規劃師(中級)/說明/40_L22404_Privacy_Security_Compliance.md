# 40. L22404 大數據隱私保護、安全與合規（45 分鐘）

> 一句話定位：初級只要你知道「個資要保護」，中級 L22 則把你放進一座**已經蓋好的大數據平台**——資料湖裡躺著數百億筆行為紀錄、下游有多個團隊與外部夥伴要取用——然後問你：這一層該套哪一種去識別化、這個請求該不該放行、這條跨境管線合不合法。

## 學習目標
- 說明大數據的「量、速、多樣、長期留存」四項特性各自放大了哪一種再識別風險，並指出橫向比對與時間軸拼接的差別
- 依「處理的是階層資訊還是連續數值」「保護的是識別還是敏感值」「保證是統計性還是密碼學的」三個判準，把七種去識別化／隱私強化技術定位到資料管線的正確層級
- 對照 GDPR、CCPA 與我國個人資料保護法在同意模式、當事人權利、通報期限與跨境傳輸上的差異，並判斷一個大數據取用情境的合法依據
- 設計資料湖的存取控制、加密三態與稽核軌跡，並說明資料生命週期每一階段對應的治理控制項

## 40.1 大數據把個資風險放大在哪裡

### 三類資料，三種處理邏輯

| 類別 | 定義 | 典型欄位 | 大數據平台的處理原則 |
|---|---|---|---|
| **直接識別資訊** | 單一欄位即可指向特定個人 | 姓名、身分證號、電話、Email、裝置 ID | 進入分析層之前就移除、遮蔽或雜湊；原始值只留在最高權限的落地層 |
| **準識別資訊（Quasi-identifier）** | 單看無識別性，組合後可能唯一 | 性別、出生年月、郵遞區號、瀏覽紀錄、GPS 軌跡 | 不能只靠移除，要用泛化／分桶／K-匿名降低鑑別力 |
| **敏感資料** | 外洩後傷害特別大的資訊 | 健康紀錄、信用狀況、宗教信仰、族群 | 原則上另案授權、獨立儲存區、獨立稽核；其中病歷、醫療、基因、性生活、健康檢查與犯罪前科屬我國個資法第 6 條的特種個資（宗教、族群是 GDPR 第 9 條的特種類別，我國並未列入） |

美國學界的經典研究指出，僅憑「郵遞區號＋出生日期＋性別」三個準識別欄位，就足以定位該國人口中的絕大多數人。這正是大數據情境的核心命題：**欄位愈多、時間跨度愈長，準識別欄位的組合鑑別力愈接近直接識別。**

### 大數據的四項特性各自放大哪一種風險

```
Volume（量大、多源匯流）
   → 橫向比對風險：內部行銷資料庫 ＋ 外部購買名單 ＋ 公開社群貼文
      三方交叉，就能把「匿名」的一列還原成一個人

Velocity（高速串流、即時軌跡）
   → 時間軸拼接風險：每 5 分鐘一筆的 GPS 或刷卡時間序列
      可推出住家、工作地、作息，本身就是身分指紋

Variety（多模態、非結構化）
   → 保護不足風險：K-匿名這類技術對表格有效，對自由文本、語音、
      影像適用性有限；客服逐字稿的個資躲在句子中間，欄位遮罩掃不到

長期留存（資料湖「先存再說」）
   → 保存期限失控風險：蒐集時的目的早已結束，資料還在；
      當年的去識別化強度，擋不住今天的比對能力
```

### 《學習指引》舉的四個實務案例

| 領域 | 出事的原因 | 指引描述的後果 |
|---|---|---|
| 醫療 | AI 診斷模型直接使用未匿名化病歷（含年齡、診斷紀錄） | 經外部資料比對識別患者，違反個資法遭罰 30 萬元 |
| 電商 | 推薦系統未匿名化顧客瀏覽紀錄 | 遭駭客以行為軌跡識別用戶，品牌信任度下降 |
| 金融 | 詐欺偵測模型使用未脫敏交易資料 | 遭時間軸拼接洩漏身分，影響用戶滿意度 |
| 教育 | 學習分析模型未移除學生年級與地區 | 身分外洩，學校合規性受質疑 |

四個案例的共同結構一樣：**不是加密被攻破，而是「以為移除了識別欄位就安全」**。

## 40.2 基礎去識別化五技術與它們在資料管線的落點

| 技術 | 原理 | 大數據管線落點 | 優點 | 限制 |
|---|---|---|---|---|
| **遮蔽 Masking** | 以符號或假值取代部分內容（王大明→王○○；A123456789→A12\*\*\*\*\*\*89） | 報表層、測試環境複製、前端顯示層（可用動態遮罩在查詢當下即時套用） | 簡單快速，**保留欄位格式**（長度、型別不變） | 只隱藏部分字元，配合旁證仍可能被推回 |
| **雜湊 Hashing** | 單向雜湊（如 SHA-256）產生固定長度字串，供比對而非顯示 | ETL 載入時對用戶 ID 做一致性雜湊，讓跨資料表仍可 join | 不可逆、跨庫比對一致、支援去重 | 原始值種類少（短 ID、手機號）易被窮舉或彩虹表還原，**應加 salt**；雜湊值無法做數值運算 |
| **泛化 Generalization** | 降低**階層式**資訊精度（1987-03-12→1980 年代；信義區某路→台北市） | Silver 層轉換階段 | 保留分佈特性，處理地理與時間階層特別有效 | 精度損失影響細分群分析 |
| **分桶 Bucketing** | 把**連續數值**切成區間（58,000→50K–60K；32 歲→30–39 歲） | 特徵工程階段，可與建模的分箱共用邏輯 | 保留趨勢，降低個體識別 | 分桶過細仍可能剩下極少數人，等於沒保護 |
| **隨機擾動 Noise Injection** | 對數值加隨機噪音（如高斯噪音）：50,000→50,123 | 對外發布的統計資料集 | 保留平均數、變異數等整體統計特性 | 噪音幅度過大失去效用、過小無保護；**單純加噪不等於差分隱私**（差分隱私要求噪音依敏感度與 ε 校準） |

**泛化 vs 分桶怎麼分：** 兩者都在降精度，差別在對象。**泛化處理階層式／類別式資訊**（日期→年代、地址→縣市），**分桶處理連續數值**（收入、年齡→區間）。題幹給地址或日期階層就往泛化想，給金額或年齡數字就往分桶想。

### 去識別化該發生在資料湖的哪一層

```
┌──────────────┬────────────────────────┬──────────────────────────┐
│ 落地層 Bronze │ 原始資料，含完整 PII    │ 靜態加密 ＋ 最嚴格權限    │
│              │ 僅資料工程與稽核可及    │ 每一次存取都留稽核軌跡    │
├──────────────┼────────────────────────┼──────────────────────────┤
│ 整理層 Silver │ 清洗 ＋ 去識別化執行處  │ 雜湊 ID、泛化、分桶、遮蔽 │
│              │ 一般分析師的起點        │ 欄位層級權限、動態遮罩    │
├──────────────┼────────────────────────┼──────────────────────────┤
│ 應用層 Gold   │ 聚合指標、特徵表、報表  │ 原則上不含個體層級識別欄  │
│              │ 業務單位與外部夥伴取用  │ 對外發布前做再識別測試    │
└──────────────┴────────────────────────┴──────────────────────────┘

要點：去識別化是「往下游逐層加強」，不是最後一關才做。Gold 層若要對外，
      必須在 Silver → Gold 之間補上 K-匿名或差分隱私，而不是靠口頭約束。
```

## 40.3 進階隱私強化技術（PETs）：用生命週期定位，而不是用名稱記憶

| 技術 | 保護發生在生命週期的哪一段 | 資料在運算當下的狀態 | 大數據典型情境 | 主要代價 |
|---|---|---|---|---|
| **K-匿名／L-多樣性／T-接近性** | 資料**發布前**的轉換 | 明文，準識別欄位已群組化 | 開放資料集、醫療研究資料釋出 | 計算複雜度高；K 值太大則資料變粗；對非結構化資料適用性有限 |
| **差分隱私 Differential Privacy** | **查詢結果或模型輸出**產生時 | 明文（在結果上加校準噪音） | 統計查詢 API、DP-SGD 訓練、差分隱私合成資料 | 效用下降；隱私預算 ε 會隨查詢次數累積消耗 |
| **聯邦學習 Federated Learning** | **訓練階段的資料移動**被取消 | 明文，但留在各參與方本地 | 跨院醫療聯盟、跨行風控、行動裝置鍵盤預測 | 通訊成本高；梯度可能被逆向推導，常需再疊 DP 或安全聚合 |
| **同態加密 Homomorphic Encryption** | **運算全程** | 密文，自始至終不解密 | 把推論或統計外包給雲端服務商 | 運算效能極低，完全同態（FHE）需高規硬體 |
| **對稱／非對稱加密** | **傳輸中與靜態儲存** | 密文（運算前須解密） | TLS 傳輸、資料湖靜態加密、金鑰交換 | 對稱的弱點是金鑰配送；非對稱慢，**主要用於金鑰交換與身分驗證，不用來加密大量資料** |
| **安全多方計算 MPC** | **多方共同運算的過程中** | 各方只看得到自己的輸入與最終結果 | 跨機構聯合統計、聯合風控 | **必須「多方且互不信任」**；題幹寫「單一雲端服務商」就排除 MPC，那是同態加密的場景。L22 官方 100 題尚未考，但與 114Q2-20 同型 |
| **亂數回應 Randomized Response** | **資料被說出來之前**（蒐集當下） | 個人端即已擾動 | 敏感問卷、端側遙測回報 | 需大量樣本才能還原母體統計；面對重複查詢保護力有限 |

### 三組最常互相當誤答的配對

```
同態加密（HE） vs 差分隱私（DP）
   HE：「一秒都不能讓雲端看到明文」→ 密文上直接運算，解密後與明文運算結果一致
   DP：「不能讓人反推某個人在不在資料集裡」→ 明文上算，在輸出加校準噪音
   看到「不解密／密文上運算」就往 HE，看到「雜訊／ε／不顯著改變輸出」就往 DP

聯邦學習 vs 同態加密
   FL 保護的是「資料不用搬家」，它本身不加密，傳的是模型參數更新
   HE 保護的是「資料就算搬家了也看不懂」
   題幹說「各醫院不得交換原始病歷，但要共同訓練一個模型」→ FL
   題幹說「要外包給單一雲端服務商，且該服務商不得解密」→ HE

K-匿名 vs 差分隱私
   K 的 k 值只保證「同一準識別組合至少有 k 個人」，是群組大小的保證
   DP 以 ε 提供形式化、可證明、且可組合（composable）的保證
   題幹問「哪一個提供可量化的隱私保證」→ DP；問「表格資料如何避免被唯一定位」→ K-匿名
```

### K-匿名家族三層遞進

```
K-匿名      每筆紀錄在準識別欄位上至少與其他 K-1 筆相同  → 管「識別」
   ↓ 弱點：同組內敏感值全一樣（5 人同病），不必識別是誰也能推出病情
L-多樣性    每個分組的敏感欄位至少有 L 種不同值          → 管「敏感值的種類」
   ↓ 弱點：種類夠多但分佈極偏（9 比 1），仍可高機率猜中
T-接近性    分組內敏感欄位的分佈需與整體分佈相近        → 管「敏感值的分佈」
```

三者是**層層補強**的關係，不是三個可互相取代的平行選項。

### 大數據平台特有的隱私攻擊面

模型上線、API 對外開放後，攻擊面就從「資料庫」轉移到「模型輸出」。這四種攻擊常被互相當成誘答：

| 攻擊 | 攻擊者想知道什麼 | 原理 | 對應防禦 |
|---|---|---|---|
| **連結攻擊 Linkage Attack** | 這筆去識別化紀錄是誰 | 拿外部資料集與準識別欄位交叉比對 | 泛化／分桶／K-匿名，並做再識別模擬測試 |
| **成員推斷 Membership Inference** | 某個人**在不在**訓練集裡 | 模型對訓練時看過的樣本通常給出**更高信心、更低損失**，反覆查詢即可辨出差異 | 以差分隱私訓練加噪；只回傳粗化的標籤或信心值；避免嚴重過擬合 |
| **模型反演／屬性推斷 Model Inversion** | 輸入的敏感特徵是什麼 | 從輸出反推輸入屬性 | 限制輸出資訊量、控制查詢粒度 |
| **模型萃取 Model Extraction** | 複製模型本身 | 大量查詢後訓練替代模型 | 限制存取與查詢額度、浮水印 |

**成員推斷不等於模型萃取**：前者的目標是「判斷某筆資料是否為訓練成員」，後者的目標是「複製模型功能」。而成員推斷的訊號來自**輸出信心分布**，不是回應時間或查詢頻率，所以「限制查詢次數」只能減緩速度，並未消除訊號。

**差分隱私合成資料**還有一個易錯點：它的做法是**先以滿足差分隱私的方式在原始資料上訓練生成模型，再由該模型產出一份可自由發布、可重複分析的合成資料集**，隱私預算在生成階段一次付清；至於「在發布查詢結果或訓練時對資料加雜訊」，講的是差分隱私的一般機制（Laplace／Gaussian 機制），不是合成資料這條路線的特徵。

## 40.4 合規：原則、合法依據與三部法規

### 五項核心原則（GDPR、CCPA、我國個資法的公約數）

| 原則 | 大數據場景的具體要求 | 常見違反 |
|---|---|---|
| **合法性、正當性與透明性** | 隱私政策要寫清楚資料會進入模型訓練，而不只寫「用於改善服務」 | 用一句「同意本公司於各項業務使用您的資料」包山包海 |
| **目的限制（Purpose Limitation）** | 蒐集時為「客服品質分析」的逐字稿，不得直接轉用於廣告投放或對外販售模型 | 資料湖「先存再說」，日後被新專案任意取用 |
| **資料最小化（Data Minimization）** | 只收任務所需欄位；建模需要交易金額與時間，就不要順手帶入婚姻狀況 | 一次拉整張表進特徵工程 |
| **保存期限限制** | 設定保留期，逾期刪除或匿名化，並落實為排程工作而非文件宣示 | 分區（partition）永不刪除，冷儲存無限累積 |
| **可追蹤與可刪除性** | 要能回答「某人的資料散落在哪幾個系統、備份與模型裡」，並在期限內完成查閱或刪除 | 只能刪主資料表，資料湖副本、快取與訓練集仍留存 |

**大數據的「被遺忘權」難題：** 刪掉來源資料列，不等於刪掉它在模型權重裡的影響。因應方式是保留資料血緣（Data Lineage）紀錄，判斷哪些模型用過該筆資料，必要時安排重訓練或機器遺忘（Machine Unlearning）。

### AI 訓練資料取得的合法依據

| 依據 | 成立條件 | 大數據情境要注意什麼 |
|---|---|---|
| **明確同意** | 蒐集前主動同意，說明用途，且可撤回 | 同意要具備自由性、明確具體性、可撤回性；撤回後必須能真的停止使用 |
| **契約履行必要** | 處理是履行契約所必需（如信用卡風險評估） | 「為了改善模型」通常不算契約必要，不要濫用此依據 |
| **公共利益或學術研究** | 資料經去識別化處理、無從識別特定個人 | 須經倫理審查（IRB）或內部審查，保留匿名化歷程與審查紀錄供稽核 |
| **非個人資料** | 已匿名化到無法直接或間接識別 | 嚴格說這是「不在個資法規範內」而非一種法律依據；必須定期做再識別風險測試並留存紀錄 |

> GDPR 另有法定義務、重大利益、正當利益等其他法律基礎；上表是《學習指引》針對 AI 訓練情境所列的四種常見情形。

### 三部法規對照

| 面向 | **GDPR**（歐盟） | **CCPA／CPRA**（美國加州） | **PDPA 個人資料保護法**（我國） |
|---|---|---|---|
| 同意模式 | 原則 **opt-in**，需事前取得合法基礎 | 偏 **opt-out**，消費者可拒絕出售／分享其個資 | 原則告知後蒐集，特種個資另有嚴格限制 |
| 當事人權利 | 查閱、更正、刪除（被遺忘權）、限制處理、**資料可攜權**、拒絕自動化決策 | 知情、刪除、更正、拒絕出售／分享、不因行使權利而受差別待遇 | 查詢、閱覽、製給複製本、補充更正、停止蒐集處理利用、刪除 |
| **回應／通報期限** | 當事人請求原則 **1 個月內**回覆（複雜案件可延長）；個資外洩應於**知悉後 72 小時內**通報監管機關 | 依法定期限回應消費者請求 | 依法通知當事人並依主管機關規定通報 |
| 跨境傳輸 | 移轉至歐盟境外須有適足性認定、**標準合約條款（SCC）**或其他適當保障措施 | 以契約與揭露義務約束第三方 | **第 21 條**：中央目的事業主管機關於特定情形（如接受國法規不完善致有損當事人權益之虞、以迂迴方式傳輸第三國規避本法等）**得限制國際傳輸** |
| 敏感／特種資料 | 特種類別個資原則禁止處理，例外才可 | 敏感個資可要求限制使用 | **第 6 條**：病歷、醫療、基因、性生活、健康檢查、犯罪前科原則不得蒐集處理利用，符合法定例外才可 |
| 罰則量級 | 依違反情節，最高可達 2,000 萬歐元或全球年營業額 4%（擇高） | 依違規件數計罰，涉及未成年人加重 | 2023 年修法後，未依規定訂定安全維護計畫或未採適當安全措施者，主管機關得限期改正並按次處罰，情節重大者罰鍰上限提高至新臺幣 1,500 萬元 |

**兩個必背而且常被對調的數字：** GDPR 的**當事人查閱請求是「1 個月內回覆」**，**資料外洩是「知悉後 72 小時內通報」**。看到題目把 72 小時掛在查閱權上，或把一個月掛在外洩通報上，直接刪。

**假名化 ≠ 匿名化：** 假名化（Pseudonymisation）以代碼取代識別欄位，但**對照表或金鑰還在**，GDPR 明定假名化資料**仍屬個人資料**，仍受完整規範；匿名化要求無法再識別，才可能降低法規適用程度。大數據平台裡最常見的錯誤，就是把「用戶 ID 換成雜湊值」當成已匿名化——只要 salt 與對照關係還在系統內、或原始值空間小到可窮舉，它就仍是個人資料。

### 我國個資法在大數據應用上的兩個額外考點

- **域外適用**：個資法第 51 條第 2 項規定，我國人民的個人資料在境外被蒐集、處理或利用者，亦適用本法。把使用者資料送到境外雲端訓練，不會因此跳出個資法。
- **安全維護義務**：非公務機關須訂定個人資料檔案安全維護計畫與業務終止後的處理方法，這使得「資料湖的存取控制與稽核軌跡」從最佳實務升格為**法定義務**，也是下一節存在的理由。

## 40.5 大數據平台的安全控制面

### 存取控制：從「誰」到「為什麼」

| 模型 | 判斷依據 | 適合情境 | 限制 |
|---|---|---|---|
| **RBAC（角色）** | 使用者屬於哪個角色 | 組織結構穩定、資料分類單純 | 角色會爆炸；同一角色難以區分不同專案的取用目的 |
| **ABAC（屬性）** | 使用者屬性 × 資料標籤 × 環境條件（部門、資料敏感度標籤、來源 IP、時間） | 資料湖多租戶、跨專案共用 | 政策撰寫與測試複雜 |
| **目的別存取（Purpose-based）** | 這次查詢宣告的用途是否與蒐集目的相符 | 落實目的限制原則 | 需要資料目錄記錄每份資料的原始蒐集目的 |

三種顆粒度要搭配使用：

```
資料集層級   這個人能不能看到這張表
   ↓
資料列層級（Row-Level Security）
             只看得到自己分行／自己地區的列
   ↓
欄位層級（Column-Level Security ＋ 動態遮罩）
             同一張表，分析師看到 A12******89，稽核人員看到完整值
```

### 加密的三種狀態

| 狀態 | 技術 | 大數據平台落點 |
|---|---|---|
| **傳輸中（in transit）** | TLS | 串流寫入、節點間 shuffle、對外 API |
| **靜態（at rest）** | AES 等對稱加密、透明資料加密、金鑰管理服務（KMS） | 物件儲存、資料湖分區、備份與冷儲存 |
| **使用中（in use）** | 機密運算（TEE）、**同態加密** | 外包給第三方的運算，或多方協作分析 |

多數企業做到前兩者就停住，而**外洩常發生在「使用中」**——資料為了運算被解密、被複製到分析師的筆電、被匯出成試算表。這也是同態加密與聯邦學習在考題裡出現的理由：它們處理的正是第三種狀態。

**雜湊不在上表任一列**：它單向、無金鑰、沒有解密程序，做的是完整性驗證與一致性比對，不是機密性保護。

### 稽核軌跡與資料血緣

| 機制 | 要記錄什麼 | 為什麼大數據特別需要 |
|---|---|---|
| **存取稽核軌跡（Audit Log）** | 誰、何時、用什麼身分、查了哪張表的哪些欄位、匯出多少列 | 資料湖的取用者多且分散，事後追查只能靠日誌；日誌本身應唯讀、獨立保存 |
| **資料血緣（Data Lineage）** | 某欄位從哪個來源系統來、經過哪些轉換、餵進哪些模型 | 當事人請求刪除或發生外洩時，能快速界定影響範圍 |
| **資料版本管理** | 資料集快照版本、處理流程版本 | 支援稽核重現與模型問題回溯 |

《學習指引》章末練習直接考過：要確保 AI 系統的合規性與可追溯性，應建立的是**資料版本管理與操作紀錄制度**，不是模型評分制度。

### 資料生命週期：每一階段的控制項

| 階段 | 主要控制 | 常見失誤 |
|---|---|---|
| 蒐集 | 合法依據、告知同意、最小化 | 同意書籠統，蒐集欄位遠超需求 |
| 傳輸 | TLS、來源驗證、完整性檢查 | 用未加密的內部管線傳 PII |
| 儲存 | 靜態加密、分層分區、權限與標籤 | 原始層與分析層混放，全體分析師可讀 |
| 使用／建模 | 去識別化、目的別存取、訓練集紀錄 | 直接拿 Bronze 層原始資料訓練 |
| 共享／發布 | 再識別測試、K-匿名或差分隱私、契約約束 | 以為聚合過就安全，未驗證小樣本群組 |
| 封存 | 降級儲存仍需加密與權限 | 備份不在權限控管範圍內 |
| 銷毀 | 逾期刪除或匿名化、刪除證明、含備份與副本 | 主表刪了，備份與特徵表沒刪 |

## 40.6 內部治理制度：五個面向

| 面向 | 具體作法 | 考點提示 |
|---|---|---|
| **政策** | 訂定資料使用範圍與限制（哪些資料可用於訓練、哪些需特別授權）、AI 倫理準則（公平、非歧視、透明）、**跨境資料傳輸規範**；政策須定期更新以納入生成式 AI 等新議題 | 政策不是一次性文件，「定期檢視更新」本身是要求 |
| **組織** | **資料治理委員會**（法務、資安、資料科學、資訊、業務跨部門組成），審議資料使用規則、授權申請與違規處理；設置首席 AI 官或資料管理員（Data Steward） | 治理是**跨部門共同責任**，不是資安部門或 IT 部門單獨負責 |
| **流程** | 資料登記與資產盤點（**資料目錄 Data Catalog**：來源、用途、風險層級、授權狀態）；**模型說明書（Model Card）**：訓練資料、假設、測試結果與限制；權限控管與審核流程 | Data Catalog 管資料，Model Card 管模型，兩者不互相取代 |
| **技術工具** | 資料稽核與追蹤系統、敏感資料自動偵測（掃描欄位中的姓名、地址、IP）、模型監控（偏誤、**概念漂移 Concept Drift**、輸出合理性） | 僅靠人工控管必然遺漏，自動化是必要條件而非加分項 |
| **文化** | 分角色的定期教育訓練、把合規納入開發流程與績效、匿名舉報與回饋機制 | 「訓練 ＋ 制度 ＋ 舉報管道」三者並列 |

```
治理成熟度的判斷順序（考題常用這條線排除選項）

  只有技術防護                → 缺少制度與責任歸屬
  技術 ＋ 政策 ＋ 跨部門組織  → 可運作
  ＋ 生命週期流程與自動化稽核 → 可持續、可稽核
  ＋ 教育訓練與舉報機制       → 可落地到日常工作
```

選項寫「由 IT 團隊部署後定期觀察效能」「採購更多訓練設備」，是把治理窄化成技術或資源問題，通常是誘答；正解方向會是**導入 AI 治理框架與跨部門監管流程**。

## 40.7 官方考過什麼

**計數基準：** 以「**題幹或選項的主要考點落在本知識點**」認定，不含只是情境背景提及個資的題目；範圍是 114-2 與 115-1 兩份官方公告試題共 100 題。依此基準，屬於 L22404 的共 **5 題（5%）**。

| # | 考點 | 怎麼問 | 正解思路 |
|---|---|---|---|
| 114Q2-13 | 同態加密核心特性 | 純定義題：下列何者為同態加密的核心特性 | 正解：**可直接在加密狀態下進行數據運算**。誘答分別是去識別化（匿名識別碼）、資料前處理（標準化）、資料清理（異常值偵測）——三個誘答都不在密碼學層面，屬於「用不同領域的名詞填空」 |
| 114Q2-20 | 同態加密的情境選用 | 銀行把信用風險模型部署到雲端，要求服務商**在不解密原始資料的情況下**執行運算 | 正解：**同態加密**。匿名化與雜湊保護身分但無法支援密文運算；資料本地化只限制**儲存位置**，沒有解決「雲端要算但不能看」的問題 |
| 114Q2-32 | 生成式 AI 客服的個資外洩防治 | 對話紀錄訓練的語言模型可能在回覆中吐出真實姓名、電話、交易資訊 | 正解：**訓練前做匿名化或偽匿名化，並建立輸出內容稽核機制**（事前＋事後雙重防護）。強化學習微調無法保證不洩漏已記憶的資訊；同態加密是密文運算技術，擋不住模型生成已學得的個資；只隱藏姓名仍會漏電話與交易資訊 |
| 115Q1-37 | 成員推斷攻擊的原理與防禦 | 信用評分模型開放 API，資安團隊警告成員推斷攻擊 | 正解：**利用模型對訓練樣本的高信心輸出判斷其是否屬於訓練集；以差分隱私或降低輸出信心防禦**。誘答把它寫成靠查詢頻率（錯，訊號在信心分布）、屬性推斷／模型反演、模型萃取 |
| 115Q1-38 | 三種去識別化技術的比較（選「不正確」） | K-匿名、差分隱私合成資料、亂數回應三者的定義與強度 | 應選的錯誤敘述是把**差分隱私合成資料**描述成「發布查詢結果或訓練時直接對原始資料加雜訊」——那是 DP 的一般機制；合成資料是先以 DP 方式訓練生成模型再發布合成集。其餘三項正確：K-匿名用於表格型、每組至少 K 筆；亂數回應提供可否認性；只有 DP 提供可組合且可量化的保證 |

**命題觀察：**

- **同態加密是這個知識點的第一考點**：5 題裡有 2 題以它為正解（114Q2-13、114Q2-20），另有 1 題（114Q2-32）把它設計成**誤用技術的誘答**。要同時記得它「能做什麼」與「不能做什麼」——它保護的是運算過程中的資料機密性，不能阻止模型把已經學進參數的個資講出來。
- **差分隱私三種身分都出現過**：在 115Q1-37 是正解防禦，在 115Q1-38 是比較基準，在 L23 的同類題中則常是同態加密的誘答。判準始終是「明文上加校準噪音、保護個體存不存在」。
- **115 年出現明顯難度升級**：114 年考的是單一技術定義，115 年改考**攻擊面**（成員推斷）與**技術強度比較**（K-匿名／DP 合成資料／亂數回應），而且是「選不正確」題型。準備方向要從背定義轉成建立橫向比較表。
- 另有 1 題（115Q1-36，電商資料湖的 Text-to-SQL 架構）題幹寫明需要「資料庫層級的權限控管與查詢審計」，但主要考點是查詢架構選型，**不計入上述 5 題**；它的存在說明官方會把權限與稽核當成架構題的限制條件。
- 官方《學習指引》本節章末自附 10 題練習中，有 5 題（第 5～9 題）落在本知識點：資料匿名化、差分隱私、醫療資料的合法授權與同意、資料版本管理與操作紀錄制度、AI 治理框架與跨部門監管流程。這 5 題與公告試題的 5 題是**兩組不同來源**，合起來可以看出官方的關注面涵蓋「技術 → 法遵 → 治理」三層。

## 40.8 易錯與陷阱

- [ ] **同態加密是在密文上直接運算，不是「壓縮後再加密」或「傳輸前加密」** —— 它的代價是運算更慢、資料更大，任何講它能加速或省資源的敘述方向相反。
- [ ] **同態加密保護的是運算過程的機密性，不是模型輸出的內容** —— 它擋不住語言模型把訓練時記住的個資生成出來；那要靠訓練前去識別化加上輸出稽核。
- [ ] **差分隱私是統計保護，不是加密** —— 運算當下資料仍是明文，它保護的是「某個人在不在資料集裡」，不是「資料內容不被看見」。
- [ ] **差分隱私加的是依敏感度與 ε 校準的噪音，不是隨手加雜訊** —— 隨機擾動只是基礎匿名化手法，沒有形式化保證；ε 越小越嚴格但效用越低。
- [ ] **差分隱私合成資料是先用 DP 訓練生成模型再發布合成集，不是在每次查詢時對原始資料加雜訊** —— 後者是 DP 的一般機制（Laplace／Gaussian）。
- [ ] **聯邦學習是分散式協作訓練框架，不是加密技術** —— 資料留本地、只交換參數更新，梯度仍可能被逆推，實務上要再疊差分隱私或安全聚合。
- [ ] **資料本地化限制的是儲存地點，不是讓外部方能在密文上運算** —— 題幹要求「雲端能算但不能解密」時，本地化不是答案。
- [ ] **雜湊是單向摘要，不是加密** —— 沒有金鑰、沒有解密程序；且原始值空間小時要加 salt，否則可被窮舉還原。
- [ ] **非對稱加密主要用於金鑰交換與身分驗證，不是用來加密大量資料** —— 大量資料以對稱加密處理，效率差距是數量級的。
- [ ] **移除姓名是移除直接識別資訊，不是完成匿名化** —— 準識別欄位的組合仍可能唯一定位個人，必須做泛化／分桶／K-匿名並執行再識別測試。
- [ ] **假名化保留了還原可能，不等於匿名化** —— GDPR 明定假名化資料仍屬個人資料；只有無法再識別的匿名化才可能降低法規適用程度。
- [ ] **K-匿名管識別、L-多樣性管敏感值的種類、T-接近性管敏感值的分佈** —— 三者層層補強，不是可互相取代的平行選項。
- [ ] **K 的 k 值只保證群組大小，不是可證明的數學隱私保證** —— 提供形式化、可量化（以 ε）且可組合保證的是差分隱私。
- [ ] **泛化處理階層式資訊、分桶處理連續數值** —— 兩者都降精度但對象不同，不要在選項裡對調。
- [ ] **K-匿名家族對非結構化資料（自由文本、影像、語音）適用性有限** —— 題幹是逐字稿或影像時，方向要往內容偵測、實體遮蔽或差分隱私走。
- [ ] **成員推斷攻擊靠的是輸出信心分布的差異，不是回應時間或查詢頻率** —— 所以限制查詢次數只能減緩，不能消除訊號。
- [ ] **成員推斷判斷「某筆資料是否為訓練成員」，模型萃取是「複製模型功能」，模型反演是「反推輸入的敏感屬性」** —— 三者目標不同，選項常互相偽裝。
- [ ] **GDPR 的當事人查閱請求是一個月內回覆，資料外洩是知悉後 72 小時內通報主管機關** —— 兩個期限常被對調。
- [ ] **CCPA 偏 opt-out（可拒絕出售／分享），GDPR 與我國個資法偏事前告知與同意** —— 不要把加州模式套到歐盟情境。
- [ ] **我國個資法的特種個資是病歷、醫療、基因、性生活、健康檢查與犯罪前科** —— 原則不得蒐集處理利用，符合法定例外才可，不是「取得同意就一律可用」。
- [ ] **把資料送到境外雲端不會跳出我國個資法** —— 個資法有域外適用規定，且中央目的事業主管機關在特定情形得限制國際傳輸。
- [ ] **刪除來源資料列不等於清除它在模型裡的影響** —— 需要靠資料血緣界定受影響模型，必要時重訓練，光刪主表不夠。
- [ ] **資料治理是跨部門共同責任，不是資安或 IT 單獨負責** —— 選項寫「由 IT 團隊部署後定期觀察」通常是誘答，正解方向是導入治理框架與跨部門監管流程。

## 延伸練習

- **L22 主題庫 290 題**：篩選「隱私／加密／匿名化／治理／合規」相關題目，優先練 40.3 的 PETs 定位表與 40.4 的法規對照表；作答時把題幹限制條件（是否可解密、有幾個參與方、資料在哪一層、保護識別還是敏感值）逐條列出再選。
- **L22 歷屆 100 題**：本節相關的 5 題（114Q2-13、114Q2-20、114Q2-32、115Q1-37、115Q1-38）務必做到能講出每個誘答錯在哪一層；115 年的兩題是難度升級的指標題，值得反覆看。
