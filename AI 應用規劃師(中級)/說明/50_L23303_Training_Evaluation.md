## 50.1 訓練流程與資料分割

### 三份資料各自的職責

| 資料集 | 用途 | 使用時機 | 誤用後果 |
|---|---|---|---|
| **訓練集（Training Set）** | 調整模型參數（權重） | 每個 epoch 反覆使用 | 只看訓練集表現 → 看不見過擬合 |
| **驗證集（Validation Set）** | 調超參數、早停判斷、模型選型 | 訓練過程中反覆評估 | 調參調太多次 → 對驗證集過擬合 |
| **測試集（Test Set）** | 最終效能報告 | **全程只用一次** | 拿來早停或選模 → 評估值虛高、失去獨立性 |

**中級最愛考的一條界線：早停（Early Stopping）要看驗證集，不是訓練集，更不是測試集。** 114Q2 第 31 題的四個選項就是繞著這條線設計的：「依訓練集損失最低點停止」會過擬合、「改以測試集損失作早停」會洩漏測試資訊、「合併全部資料訓練至收斂」則連判斷依據都沒了。

### 標準訓練流程

```
原始資料
   │
   ├─ 切分（Hold-out 或 K-Fold）
   │
   ▼
訓練集 ──► 前處理 fit（標準化／PCA／SMOTE 只在這裡 fit）
   │              │
   │              └─ transform 同步套用到驗證集、測試集
   ▼
模型訓練（forward → loss → backward → update）
   │
   ▼
驗證集評估 ──► 未改善達 patience 次？ ──是──► Early Stopping
   │                                   否
   │◄──────────── 調整超參數／學習率 ──┘
   ▼
測試集評估（只跑一次）──► 報告最終效能
```

### 資料洩漏（Data Leakage）：把 fit 放錯位置

**任何「會學到資料統計量」的步驟，都必須放在交叉驗證迴圈內部，只用當折的訓練資料 fit。** 包括：標準化（StandardScaler）、主成分分析（PCA）、線性判別分析（LDA）、特徵選擇、SMOTE 過採樣。

```python
# 錯誤：LDA 先看過全部資料（含標籤），才做交叉驗證
X_new = lda.fit_transform(X, y)
scores = cross_val_score(knn, X_new, y, cv=5)   # 每折的測試資料早已參與降維

# 正確：用 Pipeline 把前處理與模型綁在一起，每折各自 fit
pipe = Pipeline([("lda", LinearDiscriminantAnalysis()), ("knn", KNeighborsClassifier())])
scores = cross_val_score(pipe, X, y, cv=5)
```

這正是 115Q1 第 44 題的完整考點：程式先跑 `lda.fit_transform(X, y)` 再丟給 `cross_val_score`，準確率高達 0.9733 是**假的**，正解是「存在資料洩漏，應將 LDA 納入交叉驗證流程」。

## 50.2 批次策略、學習率與早停

### 三種批次更新策略

| 策略 | 每次更新用多少資料 | 梯度穩定性 | 速度／硬體利用 | 適用 |
|---|---|---|---|---|
| **全量（Full-batch GD）** | 全部樣本 | 最穩，路徑平滑 | 每次更新極慢、記憶體吃重 | 小資料集 |
| **隨機（SGD）** | 1 筆 | 震盪劇烈 | 單次極快但總體收斂不穩 | 線上學習、資料流 |
| **小批次（Mini-batch SGD）** | 固定筆數（常見 256～2048） | 靠批內平均抵銷雜訊 | **GPU 平行度最佳** | 深度學習業界標準 |

115Q1 第 11 題把這張表寫成情境：全批次每次更新 45 秒、SGD 每次 0.01 秒但震盪劇烈，問「兼顧梯度穩定性與 GPU 吞吐量」該用什麼——正解就是 Mini-batch GD。誘答放了牛頓法（Newton's Method），聽起來高級，但億級參數要算並反轉 Hessian 矩陣，成本根本不可行。

### 學習率（Learning Rate）的四種調整策略

| 策略 | 做法 | 解決什麼 |
|---|---|---|
| **固定（Constant）** | 全程單一值 | 簡單任務；收斂後期難再進步 |
| **遞減（Step / Exponential Decay）** | 依訓練輪數定期調降 | 後期震盪、無法精修 |
| **動態調整（ReduceLROnPlateau）** | 驗證指標停滯就自動調降 | 不確定該在第幾輪降 |
| **預熱（Warmup）** | 初期用小學習率再逐步升高 | 初期梯度爆炸，常見於 Transformer |

**學習率的症狀對照（考題直接考因果）：**

```
學習率過大 → 參數在最小值兩側反覆跨越 → 損失震盪或發散（Divergence）
學習率過小 → 步伐太小 → 收斂緩慢，訓練集與驗證集曲線一起慢慢爬
```

115Q1 第 8 題問「學習率過大最直接導致下列哪種現象」，正解是**損失震盪或發散**。誘答會放梯度消失（成因是激活函數飽和或網路過深，與學習率無直接關係）與過擬合（是題幹前半段驗證損失上升造成的，不是調高學習率的直接結果）。114Q2 第 12 題則是反向問：收斂「有時過快導致過擬合、有時遲遲達不到最佳準確率」，該調哪個超參數——答案同樣是學習率；誘答放的「神經元輸出」「梯度」「權重值」都是訓練過程產生的結果，不是可調超參數。

### 早停三要素

| 參數 | 意義 | 設太小 | 設太大 |
|---|---|---|---|
| **監控對象** | 驗證集損失或指標 | — | — |
| **耐心值（Patience）** | 連續 N 輪未改善才停 | 被單次偶發波動誤判，過早終止 | 白跑很多輪，過擬合已經發生 |
| **最小改善幅度（Min Delta）** | 小於此幅度視為沒進步 | 微幅雜訊被當成進步 | 真實的小幅改善被忽略 |

驗證損失若因季節性或雜訊而**週期性上下抖動**，正確做法是把 patience 放大，而不是改用訓練集或測試集當依據（114Q2 第 31 題）。

## 50.3 分類評估指標與混淆矩陣

### 混淆矩陣（Confusion Matrix）四格

```
                    │ 實際為正（Positive） │ 實際為負（Negative）
────────────────────┼──────────────────────┼──────────────────────
預測為正（Positive）│  TP 真正             │  FP 假正（誤報）
                    │                      │  ＝ 型一錯誤
────────────────────┼──────────────────────┼──────────────────────
預測為負（Negative）│  FN 假負（漏抓）     │  TN 真負
                    │  ＝ 型二錯誤         │
```

**看附圖混淆矩陣時的固定讀法：** 先鎖定「正類」是誰（通常是少數、要抓出來的那類），再用「第一個字母＝預測對不對，第二個字母＝預測成什麼」拆解。FN 是「預測成負、但其實是正」＝**漏抓**；FP 是「預測成正、但其實是負」＝**誤報**。

### 四大指標公式與分母記憶法

| 指標 | 公式 | 分母是什麼 | 關心什麼 |
|---|---|---|---|
| **準確率 Accuracy** | (TP+TN) / (TP+TN+FP+FN) | 全部樣本 | 整體對了幾成 |
| **精確率 Precision** | TP / (**TP+FP**) | **預測為正**的全部 | 說是正的，有幾成真的是正 |
| **召回率 Recall** | TP / (**TP+FN**) | **實際為正**的全部 | 實際的正，抓到幾成 |
| **F1 分數** | 2·P·R / (P+R) | — | 兩者的**調和平均** |

> **注意：** 官方《學習指引》原文在 Recall 這一條把分母誤植成 TP+FP（與 Precision 相同）。正確的分母是 **TP+FN**——記法是「Recall 是站在**實際**那一側看，所以分母是實際為正的全部」。

**特異度與假正率（畫 ROC 要用）：**
- Specificity（特異度）＝ TN / (TN+FP)
- FPR（假正率）＝ FP / (FP+TN) ＝ 1 − Specificity
- TPR（真正率）＝ Recall

### F1 為什麼是調和平均，不是算術平均

```
Precision = 0.99，Recall = 0.01 的極端模型：
  算術平均 = (0.99 + 0.01) / 2 = 0.500   ← 看起來還行，完全掩蓋失敗
  調和平均 = 2 × 0.99 × 0.01 / 1.00 = 0.0198  ← 誠實地被拉到接近 0
```

調和平均只要有一項偏低，整體就被明顯拉下，**逼模型不能犧牲一方換另一方的高分**——這句話就是 115Q1 第 32 題的正解敘述。

**必練的計算題（114Q2 第 16 題原型）：** P=0.8、R=0.6，
F1 = 2 × (0.8 × 0.6) / (0.8 + 0.6) = 2 × 0.48 / 1.4 = 0.96 / 1.4 ≈ **0.686**。
誘答 0.700 正是算術平均 (0.8+0.6)/2。**調和平均恆小於算術平均**，所以答案一定低於 0.7——這個性質可以用來秒殺選項。

**需要偏重某一方時用 F-beta：** Fβ = (1+β²)·P·R / (β²·P + R)。β > 1 偏重 Recall（如 F2），β < 1 偏重 Precision。F1 是 β=1 的特例，兩者等權。

### Accuracy 的致命陷阱：類別不平衡

```
肺癌篩檢：正常 99%、陽性 1%
模型策略：全部預測為「正常」
  Accuracy = 99%   ← 數字漂亮
  Recall   = 0%    ← 一個病人都沒抓到
```

這個場景官方考了兩次：114Q2 第 19 題問「哪種作法最不適合提升少數類預測能力」，正解是**使用 Accuracy 作為評估指標**（SMOTE、類別權重、欠採樣多數類都是正當手段）；115Q1 第 12 題問「僅以 Accuracy 評估最嚴重的缺陷」，正解是「Accuracy 對類別不平衡不敏感，無法反映對陽性的偵測能力，**漏診風險被徹底掩蓋**」。

## 50.4 指標選擇與決策門檻（Threshold）

### 成本判準：一句話決定選哪個指標

| 業務痛點 | 要壓低的錯誤 | 主要指標 | 典型場景 |
|---|---|---|---|
| **漏抓成本高**（漏掉就出大事） | FN | **Recall** | 癌症篩檢、詐欺偵測、設備故障預警、瑕疵檢測 |
| **誤判成本高**（誤報就擾民／賠錢） | FP | **Precision** | 垃圾郵件過濾、帳號凍結、推播行銷、司法輔助 |
| **兩者都不能犧牲** | FN 與 FP | **F1 / F-beta** | 詐欺偵測（既怕漏放也怕誤凍結） |
| **要比較整體區分能力** | — | **ROC-AUC** | 需要跨門檻比較多個候選模型 |

判準記法：**問自己「這個錯誤讓誰受傷」**——漏掉一個癌症病人 vs 誤把正常信判成垃圾信，前者要 Recall，後者要 Precision。

### 門檻怎麼調：方向是固定的

分類模型輸出的是機率，**門檻（Threshold）預設 0.5 只是慣例，不是最佳值**。

```
調低門檻（0.5 → 0.3）
  更多樣本被判為正 → TP↑、FN↓ → Recall ↑
                    同時 FP↑          → Precision ↓
  適用：零容忍漏抓（癌症、詐欺、公安、瑕疵流出）

調高門檻（0.5 → 0.7）
  只有很有把握才判正 → FP↓          → Precision ↑
                      同時 TP↓、FN↑  → Recall ↓
  適用：誤判成本高（凍結帳號、發出告警、自動拒貸）
```

**背這一句就夠：「零容忍漏抓 → 調低 Threshold → 拉高 Recall」。** 反過來「怕誤報 → 調高 Threshold → 拉高 Precision」。注意調門檻**不需要重新訓練模型**，它是推論階段的後處理，這也是它在成本敏感場景被優先採用的原因。

### ROC-AUC 與 PR 曲線

| 曲線 | 橫軸 | 縱軸 | 特性 |
|---|---|---|---|
| **ROC** | FPR（假正率） | TPR（＝Recall） | 橫軸分母是負類總數，**極不平衡時會顯得過於樂觀** |
| **PR 曲線** | Recall | Precision | 不看 TN，**極不平衡時鑑別力較佳** |

- **AUC 的意義：** 隨機取一個正樣本與一個負樣本，模型給正樣本較高分數的機率。AUC = 0.5 等同亂猜，越接近 1 越好。
- **AUC 的價值：** 它是「跨所有門檻」的綜合指標，因此比較模型時不受單一門檻選擇影響。

**官方兩份試卷沒有直接考門檻計算，但把它藏在情境裡：** 115Q1 第 12 題的漏診疑慮、115Q1 第 32 題的 Precision-Recall Tradeoff，本質都是門檻思維的敘述版本。站上主題庫則有直接問「零容忍漏抓該怎麼調門檻」的題型，判斷方向與上面完全一致。

## 50.5 迴歸評估指標

### 四個指標的運算結構對照

| 指標 | 公式 | 對誤差的處理 | 單位 | 對離群值 |
|---|---|---|---|---|
| **MAE** | (1/n)·Σ\|yᵢ − ŷᵢ\| | 取**絕對值** | 與 y 相同 | **不敏感**（線性懲罰，梯度近似固定） |
| **MSE** | (1/n)·Σ(yᵢ − ŷᵢ)² | 取**平方** | y 的平方（如「元²」） | **高度敏感**（平方放大，梯度與誤差成正比） |
| **RMSE** | √MSE | 平方後**開根號** | 與 y 相同 | 敏感，但單位可讀 |
| **R²** | 1 − RSS/TSS | 殘差平方和 ÷ 總變異 | 無單位（比例） | — |

**三句話記住差別：MAE 取絕對值、MSE 取平方、RMSE 在 MSE 之上再開根號。** 這正是 114Q2 第 38 題附圖程式碼題的判斷依據：程式若只有「相減、平方、取平均」沒有開方 → MSE；多一個 `np.sqrt` → RMSE；用的是 `np.abs` → MAE；要算 RSS 與 TSS 的比值 → R²。

```python
import numpy as np

np.mean(np.abs(y_true - y_pred))              # MAE   ← 絕對值
np.mean((y_true - y_pred) ** 2)               # MSE   ← 平方、無開方
np.sqrt(np.mean((y_true - y_pred) ** 2))      # RMSE  ← 平方後開根號

ss_res = np.sum((y_true - y_pred) ** 2)       # RSS 殘差平方和
ss_tot = np.sum((y_true - y_true.mean()) ** 2)  # TSS 總變異平方和
r2 = 1 - ss_res / ss_tot                      # R²    ← 兩個平方和的比值
```

scikit-learn 對應：`mean_absolute_error`、`mean_squared_error`、`r2_score`；RMSE 在較新版本有 `root_mean_squared_error`，舊版則寫成 `mean_squared_error(y_true, y_pred, squared=False)`。

**恆成立的性質：RMSE ≥ MAE**（平方會放大大誤差，唯有所有誤差絕對值相等時兩者才相等）。兩者的差距越大，代表誤差分布越不均勻、存在少數極端偏差。

### R² 判讀

| R² 值 | 意義 |
|---|---|
| **= 1** | 完全解釋資料變異，預測完美 |
| **= 0.85** | **85% 的變異可被模型解釋**（不是「準確率 85%」、不是「誤差 15%」、不是「信心水準」） |
| **= 0** | 與「永遠預測平均值」的常數模型同等表現 |
| **< 0** | 比常數模型還差，模型嚴重偏離資料趨勢 |

114Q2 第 15 題就是直球考「R²=0.85 的意義」，四個誘答分別是準確率、誤差百分比、信心水準——全都是把「解釋變異的比例」誤讀成其他統計量。另外，**不同任務或不同資料集之間的 R² 不可直接比較**。

### 損失函數選擇：跟著「要不要放大離群值」走

| 需求 | 選擇 | 理由 |
|---|---|---|
| 要模型**對極端值更敏感** | **MSE** | 平方懲罰放大大誤差，梯度與誤差成正比 |
| 要**壓低離群值影響** | **MAE** | 線性懲罰，梯度近似固定 |
| 想折衷 | **Huber Loss** | 小誤差用平方、大誤差轉線性 |
| 分類任務 | **交叉熵（Cross-Entropy）** | 衡量機率分布差異，迴歸不適用 |

115Q1 第 2 題（豪宅房價）就是考這個方向：題幹要「對極端高價物件誤差更敏感、產生較大梯度更新」，正解是 **MSE**；Huber 的設計目的與需求完全相反，是最漂亮的誘答。另有題目考「App 使用時長（連續值）配 MSE、是否流失（二元）配 Binary Cross-Entropy」，兩者對調就是錯的。

## 50.6 交叉驗證方法全覽

### 五種方法對照

| 方法 | 切法 | 訓練次數 | 優點 | 代價／限制 |
|---|---|---|---|---|
| **Hold-out** | 一次切成訓練／驗證 | 1 | 最快、最省 | 受單次切分運氣影響大 |
| **K-Fold** | 等分 K 折，輪流當驗證 | **K 次** | 降低切分偶然性，適用性廣 | 計算成本 K 倍；**不保證類別比例** |
| **Stratified K-Fold** | K-Fold + 各折維持類別比例 | K 次 | **類別不平衡的標準做法** | 僅適用分類任務 |
| **LOOCV（留一法）** | 每次只留 **1 筆** 當驗證 | **n 次**（n＝樣本數） | 資料利用率最高、偏差最小 | 成本極高、結果變異大 |
| **Repeated K-Fold** | K-Fold 多輪隨機重切 | K × 重複次數 | 可報告平均與標準差 | 成本最高 |

### 選型決策樹

```
資料有時間順序嗎？（銷量、用電、設備感測）
 ├─ 是 → 時間序列交叉驗證 / 滾動窗口驗證（Rolling Window / TimeSeriesSplit）
 │        ※ 絕不可用隨機 K-Fold：會用未來預測過去 = 資料洩漏
 └─ 否 ↓
     是分類任務且類別不平衡嗎？
      ├─ 是 → Stratified K-Fold（樣本極少時用 Stratified LOOCV）
      └─ 否 ↓
          樣本數極少且珍貴嗎？（臨床、稀有病）
           ├─ 是 → LOOCV
           └─ 否 → K-Fold（K=5 或 10，精度與成本的平衡點）
                    需要報告穩定性／標準差 → Repeated K-Fold
```

**114Q2 第 34 題是這棵樹的完整走法：** 150 筆、陽性不到 8%，要「兼顧資料利用率」與「各類別在驗證折中的比例一致性」——兩個條件各指一邊，正解是**分層留一法（Stratified LOOCV）**。一般 5-Fold 在小樣本下訓練資料被切掉太多且未必分層；標準 LOOCV 利用率高卻不保證類別比例；隨機交叉驗證更不控制分層。

**115Q1 第 27 題則是時間軸的走法：** 前 52 週訓練、第 53 週測試，半年後對第 80 週明顯衰退——正解是**滾動窗口驗證（Rolling Window / Time Series Split）**，永遠以過去預測未來且每輪納入最新資料。K-Fold 與 LOOCV 會打散時間順序造成洩漏，Stratified K-Fold 處理的是類別不平衡不是時間順序。

### scikit-learn 的預設行為（程式碼題直接考）

```python
# cv=5：若估計器是「分類器」且標籤為離散類別，scikit-learn 預設就用 StratifiedKFold
cross_val_score(knn, X, y, cv=5)

# 明確指定分層
cross_val_score(knn, X, y, cv=StratifiedKFold(n_splits=5, shuffle=True))

# 重複多輪分層切分，同樣維持比例
cross_val_score(knn, X, y, cv=RepeatedStratifiedKFold(n_splits=5, n_repeats=3))

# KFold 只是打亂後等分，完全不考慮類別比例 → 不符合「維持類別比例」的要求
cross_val_score(knn, X, y, cv=KFold(n_splits=5, shuffle=True))
```

115Q1 第 45 題就是問「哪幾段程式碼能確保每折類別比例與原始資料一致」，正解是 `StratifiedKFold` + `cv=5`（預設分層）+ `RepeatedStratifiedKFold` 三者，**只有 `KFold` 不合格**。

### 交叉驗證的成本：網格搜尋會乘起來

```
總訓練次數 = 各超參數候選數的乘積 × 折數

例：3 × 4 × 5 × 3 × 3 = 540 組參數組合
    540 × 5 折 = 2,700 次訓練
```

115Q1 第 34 題就是這題。誘答分別是「相加」（3+4+5+3+3=18，把組合誤解成選項總數）、「只算折數」（5×5）、「取最大值再乘折數」——全都嚴重低估。重點觀念是**網格搜尋成本隨超參數個數呈指數成長**，這也是 Random Search 在高維參數空間更有效率的理由。

### 交叉驗證還能診斷高變異

訓練 AUC 0.97 / 驗證 AUC 0.72，且**不同 K-Fold 切分結果差異明顯**——這組症狀指向「高變異（High Variance）」。115Q1 第 30 題把「高變異」與「過擬合」同時放進選項，兩者概念高度相關，判準是：**題幹強調「切分之間的不穩定」就選高變異**；高偏差則會表現為訓練與驗證同時不佳。

## 50.8 易錯與陷阱

- [ ] **Recall 的分母是 TP+FN，不是 TP+FP** —— Precision 站在「預測」那側（分母 TP+FP），Recall 站在「實際」那側（分母 TP+FN）。官方《學習指引》原文此處有誤植，以本條為準。
- [ ] **F1 是調和平均，不是算術平均** —— 所以 P=0.8、R=0.6 的 F1 是 0.686 而非 0.700；調和平均**恆小於**算術平均，可用來排除選項。
- [ ] **MSE 對離群值敏感，MAE 才是壓離群值的那個** —— 要模型「對極端值更敏感」選 MSE，要「降低離群值影響」選 MAE 或 Huber，兩者方向相反。
- [ ] **RMSE 是 MSE 開根號，MSE 的單位是平方單位** —— 要報告「與目標同單位」的誤差只能用 MAE 或 RMSE，不能用 MSE。
- [ ] **R²＝0.85 是「85% 的變異被解釋」，不是「準確率 85%」** —— R² 也不是誤差百分比，更不是信心水準；且不同資料集間的 R² 不可互相比較。
- [ ] **Accuracy 在不平衡資料下會說謊，不是「不能處理多分類」** —— 它本來就適用多分類；它的問題是分母被多數類主導，掩蓋漏抓。
- [ ] **零容忍漏抓 → 調低門檻拉高 Recall，不是調高門檻** —— 調低門檻讓更多樣本被判為正，FN 減少、Recall 上升，代價是 Precision 下降。
- [ ] **調整決策門檻不需要重新訓練模型** —— 它是推論階段的後處理，這正是它在成本敏感場景被優先採用的原因。
- [ ] **Stratified K-Fold 解決的是「類別不平衡」，不是「時間順序」** —— 時序資料要用 TimeSeriesSplit／Rolling Window；把時序資料丟進隨機 K-Fold 是拿未來預測過去的資料洩漏。
- [ ] **LOOCV 是「每次留一筆」，不是「只做一次驗證」** —— K = n，共訓練 n 次，資料利用率最高但成本極高、結果變異也大。
- [ ] **K-Fold 的計算成本是 K 倍，網格搜尋還要再乘上組合數** —— 總次數 = 各參數候選數相乘 × 折數，是乘法不是加法。
- [ ] **早停監控驗證集，不是測試集** —— 用測試集早停會洩漏測試資訊、破壞最終評估的獨立性。
- [ ] **前處理要放進 Pipeline，在交叉驗證迴圈內 fit** —— 先對整體資料做 PCA／LDA／標準化／SMOTE 再做 CV，是最常見的資料洩漏寫法，準確率會假性偏高。
- [ ] **`cv=5` 對分類器預設已是分層切分，但 `KFold` 明確不是** —— 程式碼題要挑「維持類別比例」的選項時，含 `KFold` 的組合一律排除。
- [ ] **高變異與過擬合概念相關但考法不同** —— 題幹強調「不同切分之間結果差異明顯」選高變異；只講「訓練好、測試差」選過擬合。
- [ ] **學習率過大 → 震盪發散；過小 → 收斂緩慢** —— 梯度消失是激活函數飽和或網路過深造成的，跟學習率無直接關係，別混為一談。
- [ ] **ROC-AUC 在極度不平衡時偏樂觀** —— 因為 FPR 的分母是龐大的負類總數；此時 PR 曲線與 F1 的鑑別力較佳。
